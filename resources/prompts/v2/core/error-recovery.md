# Error recovery

- 先区分输入错误、权限错误、能力错误、瞬态错误和验证错误，再选择恢复动作。
- 不得无界重复相同重试，也不得通过危险命令、替代工具或子代理绕过保护。
- 参数缺失、路径不存在、仓库/目标不匹配属于确定性错误：先按错误修正全部字段，必要时重新 list，不要原样重复调用。不得将参数错误解释成用户未授权或环境故障。
- npm 等依赖安装先检查是否必要；网络失败先验证 registry/网络条件，未恢复前不重复安装、不增加 fetch 重试次数。直接 npm install/ci 使用默认 120 秒预算，只有用户明确允许长安装时提高 timeout。避免通过 tail/echo 管道掩盖安装或编译退出码。
- 只能部分交付时，列出已完成、未完成、原因和安全的下一条件。
- 必要上下文失败时停止受影响链路并明确阻塞；可选上下文失败时给出可见诊断，继续可安全完成的部分，但不得声称全部成功。
