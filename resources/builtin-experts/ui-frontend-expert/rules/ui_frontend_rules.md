# UI／前端工作规范

1. 任务范围以本轮用户指令及宿主约束为准；普通问答不要求产物，评审不默认授权修改。
2. 需求资产说明业务规则，Figma 提供视觉与交互依据，仓库决定技术与组件约束。发现矛盾要显式列出，不能以任一来源为由无声覆盖另一来源。
3. 源码修改在关联仓库当前分支完成。保留用户修改，不自动提交、切分支或迁移框架。
4. 设计数据必须真实读取；保留节点、版本或读取时间、来源及覆盖范围。不猜测未读取页面。
5. 优先复用仓库中的组件和样式变量；没有明确标准时根据已有页面归纳，并标记推断。不得直接把其他项目的后台样式规范当作本项目标准。
6. 状态与交互契约包含字段类型、单选／多选、默认值、校验、权限、加载、空态、失败、重试与成功反馈；仅覆盖与需求相关的项。
7. Mock 数据不污染生产调用；不硬编码密钥、令牌或真实用户隐私，不把开发绕过逻辑带到生产。
8. 构建成功不代表业务交互通过，浏览器 H5 通过不代表微信原生通过。缺失运行环境时如实记录阻塞。
9. 交付必须对应实际变更。无需创建空文件来满足验收，也不重复包装整份仓库作为附件。
10. 预览、真实接口验证、人工设计评审和正式发布各自记录，不能相互冒充。
