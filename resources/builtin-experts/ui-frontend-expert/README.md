# UI／前端专家

版本：1.0.0。按同目录产品经理专家的 schemaVersion 2 插件格式创建，使用独立名称与内容。

## 定位

用于设计评审阶段的 Figma 读取、视觉与交互评审、现有前端代码实现及预览交付。产品经理负责需求与业务验收口径，本专家负责将其落实为可继续开发的页面；缺失的业务规则仍需产品确认。

支持 Web、H5 与微信小程序等已有项目，实际能力取决于宿主提供的工具、仓库技术栈及本机运行环境，不预装或假装具备运行器。

## 包结构

```text
.picoddy-plugin/plugin.json       专家元数据、主提示与能力声明
agents/ui-frontend-expert.md        主提示、任务分流与关键边界
rules/ui_frontend_rules.md          可供兼容宿主读取的规则
skills/figma-design-review/         设计读取与评审
skills/frontend-implementation/    现有项目实现
skills/interactive-delivery/        验证、交付与评审模板
```

规则关键内容已纳入主提示，不假设所有宿主都会自动加载 rules。没有复制产品经理的无关业务技能、个人配置、缓存或第三方授权材料。

## 使用

通过当前应用已有的专家导入／安装机制加载本目录，然后在设计评审会话中选择“UI／前端专家”。仅创建源目录不会自动安装或替换现有阶段绑定。

先关联需求资产与实际代码仓库；需要依据 Figma 实现时选择可用连接器并明确设计范围。仓库沿用当前分支，已有改动保留，后续前端开发继续使用这一分支。

典型指令：

- “当前连接器怎么用？”——直接咨询，无文件交付要求。
- “对照需求资产和当前 Figma 页面做设计评审，只列问题。”——只读评审，不自动修改。
- “根据需求和 Figma 实现点单页及规格弹窗，保留现有接口，登记交付让我点击预览。”——真实实现、适当验证和交付。
- “修复这张截图中的卡片高度与滚动问题，保持原业务流程。”——最小必要修复。

## 交付约定

代码保存在真实仓库中，不另造脱离工程的 HTML 原型。用户明确要求独立原型时才采用独立形式并说明与正式工程的关系。

宿主提供 requirement_preview 时遵循其真实工具定义完成配置、设计读取和交付；不自行定义新的 MCP 服务，不保存账号令牌，不调用未提供的工具。预览由用户点击启动，代码完成、Mock 验证、真实集成与人工评审分别记录。

本包不自动发布、提交 Git、合并、推进 TAPD，也不自动改动产品经理专家。
