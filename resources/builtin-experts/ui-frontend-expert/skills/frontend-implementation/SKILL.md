# 现有前端实现

开始前读取关联仓库的工程说明、包配置、锁文件、现有页面及相邻组件。识别原生 Web、React、Vue、uni-app、Taro 或原生小程序等真实技术栈；不得默认使用 React 或独立 HTML 覆盖原项目。

## 实现顺序

1. 检查 Git 当前分支与修改状态，识别本轮要改的文件。对已有改动做局部增量编辑，冲突处先澄清；不自动清理仓库。
2. 梳理现有路由、组件、数据访问、状态、权限、埋点和国际化。小范围修改保持既有接口与目录结构。
3. 将设计映射到现有组件及 tokens；仅新增必要扩展。图标、字体、图片来自授权设计资产或仓库，不杜撰下载地址。
4. 实现与需求相关的完整状态和操作反馈。按钮不能只有外观；导航、校验、提交、取消、返回及错误恢复遵守现有业务契约。
5. 使用现有断点、容器规则、安全区和滚动方式。检查长文案、溢出、省略后的详情入口、弹层层级、焦点管理和小屏布局。
6. 模拟交互优先通过隔离场景模块注入，不改生产 API 地址或通过注释权限校验实现“可运行”。说明哪些状态是模拟。
7. 按仓库现有命令做必要验证，检查最终 diff 没有无关修改。依赖确需新增时说明原因并遵守当前授权，不自动升级整套依赖。

## 端差异

- Web／H5：沿用仓库启动脚本与路由；可用 Playwright 验证页面状态、视口、点击和表单行为。
- 微信小程序：遵守实际工程的 WXML／WXSS／JS／TS 或现有跨端框架，核对 project.config.json、编译输出和页面路径；使用已安装的微信开发者工具及宿主支持的 CLI／Automator。缺少登录、工具或项目配置时报告阻塞。
- 跨端工程：只验证实际运行过的目标。H5 预览是辅助验证，不能宣称小程序能力和真机表现已通过。

开发依赖、启动命令和端口以项目事实为准，不给所有仓库套用同一端口或强制安装新运行器。
