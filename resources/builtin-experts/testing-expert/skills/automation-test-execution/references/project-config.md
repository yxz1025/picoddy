# 项目测试配置

获得本轮执行授权后（用例交付后确认或直接启动请求），优先读取关联仓库已有的自动化配置；不存在时按仓库规范建立配置文件（微信无约定可使用 tests/automation/wechat.json）。向用户获取缺失事实后写入，不能从仓库名、接口域名或 Jenkins Job 猜页面域名。配置可复用，具体运行快照不可变。

微信运行配置使用 templates/wechat.config.example.json 的单目标结构：schemaVersion/kind/repositoryRoot/projectPath/cliPath/appId/environment/timeoutMs/cases。Web 复用项目原生 Playwright 配置。先复用已有值，只追问下列缺失信息，不能把配置收集提前到纯用例设计阶段。

| 类型 | 必要信息 | 可选增强 |
|---|---|---|
| Web/H5 | baseUrl（HTTP(S) 测试域名）、entryPath（入口路径，可为空）、实际 Playwright 配置位置 | 视口、浏览器项目、版本接口及预期 SHA |
| 微应用 | 独立应用 URL，或主应用 baseUrl + 挂载 entryPath；明确运行方式 | 主应用登录 fixtures、子应用版本接口 |
| 微信小程序 | 开发者工具可打开的项目目录、AppID、CLI 绝对路径、后端测试环境 | 项目构建命令与输出目录、基础库版本 |

入口可以是 hash 路由。保持 URL 解析语义，不用字符串随意拼接，也不自动换域名。测试脚本通过 BASE_URL/ENTRY_URL 或项目现有等价配置访问实际入口。认证允许使用业务真实登录跳转，不能因此将任意外部域名变成测试目标。

认证配置只记录 credentialRef、环境变量名称或本地登录态文件路径，不保存凭据正文。数据配置说明专用账号、种子数据/隔离 ID 和清理方式。先核实所用脚本或项目 fixtures 是否支持对应认证与数据方式；不支持的项列为具体缺口。

微信首次准备：安装微信开发者工具、登录并具备项目访问权限、开启 CLI/HTTP 调用；目标测试工程安装锁定版本的 miniprogram-automator。Web 首次准备：安装项目使用的 @playwright/test 及对应浏览器。技能更新或读取配置不应执行这些安装动作。

Windows CLI 常为 cli.bat，macOS 为应用内 cli。路径可包含空格，交给执行器的结构化参数，不拼接未经转义的 shell 命令。所有配置采用实际检测值，不硬编码开发者用户名或电脑路径。

编译型小程序必须先核对本地输出对应的源码版本。目录哈希只能证明这次测试的内容及执行中是否变化，不能证明构建来源，也不能证明线上发布版本。缺少构建来源证据时在报告中明确说明。

## 单端与跨端配置

先明确用户业务范围。单端复用本文件既有配置；跨端使用 [场景清单示例](../templates/business-scenario.example.json)，为每端登记入口、角色、认证引用和仓库映射，依照 [业务场景编排](business-scenarios.md) 生成业务仓库内的统一入口。示例不是 run-wechat.cjs 的输入，不能将多端清单传给单端运行器。

数据配置记录 setup/cleanup 模块、人工准备项、真实业务 ID 输出及本轮归属；每端独立登录态，共用同一测试环境业务链路。先生成用例无需补全执行地址；直接启动路径须先补齐执行条件，再生成用例/脚本并运行。
