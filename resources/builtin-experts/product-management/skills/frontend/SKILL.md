# box-center 风格交互 PRD 参考

给产品专家使用的自包含规范包。读取同目录文档和交互样例即可生成原型，不依赖原代码仓库、源码链接或生产组件导入。

## 使用流程

1. 先读 [overview.md](overview.md)，确认版本与审核状态。当前 pending，只能作为明确标注的评审预览；正式规范须有负责人、日期、凭据和批准版本。不能自行批准。
2. 读 [design-tokens.md](design-tokens.md) 确定颜色、字号、尺寸、间距。候选 token 不是生产环境已生效主题。
3. 读 [page-patterns.md](page-patterns.md)，按需求选列表、短表单、分组表单或多标签详情。
4. 按需读 [components.md](components.md)，确定控件的单多选、输入输出、显示值和业务边界。
5. 读 [interactions.md](interactions.md)，实现本次需求相关的校验、查询、保存、取消、加载、错误与权限状态。
6. 打开或读取 [reference.html](reference.html) 作为视觉和交互起点。它是离线模拟参考，不是生产截图；未演示的组件仍按文字契约实现。

产品需求、页面范围、独立或嵌入模式可从上下文推断；业务权限、字段含义和接口未知时列出待确认，不能从历史样本擅自填充。

## 必须保持的边界

- 已核实事实 F 不自动成为规范；候选 C 需审核；例外 X 不继承。草案可以做评审预览，不能标为正式批准。
- C-03 仅为服务搭配师单选，保存单个 ID；员工多选或组织架构选择应声明新增候选。人群包和部门选择不是人员选择。
- 显示姓名不决定 ID 类型或含义；不能把 id、code、phone 当成可互换主键。
- 技术栈可以选 HTML、React、Vue；保留外观与值模型，无需安装原工程。模拟保存要更新本地演示数据，不调用生产接口。
- 未收录控件标记为新增候选并定义行为；不要编造现成组件、批准记录或后端能力。
- 所有显眼按钮应有可观察结果；失败、空数据、无权限要能区分，不能只绘制静态外观。

## 映射示例

需求：“服务记录列表，支持编辑搭配师并查看详情。”

| 页面/字段 | 引用 | 原型行为 |
| --- | --- | --- |
| 服务记录列表 | P-01 + C-01 | 查询、重置、翻页，空态与失败重试 |
| 编辑弹窗 | P-02 + I-01/I-02 | 回显、校验、保存、取消，失败保留输入 |
| 服务搭配师 | C-03 | 姓名搜索单选，存一个稳定 ID |
| 详情返回 | P-04 + C-02 | 返回列表并恢复筛选页码 |

若需求变成“多选审批人”，C-03 不适用，应新增候选并说明人员范围与数组等值模型待确认。

## 交付要求

交付可操作页面，同时附简短引用说明：规范版本与状态、采用的 P/C/I 规则、新增差异、实际验证结果。未验证项如实列出。
当前预览展示“规范草案 0.1.0-draft，待前端确认”；技术映射放在独立评审说明，不混入业务字段。

## 携带与维护

本目录包含技能入口、五份规范和 reference.html；可整体作为 frontend 技能包携带。无需复制生产代码。产品专家读取本入口即可引用，不能只搬一个 SKILL.md 丢掉资源。
维护者新增规范时重新核对实际实现，将必要事实转写为自包含示例；更新版本并重新审核。不以源码链接代替组件行为说明。
