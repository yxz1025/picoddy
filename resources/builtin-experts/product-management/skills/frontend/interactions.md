# 交互规则与原型验收

本页 I-01～I-08 全部是待审核候选；每行明确源码事实与补全规则。发布流程见 [overview.md](overview.md)。原型展示模拟业务状态，不从生产账户读取或提交真实数据。

| ID | 规则 | 源码事实 F | 候选规范 C / PRD 验收 |
| --- | --- | --- | --- |
| I-01 | 字段校验 | 字典编辑弹窗 的 validatorRules / validate；数值范围组件 没有跨字段区间校验 | 必填标识与规则一致；文本按业务约定 trim 后校验；错误显示在字段旁且提交被阻止；数值范围 low≤high，允许空端点与否明确；0 不能当空值 |
| I-02 | 提交与取消 | DictModal 使用 confirmLoading，但 finally 中 close，见 X-05 | idle→validating→submitting→success/error；提交中禁重复提交；成功才关闭并更新数据；失败保留字段；取消不保存，重新打开的回填规则明确 |
| I-03 | 加载、空与失败 | 公共列表组件 具有 localLoading，但 reject 收尾不完整；列表共享逻辑 未传递失败 | initial/loading/success-empty/success-data/error 分开；loading 必须能结束，错误显示重试；成功零条才显示空态；刷新失败可保留旧数据并提示，不伪造成功 |

| I-05 | 消息与危险操作 | 消息注册层 注册 message/confirm；`续订授权记录` 取消授权先确认 | 成功短提示；失败可理解且可重试；危险操作说明对象与后果并允许取消；确认后才变更状态，取消后列表不变，不为每个查询增加确认框 |

## 接口边界：源码存在多套返回结构

请求适配层 的 returnCode 默认 true，此时返回响应业务体；false 分支只对 code===0/200 返回 data。网络异常在 handleError 为 true 时 message.error 并继续 reject。旧字典组件使用 success/result，box 页面常判断 code==0、data/page。HTTP 200 不等于业务成功，不统一猜成 `{success:true}`。

产品专家的模拟层可以定义自己清晰的成功 / 失败分支，再适配 C-01 或字段契约；不能只拷贝线上 URL 而缺少认证、响应适配或错误处理。原型“保存成功”指本地演示数据更新，应在交付说明中标明，不暗示生产已保存。

## 每个交互 PRD 至少实际检查

1. 从列表进入详情 / 编辑并返回，路径或视图真实改变，选中实体正确。
2. 关键词、枚举 0、重置和分页都改变数据，初始值与 PRD 一致。
3. 必填错误可见且阻止提交；改正后可提交，重复点击不会生成多条。
4. C-03 选一个搭配师只保存一个 ID；字段回显姓名，联动后旧 ID 不残留。
5. 危险操作取消不变更，确认后数据或状态更新。
6. 列表加载结束；空态、失败重试、提交失败保留输入都能演示。
7. 角色无权限和业务禁用有明确区别，直接访问详情不会绕过演示权限规则。
8. 所有显眼按钮有可观察结果；无法支持的动作明确标记模拟或待设计，不放空点击处理器。

本清单用于后续 PRD 的逐项验收。随附 reference.html 已验证筛选、重置、分页、必填、保存失败保留值与重试、详情标签、授权确认/取消、只读、列表错误重试和无权限状态，未发现 JavaScript 运行错误；已检查桌面和窄视口截图。此结果仅适用于离线样例，不代表生产页面已验证或规范已批准。日期、范围、上传和复杂长表单未在本样例中演示。
