# 组件规范：能力、样式与值模型

本页是可独立使用的组件目录，状态见 [overview.md](overview.md)。C-01～C-07 为待审核候选，实际展示见 [reference.html](reference.html)。组件名称用于明确能力来源，不要求产品专家安装或导入生产组件。

## 选型表

| ID | 产品能力 | 既有实现身份 | 原型呈现 | 边界 |
| --- | --- | --- | --- | --- |
| C-01 | 分页列表 | box 业务公共 STable | 筛选、表格、行操作、右侧分页 | 失败与重试需补全 |
| C-02 | 返回标题 | box Header | 返回入口 + 当前标题 | 返回目标与列表状态由页面管理 |
| C-03 | 服务搭配师选择 | 要盒需求里的 Antd Select 组合 | 姓名搜索 + 单选下拉 | 不是独立通用员工选择器 |
| C-04 | 字典单选 | JDictSelectTag | 下拉或单选组 | 显示文案，保存字典值 |
| C-05 | 日期时间 | JDate | 单日期或日期时间输入 | 保存格式化字符串 |
| C-06 | 数值范围 | RankPrice | 最低 ~ 最高 + 确定/取消/清空 | 两个输出参数，需补区间校验 |
| C-07 | 图片上传 | JImageUpload 的现用版本 | 上传中、缩略图、预览、删除、失败 | 原型模拟，不上传真实服务 |

## C-01：分页列表

**样式：** 白色卡片、14px 正文、32px 筛选控件、8px 按钮间距。列表描述文本左对齐，数量金额右对齐；长文本省略并提供全文查看。稳定记录 ID，操作列可见，不给每张表自动增加复选框。

**输入：** 列定义、查询条件、pageNo（默认1）、pageSize（默认10）；可选排序、批量选择。

**数据契约（F）：** 现有 STable 的数据函数返回 Promise，结果如下，count 是总条数：

```json
{
  "data": [{ "id": "demo-001", "name": "示例记录", "status": 1 }],
  "page": { "pageNo": 1, "count": 23 }
}
```

查询 / 重置后从第一页加载；普通刷新保持页码。原组件分页时清空选中项；需要跨页选择属于扩展。原型可采用自己的状态管理，但不能把分页总条数误成总页数。失败状态应独立显示并允许重试，不能因为旧组件缺少异常收尾就复制这一缺陷。

## C-02：返回标题

**外观：** 白底标题区，返回动作清晰，标题16px；与下一块内容候选间距24px。

**行为（F）：** 既有 Header 接受 title/subTitle 和 hasBackPath；hasBackPath=false 会返回历史上一页，true 发出无参数 headerBack 交由父页面处理。

**原型规则（C）：** 明确返回目标列表，即使直接打开详情也能返回。筛选和页码由页面状态保留，不能认为标题组件自带保留能力。

## C-03：服务搭配师选择——人员选择的明确边界

| 项目 | 规范说明 |
| --- | --- |
| 选择对象 | 本次会员与要盒类型允许的搭配师，不是全公司员工 |
| 单选 / 多选 | 单选；现有组合没有多选能力 |
| 输入选项 | `{id, name}[]`；ID 类型保持业务提供的 string 或 number |
| 显示 | 姓名；对已加载姓名进行忽略大小写的本地搜索 |
| 保存 | 单个 id；不返回人员对象、姓名或数组 |
| 现有字段 | form.createFasId；随要盒需求整体提交 |
| 默认 | 空字符串；已有值按 ID 回显姓名 |
| 联动 | 上游要盒类型改变时清空失效搭配师并刷新候选 |
| 清除 | 现有选择没有独立清除按钮；需要此能力应标明扩展 |
| 校验 | 此业务要求必选；无候选与获取失败要区分 |
| 外层事件 | 需求保存成功通知 update，无人员参数；不存在独立 selectPerson 输出事件 |

可直接用于原型的输入输出示例：

```json
{
  "options": [
    { "id": "demo-fas-001", "name": "林晓（示例）" },
    { "id": "demo-fas-002", "name": "陈宁（示例）" }
  ],
  "initialValue": "",
  "afterSelect": "demo-fas-001",
  "submit": { "createFasId": "demo-fas-001" }
}
```

交互：展开 → 搜索姓名 → 点选一人 → 输入框回显姓名 → 保存一个 ID。独立原型可使用原生 select 或自定义下拉模拟，必须保留以上语义。

**需要员工多选时：** 标为“新增组件候选”，另定义人员范围、搜索方式、ID含义、多选返回结构、清空及回显。不能把本条宣布为现成的组织架构多选组件。其他历史搭配师场景也存在 id/code 差别，不因显示都是姓名就认定值可互换。

PeoplePackage 是人群包，保存人群包 ID；DepartSelect 是登录部门切换，保存组织编码。二者都不等于人员选择。

## C-04：字典单选

输入 dictCode、value、placeholder、disabled、展示形式。已有封装支持下拉、radio、radioButton；显示选项文案，输出选择值。已有 value 接受 String/Number，显示会做字符串转换；原型应统一同一字段选项和值的类型。

```json
{
  "options": [{ "value": 1, "label": "同意" }, { "value": 0, "label": "拒绝" }],
  "value": 0,
  "display": "拒绝"
}
```

0 是合法值，不能在重置或筛选时当空值。不限值可设 null，需与业务模型一致。

多选字典 JMultiSelectTag 的源码事实：输入为分隔字符串，默认以逗号拼接输出，例如选择 a、b 输出 `"a,b"`，清空 `""`，不是数组。本次未核实代表业务调用，暂不进入白名单；不能将它当通用人员多选。

## C-05：日期时间

已有 JDate 输入输出都是字符串，默认格式 `YYYY-MM-DD`，showTime 默认 false。启用时间应同时设置 `YYYY-MM-DD HH:mm:ss`，清空输出空字符串。disabled/readOnly 禁止编辑。

示例：`"2026-09-09"` 或 `"2026-09-09 14:30:00"`，不是时间戳、Date 对象或日期数组。时区、可选边界、是否允许未来日期由 PRD 指定，不从业务样本泛化。

## C-06：数值范围

输入标题及最低/最高输入框的 min/max/step。编辑中暂存，确定后输出两个位置参数 `updateRank(low, high)`；取消恢复上次确认值；清空输出 `('', '')`。原组件没有外部 value/v-model，不能声称已支持声明式回显。

示例：最低10、最高50，确定输出 `(10, 50)`；原型可再明确映射为 `{min:10,max:50}`，该对象是适配层格式，非现有组件输出。补 low≤high 校验；允许只填一端与否由 PRD 定义。外部重置和初始回显属于需补的能力。

## C-07：图片上传

输入允许 String/Array，isMultiple 默认 false，可配置多图；数量上限要由需求明确，不能把现有默认 number=0 推断为无限制。声明允许类型和大小限制，现有 fileSize 默认2，但本次未核验其单位与有效性，不作为统一上传限额。

已有 change 输出路径字符串：单图 `"demo/a.png"`，多图 `"demo/a.png,demo/b.png"`，清空 `""`；另有 fileChange 返回文件列表。输入能接收数组不代表 change 输出数组。

原型演示：选取模拟图片 → 上传中 → 缩略图 → 点击预览 / 删除；失败保留重试入口。使用模拟路径或本地预览，保存结果标为演示数据。多图、大小限制、排序和封面等未明确能力不自行添加。

## 产品专家的组件引用记录

每个关键字段说明：组件 ID、展示方式、初始值、选择或编辑后的值、校验、联动、扩展。这样负责人能直接审核生成结果，无需打开源码。

例：服务搭配师 → C-03 → 姓名搜索单选 → 初始空 → 保存搭配师ID → 必填 → 类型变化清空 → 无新增多选能力。
