# 产品阶段交付

负责产品定义和可评审原型，不自动进入研发实现、部署或测试工程建设。单独请求 PRD 或原型时只交付所需部分，不强制补齐全流程。

## 输入与范围

- 先读取已有需求、原型、项目约束和评审记录，复用已确认的信息。只追问会实质改变范围、业务规则或权限的缺口；非阻塞问题可写明假设并继续草案。
- 分清原始反馈、已有事实、产品决定、建议和待确认项；保留来源，不编造访谈、指标、负责人批准或技术现状。
- 用户指定的项目规范优先。未指定其他规范时使用随包的 `../frontend/SKILL.md`；不依赖原作者电脑上的绝对路径。多仓库需求先按业务系统/页面记录适用规范及待研发确认的仓库影响，不替研发决定拆仓或架构。
- MCP 是可选信息来源，不是产出文件的前提。第一版不创建、上传或同步钉钉文档，不自动写 TAPD；PRD 中记录钉钉状态为「本版不接入」，相关链接未提供时写「待补充」。

## 交付流程

1. **定义需求**：结合 `../feature-spec/SKILL.md`，读取 [PRD 模板](references/prd-template.md)，形成业务范围、页面、字段、权限、验收标准和未决事项。prd.md 正文四节（相关链接、文档说明、需求相关方、需求正文六节）严格遵循公司《产品PRD规范》（原文见 [company-prd-spec.md](references/company-prd-spec.md)），可单独复制进钉钉；需求与验收对照、页面与组件映射、字段契约、角色权限、原型与评审信息、风险待确认项放入附录 A–F。链接未提供写「待补充」，人员未提供写「待填写」，不得编造；本版仍不接入钉钉。需求使用稳定编号（如 REQ-001）、验收项使用 AC-001，修订时不重新编号旧需求。
2. **确定前端依据**：生成或评审交互页面前完整读取 `../frontend/SKILL.md` 并按其路由读取规范和 `reference.html`。引用规范版本、状态和适用的 P/C/I 编号。附带版本目前为 `0.1.0-draft`，只能标记“规范草案，待前端确认”；可继续生成评审预览，不得自行提升为已批准。
3. **生成可操作文件**：默认交付 `prototype/index.html`，必要的 CSS、JS、图片存入 `prototype/assets/` 并使用相对路径。可从参考页改造，但必须替换为当前需求，不能把示例业务或限制当作真实需求。使用本地模拟数据，双击 HTML 可打开，不依赖 CDN、在线字体、生产 API、构建工具或开发服务器；避免 file:// 下需要 fetch 本地 JSON 或模块加载的实现。若明确要求 React/Vue，则同时交付可打开的构建产物与必要源码及运行说明，不能只给源码声称可交互文件已交付。
4. **实现交互契约**：对范围内页面实现跳转、返回、查询/重置、分页、弹窗、校验、保存、取消和角色差异；按需求取舍，不凭空增加功能。可点击控件必须有可观察效果，保存应更新演示数据；取消不提交，保存失败保留输入，提交中避免重复操作。说明数据存于内存还是本地存储及刷新/重置行为。异常/空态/加载/无权限通过独立的“演示控制”切换，不混入业务字段。未实现功能明显标记且列入缺口，不能伪装完成。
5. **验证与评审**：读取 [评审模板](references/review-template.md)，逐项核对需求与原型。具备浏览器工具时实际打开交付文件并验证主路径、负向路径、页面状态、控制台错误及离线资源加载；记录执行环境、步骤、结果和证据。没有工具或未执行的项目写“未验证”，给出可复现步骤，不能沿用参考页的既有验证结果。
6. **一致性交付**：PRD（附录 E）、原型可见标识和评审记录使用同一交付 ID/版本；原型入口和评审引用可定位至具体页面或锚点。修改业务规则后更新对应原型、验收项和复测状态，旧评审不自动适用于新版。最后提供真实文件路径、打开方法、已检查项和未决事项。

## 最小交付包

用户指定目录优先；否则在当前项目 `product/<需求标识>/<交付版本>/` 中生成，不覆盖已评审版本。沿用项目既有命名约定。

```text
prd.md
prototype/
  index.html
  assets/           # 仅有资源时创建
review.md
```

原型文件是第一版默认交付。只有用户选择已存在的托管原型时才用固定版本链接替代，并记录不可变版本标识和访问限制；无权限核验时明确标注。文件没有实际写出或链接没有实际取得，不声称已交付。

## 完成边界

- AI 自检结论、人类产品评审、前端规范确认分别记录。没有人类确认时交付状态是“待评审”，不是“评审通过”；阻塞问题未解决不得称可直接研发。
- 原型的模拟权限、上传、保存不等于生产能力。新增组件/交互记录为扩展建议，不能称为已有前端组件。关键字段保持 ID/value 的类型和单多选契约。
- 不生成研发 `spec.md`、`design.md`、`tasks.md` 或执行正式系统测试，除非用户另外请求。这里的交互验证仅验证产品原型。
