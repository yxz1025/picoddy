# prd.md 遵循公司《产品PRD规范》改造设计

日期：2026-09-18
状态：已实现（2026-09-18，终审修复提交 `a6e69d4`）

## 背景

插件 `product-delivery` 技能输出的 `prd.md` 目前使用自研模板（交付元信息 → 背景目标边界 → 需求与验收 → 页面与流程 → 字段契约 → 角色权限 → 原型说明 → 风险待确认 → 版本变更）。

公司规范要求 PRD 统一使用钉钉在线文档，结构固定为：相关链接 / 文档说明 / 需求相关方 / 需求正文（背景、价值、清单、流程图、描述、埋点）。两者有重叠也有冲突，需要合并。

## 已确认的决策

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| D-1 | 模板结构 | 公司规范做正文骨架；插件特有的交付信息降为文末附录 A–F |
| D-2 | 钉钉与链接 | 保持 v1 不接入钉钉；相关链接未提供的一律写「待补充」 |
| D-3 | 真实信息 | 日期用实际交付日；人名、负责人一律「待填写」；当次提供则填入，不编造 |
| D-4 | 图文结合 | 需求描述用「标记点 1/2/3」文字编号 + 指向原型锚点；不自动截图 |
| D-5 | 附录 F | 风险与待确认项单列附录 F |
| D-6 | 改造范围 | 重写模板 + 同步 SKILL.md 等引用（方案 A）；规范原文随包保存，技能包保持自包含 |

## 目标产物：prd-template.md 新结构

标题：`# <需求名称>`，与 TAPD 需求名称保持一致。

### 正文（严格按公司规范，可单独复制进钉钉文档）

**1、相关链接（必有）**

- TAPD链接：
- 蓝湖设计稿链接：
- 业务需求文档链接：
- 数据调研分析链接：

填写规则：当次提供了就填真实链接；未提供写「待补充」；明确不涉及的可整行省略。

**2、文档说明（必有）**

| 序号 | 说明 | 日期 | 产品经理 |
| --- | --- | --- | --- |
| 1 | 完成产品文档 | <实际交付日期> | 待填写 |

第一行固定为「完成产品文档」；后续每次需求调整追加一行，说明列写清调整内容；日期用实际日期，产品经理未提供则写「待填写」。

**3、需求相关方**

需求方 / PM / PD / 交互 / UI / 前端 / 服务端 / 测试，共 8 项。全部「待填写」，当次提供了谁就填谁。

**4、需求正文**

一、需求背景（必有）：问题是什么、谁受影响、不解决的代价。区分事实与假设，有证据引用证据。

二、需求价值（必有）：用户价值与业务价值；成功指标，基线/目标缺失时标「待确认」。

三、需求清单：
- 从 1–N：`产品域 | 模块 | 需求` 表，条目必须带【新增】【改造】等改动类型标记。
- 从 0–1：产品架构/拆解说明或产品范围说明；无法给图时用文字范围说明代替并注明。
- 非目标（本次不做）在此节列出，保持插件「非目标必写」原则；公司规范无对应章节，统一放在本节清单表之后。

四、流程图/状态机：存在状态流转、多系统数据交互或纯接口对接（无界面）时必须给出（Mermaid 或文字状态表）；否则整节写「本次不涉及」。

五、需求描述（有界面时必有；纯逻辑/接口类可省略）：
- 按页面分节；每页面用「标记点 1/2/3」编号逐条描述。
- 每条带改动类型【新增】【改造】和对应 REQ 编号，并指向原型页面/锚点。
- 覆盖加载、空数据、错误、无权限、只读、成功状态；异常与边界单独列出。
- 纯后台规则标注「原型不可验证」。

六、数据埋点：有行为埋点或数据表抽取要求时必须（埋点表：事件/触发时机/参数）；否则整节写「本次不涉及」。

### 附录（本地交付与原型追溯用，不随正文进钉钉）

- **附录 A 需求与验收对照**：`需求 ID | 用户故事/业务规则 | 优先级 | 验收 ID 与 Given/When/Then | 原型页面/锚点 | 依赖/未决项`
- **附录 B 页面与组件映射**：`页面 ID | 对应需求 | 页面模式 P | 组件 C | 交互 I | 原型定位 | 与规范的差异及确认状态`
- **附录 C 字段与组件契约**：`页面/字段 | 业务含义 | 组件 | 显示值 | 存储值及类型 | 初始值/空值 | 单选/多选 | 校验/边界 | 联动清理规则`
- **附录 D 角色与权限**：`角色 | 页面访问 | 操作/数据范围 | 无权限呈现 | 原型模拟方式`
- **附录 E 原型说明与评审联动**：交付 ID/版本/状态、前端规范版本与批准状态、原型打开方法、模拟数据与保存/刷新行为、review.md 路径、钉钉「本版不接入」、版本变更影响（相对前版的需求/原型变化、受影响需重审或复测的验收 ID）
- **附录 F 风险与待确认项**：`问题 ID | 问题/假设 | 影响的需求 | 是否阻塞 | 待确认角色/负责人 | 状态与实际决定`

附录 A–F 的既有填写规则（稳定编号 REQ/AC、0 值边界、单选/多选契约、不编造通过结论）全部保留。
