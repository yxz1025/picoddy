# 会员方案 HTML 报告生成

> **交付标准：用户打开就能直接拿去汇报和执行，不需要再排版、再补图、再算数。**

---

## 一、硬性技术要求（**不可妥协**）

| 要求 | 说明 |
|---|---|
| **单文件自包含** | 所有 CSS / JS 内联，图表用**内联 SVG** 或原生 Canvas 绘制。**禁止**任何 CDN、外链字体、外链图片、外部请求 |
| **字体** | 只用系统字体栈，不外链 Web Font |
| **响应式** | 手机可读；宽表格包在 `overflow-x:auto` 容器内；页面本体不得横向滚动 |
| **深浅色** | 用 CSS 变量定义调色板；`prefers-color-scheme` 自动适配 + 手动切换按钮 |
| **可打印** | `@media print` 下隐藏导航与交互控件、避免章节被切断、图表可见 |
| **可交互** | 至少含：目录锚点跳转、阅读进度、章节展开收起、**一个可调参数的测算器** |
| **无障碍** | 语义化标签、合理对比度、图表配文字说明（不能只靠颜色传达信息） |

**生成方式**：基于 `templates/report-template.html` 修改，用 `Write` 工具写入用户工作目录。
默认文件名：`会员运营方案_{品牌名}_{YYYYMMDD}.html`

## 二、标准 12 章结构

| # | 章节 | 必含内容 | 关键图表 |
|---|---|---|---|
| **0** | **封面 + 执行摘要** | 一句话核心主张、4 个关键数字卡、3 条核心结论、本方案要解决的一号问题 | — |
| **1** | 业务现状与适配度判断 | 业务画像、该做哪种会员制及理由 | 会员制形态定位四象限 |
| **2** | 体系健康度体检 | 11 项指标现状/基准/差距/判定、问题优先级矩阵 | 体检雷达图、问题优先级四象限 |
| **3** | 策略主张 | 一号目标、北极星指标、要做什么 / **明确不做什么** | 策略主张卡 |
| **4** | 会员体系架构 | 形态、等级、门槛（含分位数依据）、成长值公式、保级降级 | 等级金字塔、门槛分布图 |
| **5** | 权益体系 | 各档权益表、感知/成本四象限、记忆点权益、权益成本测算 | 权益四象限、成本堆叠图 |
| **6** | 积分经济 | 汇率、发放规则、行为价目表、出口结构、五池模型、负债与沉淀率 | 积分五池流向图、出口结构环形图 |
| **7** | 全生命周期运营 | 六阶段策略、RFM 八分群及动作、自动化旅程清单 | 生命周期漏斗、RFM 九宫格热力 |
| **8** | 活动与营销日历 | 12 个月日历、重点活动详案、ROI 预估 | 年度日历甘特 |
| **9** | **三张账（算账章节）** | 权益成本账、积分负债账、生命周期迁移账、成本率与熔断阈值 | 成本结构图、三情景对比柱状 |
| **10** | **合规检查** | 逐项核对结果、需法务确认项 | 合规检查表 |
| **11** | 落地路线图 | 90 天分阶段计划、12 个月里程碑、组织分工、系统需求清单 | 甘特图 |
| **12** | KPI 看板与假设登记 | 12 项监控指标+目标值+预警阈值、**全部假设及待替换项** | 指标卡阵列 |

> **第 9、10、12 章是这份报告区别于普通"会员方案 PPT"的地方，绝不可省略。**
> 第 12 章的假设登记表尤其重要——它让用户清楚知道哪些数字是估的、要替换成什么。

## 三、内容写作规范

### 3.1 每一章的固定结构

```
【结论先行】     一句话说清这一章的结论（加粗，放在最前）
【依据】         数据/测算/方法论支撑
【方案】         具体做什么（表格化，可执行）
【风险与前提】   这个方案在什么条件下成立
```

### 3.2 数字规范

- **所有数字必须标注来源**：`【客户数据】` / `【行业经验值·待替换】` / `【测算，公式见附录】`
- **预测给区间**：`复购率预计提升 3–6pp`，不写 `提升 5%`
- **大额数字加千分位**：`1,280,000 元`
- **百分点用 pp，百分比用 %**：混用是不专业的表现

### 3.3 语言规范

- 用**动词开头**写建议："把第一档门槛下调至 388 元"，不是"关于第一档门槛的建议"
- **禁止空话**："提升用户粘性""加强精细化运营""打造闭环"——这类句子一律删掉重写
- 每条建议必须能回答："谁在什么时候做什么，成本多少，看什么指标"

## 四、图表规范

详见 `@references/chart-recipes.md`（含可直接复制的内联 SVG 代码）。

**图表选择原则：**

| 要表达 | 用什么图 | 不要用 |
|---|---|---|
| 阶段转化 | 漏斗图 | 饼图 |
| 等级人数分布 | 金字塔 / 横向条形 | 3D 饼图 |
| 成本/感知定位 | 四象限散点 | 表格堆文字 |
| 构成占比 | 环形图（≤5 项）/ 堆叠条 | 饼图切成 8 块 |
| 时间趋势 | 折线 | 柱状 |
| 分群矩阵 | 热力九宫格 | 表格 |
| 排期 | 甘特 | 文字罗列 |
| 三情景对比 | 分组柱状 | 三段文字 |

**图表铁律：**
1. 每张图必须有**标题 + 一句话结论**（"从图中可见…"要写出来，别让读者自己猜）
2. 数据标签直接标在图上，**不要让读者去对照坐标轴**
3. 颜色不超过 5 种，且与设计系统的图表色板一致
4. **不能只靠颜色传达信息**——加文字标签或图案区分

## 五、交互组件（必做）

| 组件 | 作用 | 实现要点 |
|---|---|---|
| **侧边目录 + 阅读进度** | 长报告导航 | `position:sticky`；滚动高亮当前章节；移动端折叠为顶部抽屉 |
| **章节展开/收起** | 控制信息密度 | `<details>` 或 JS 切换；默认展开前 3 章 |
| **参数测算器** ★ | 让用户自己调参看结果 | 滑块/输入框 + 实时计算 + 结果高亮；至少做「积分成本」或「权益成本」测算器 |
| **深浅色切换** | 阅读舒适度 | CSS 变量 + `localStorage` 记忆 |
| **返回顶部** | — | 滚动超过一屏后出现 |

> **测算器是这份报告最有价值的交互**。它把"一个静态结论"变成"一个可以被质疑和验证的模型"——
> 用户可以把自己的真实数字填进去，立刻看到结论怎么变。这是普通 PPT 做不到的。

## 六、生成流程

```
1. 读取 templates/report-template.html 作为基底
2. 按 12 章结构填充内容，删除用不到的示例区块
3. 图表：按 chart-recipes.md 的配方生成内联 SVG，替换示例数据
4. 测算器：把用户的真实参数设为默认值
5. 自检（见下）
6. Write 写入用户工作目录
7. 告诉用户：文件路径 + 报告含哪几章 + 建议先看哪两章
```

## 七、交付前自检清单

**技术**
- [ ] 无任何外部资源引用（搜索 `http://`、`https://`、`cdn`、`@import`、`<link` 确认）
- [ ] 深色模式下所有文字可读、图表可见（SVG 用 `currentColor` 或 CSS 变量）
- [ ] 手机宽度（375px）下无横向滚动，表格可独立横向滚动
- [ ] 打印预览正常，导航与交互控件已隐藏
- [ ] 测算器可正常计算，边界值（0、极大值）不报错

**内容**
- [ ] 12 章齐全（升级项目含 4.5 迁移方案）
- [ ] 第 9 章三张账数字完整（权益成本率、积分成本率与负债、迁移矩阵）
- [ ] 第 10 章合规检查逐项有结论
- [ ] 第 12 章假设登记表列全了所有代入的行业经验值
- [ ] 每张图有标题和一句话结论
- [ ] 所有数字有来源标注
- [ ] 有"不做什么"的明确列表
- [ ] **没有编造用户的经营数据**

**表达**
- [ ] 无"提升粘性""打造闭环"类空话
- [ ] 建议均为动词开头、可执行
- [ ] 预测均为区间且注明假设
