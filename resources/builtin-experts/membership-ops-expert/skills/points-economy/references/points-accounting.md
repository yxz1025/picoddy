# 积分负债、收入确认与合规

> **免责说明**：本文是**运营与管理会计视角**的测算与风险提示，用于让会员方案"算得清账、避得开坑"。

> 报告中引用本文内容时，必须保留这句免责说明。

## 一、为什么积分是负债，不是费用

用户消费时获得的积分，是"公司未来要向用户提供商品/服务/折扣"的承诺。
在收入准则（IFRS 15 / ASC 606 / 中国企业会计准则第 14 号——收入）的框架下：

1. 销售时授予的积分，通常构成合同中的**一项单独的履约义务**（因为它赋予了客户一项"重大权利"）；
2. 交易价格应按各项履约义务**单独售价的相对比例**进行分摊；
3. 分摊至积分的部分，在销售当期**不确认为收入**，而是先计入**合同负债 / 递延收益**；
4. 待客户**兑换积分**时，将对应部分转为收入；
5. 积分**失效/过期**时，剩余的递延部分也应转为收入。

**运营侧的三个推论：**
- 发积分不是"花掉一笔营销费"，而是"欠下一笔账"。这笔账在资产负债表上是真实存在的。
- 因此**积分成本率不能只看当期兑换支出**，必须看**流通池的增减**。流通池持续膨胀 = 负债在积累。
- 沉淀（breakage）会在未来转为收入，但**不能作为设计目标**——靠用户用不掉来盈利，是短视的体系设计。

## 二、积分负债的测算模型（管理口径）

```
【基础量】
  I  = 累计发行积分数
  R  = 累计已核销积分数
  E  = 累计已过期清零积分数
  O  = 流通池积分数 = I − R − E        ← 用户账上还躺着的积分
  v  = 单位积分价值（元/分），如 100:1 汇率下 v = 0.01
  b  = 预计沉淀率（0–1）

【负债估算】
  名义负债   L_nominal = O × v
  预期负债   L_expected = O × v × (1 − b)      ← 管理口径主用这个
  兑付成本   C_actual  = Σ(各兑换出口的实际成本)  ← 真实现金/毛利流出

【效率指标】
  负债消化效率 = 被消化的名义负债 ÷ 实际成本
      >1.5×  🟢 优秀（说明兑换品选得好：高售价、低成本）
      1.0–1.5× 🟡 一般
      <1.0×  🔴 亏（兑换品成本高于其名义积分价值，选品有问题）
```

### 每月必盘的六个数

| # | 指标 | 计算 | 健康信号 |
|---|---|---|---|
| 1 | 本月发行 | 当月新增积分 | 在预算带内 |
| 2 | 本月核销 | 当月消耗积分 | 与发行大致平衡 |
| 3 | 本月过期 | 当月清零积分 | 平稳，无集中尖峰 |
| 4 | 流通池余额 | O = 上月 O + 发行 − 核销 − 过期 | **不持续单向膨胀** |
| 5 | 流通池周转率 | 本月核销 ÷ 期初流通池 | 3–8%/月为宜 |
| 6 | 预期负债 | O × v × (1−b) | 占月 GMV 比例稳定 |

> **最重要的单一信号：流通池是否连续 6 个月单向膨胀。**
> 如果是，说明"发得比用得快"，负债在积累，且用户正在积累"积分没用"的印象——这是双重坏消息。

## 三、沉淀率（Breakage）的估算方法

### 方法一：历史队列法（首选，需 ≥18 个月数据）

```sql
-- 取 18 个月前某月发放的积分，追踪其至今的核销情况
WITH issued AS (
  SELECT user_id, points AS issued_pts, issue_date
  FROM points_ledger
  WHERE type = 'ISSUE'
    AND issue_date BETWEEN '2024-01-01' AND '2024-01-31'
),
redeemed AS (
  SELECT user_id, SUM(points) AS used_pts
  FROM points_ledger
  WHERE type = 'REDEEM' AND issue_batch_month = '2024-01'
  GROUP BY user_id
)
SELECT
  SUM(i.issued_pts)                                   AS total_issued,
  COALESCE(SUM(r.used_pts), 0)                        AS total_redeemed,
  1 - COALESCE(SUM(r.used_pts), 0) / SUM(i.issued_pts) AS breakage_rate
FROM issued i LEFT JOIN redeemed r ON i.user_id = r.user_id;
```

> 若系统未记录"核销的是哪一批积分"（多数系统如此），退而用**先进先出假设**近似：
> 按发放时间排序，假设用户优先消耗最早获得的积分。

### 方法二：衰减外推法（数据不足 18 个月时）

统计积分发放后第 1/2/3/6/9/12 个月的**累计核销率**，画出曲线并外推渐近线：

```
典型形态：
  M1   15–25%   ← 首月核销占比最高（活跃用户立刻用）
  M3   30–45%
  M6   40–55%
  M12  50–70%   ← 通常在此后趋于平缓
  渐近 55–80%   → 沉淀率 = 1 − 渐近值 = 20–45%
```

### 方法三：分层估算（更准）

不同人群的沉淀率差异极大，加权更准：

| 人群 | 典型沉淀率 | 说明 |
|---|---|---|
| 高频活跃会员 | 10–20% | 会主动兑换 |
| 中频会员 | 25–40% | 想起来才用 |
| 低频/沉睡会员 | 60–85% | 基本不会回来 |
| 一次性羊毛用户 | >90% | 基本全沉淀 |

```
加权沉淀率 = Σ(各人群积分占比 × 该人群沉淀率)
```

### 敏感性测算（**报告必做**）

沉淀率是估计值，必须给区间：

```
        沉淀率 15%    沉淀率 30%    沉淀率 45%
预期负债   XXX 万        XXX 万        XXX 万
成本率     X.XX%        X.XX%         X.XX%
```

## 四、合规风险清单（积分相关）

| # | 风险点 | 要求 | 落地动作 |
|---|---|---|---|
| 1 | **清零未告知** | 积分是消费者的既得利益，规则须提前、显著告知；未尽提示说明义务的格式条款存在被认定为不公平条款的风险 | 规则页显著位置公示；到期前 T-30/T-7/T-1 三次提醒并留痕 |
| 2 | **规则单方变更** | 不得单方面下调用户既有积分的价值 | 变更只对未来发放生效；既有积分给足过渡期 |
| 3 | **积分抵现被视为价格行为** | 折价、减价应标明基准 | 抵现规则页写清计算方式与上限 |
| 4 | **积分抽奖** | 抽奖式有奖销售最高奖金额不得超过五万元；须公示奖项、概率或数量、兑奖方式等 | 详见 `campaign-playbook/references/compliance-redlines.md` |
| 5 | **积分兑换实物的质量责任** | 奖品/赠品须符合国家规定，不得以不合格产品充当 | 兑换品需同样走质检与售后流程 |
| 6 | **积分与个人信息** | 用积分换取用户授权个人信息时，须单独告知并取得同意，不得强制 | "完善资料得积分"必须可跳过，且说明用途 |
| 7 | **积分对外兑换/转让** | 若涉及提现、跨主体流通、可自由转让，可能触及支付、预付卡或代币相关监管 | **默认不做积分提现与自由转让**；确有需要必须过法务 |
| 8 | **跨境/多主体积分互通** | 涉及数据出境与主体间债权关系 | 需单独合规评估 |

> **底线原则**：积分体系设计中，凡涉及"可提现、可转让、可跨主体流通"的设计，一律先停下来过法务。
> 这是把营销工具变成金融产品的红线，风险等级远高于普通促销。
