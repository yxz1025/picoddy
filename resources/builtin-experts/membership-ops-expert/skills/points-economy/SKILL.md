# 积分经济学

> **核心认知：积分不是营销费用，是公司发给用户的一种"内部货币"，本质是一笔负债。**
> 你在设计的是一套货币政策——要定汇率、控发行、管流通、防通胀、留退出通道。
> 绝大多数积分体系失败，是因为设计者只想了"怎么发"，没想"怎么收回来"。

---

## 一、积分设计五要素（缺一不可）

| 要素 | 要回答的问题 | 失败后果 |
|---|---|---|
| **① 定价** | 1 积分 = 多少钱？ | 用户算不清价值 → 无感知 → 不参与 |
| **② 发行** | 什么行为发多少分？总发行量上限？ | 成本失控 / 通胀 |
| **③ 消耗** | 有哪些出口？兑换比例？ | 积分堆积 → 用户认为是"假福利" |
| **④ 沉淀** | 多少积分永远不会被用？如何计提？ | 负债不可控，财务无法预估 |
| **⑤ 退出** | 有效期、清零、体系升级时怎么办？ | 用户投诉、舆情、法律风险 |

---

## 二、① 定价：先定单位价值，再定其他一切

**必须先确定 `1 积分 = X 元`，这是整个体系的汇率锚。**

| 方案 | 换算 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| **100 : 1** | 100 积分 = 1 元 | 数字大、有获得感；调节空间大 | 用户需心算 | **最推荐**，通用性最好 |
| 10 : 1 | 10 积分 = 1 元 | 换算简单 | 数字偏小，缺获得感 | 高客单行业 |
| 1 : 1 | 1 积分 = 1 元 | 极度透明 | 等于明码打折，失去积分的心理账户价值 | 不推荐 |
| 非货币积分 | 积分只换商品，不标价 | 可模糊定价、灵活控成本 | 用户不信任，感觉被糊弄 | 慎用 |

> **关键原则：让用户能一眼算出积分值多少钱。**"你有 3,200 积分 ≈ 32 元"这句话必须出现在会员中心。
> 用户算不清价值的积分，等于不存在。

### 发放系数

```
发放系数 r = 每消费 1 元发放的积分数

积分成本率 = r × 单位积分价值 × 预计核销率
           ────────────────────────────
                      1

示例：r=1（消费1元得1分），100分=1元 → 单位价值 0.01 元
     若预计核销率 60%
     → 积分成本率 = 1 × 0.01 × 0.60 = 0.6% GMV

常用档位（100:1 汇率下）：
  r = 1    → 名义 1% 让利，实际成本 0.4–0.7% GMV   ← 最常用起点
  r = 0.5  → 名义 0.5%，实际 0.2–0.35%             ← 低毛利行业
  r = 2    → 名义 2%，实际 0.8–1.4%                ← 高毛利/强争夺市场
```

**倍率的正确用法**：基础系数保守设置，把弹药留给**倍率**（等级倍率、会员日倍率、指定品类倍率、任务倍率）。
基础系数一旦定高就再也降不下来（降低必被投诉），而倍率是可以随时收放的阀门。**这是积分设计最重要的一条纪律。**

## 三、② 发行：把积分当预算管，不当赠品发

### 行为价目表（创新工具，**强烈推荐**）

不要只对"消费"发积分。把所有你希望用户做的行为都定价，形成一张**行为价目表**：

| 行为类型 | 示例行为 | 定价逻辑 | 建议积分（100:1 汇率） |
|---|---|---|---|
| 交易 | 消费 | 按 GMV × 系数 | 1 分/元 |
| 交易质量 | 好评 + 晒图 | 相当于一条 UGC 的采买成本 | 50–200 |
| 频次 | 连续签到 7 天 | 相当于一次触达的价值 | 20–100 |
| 拉新 | 邀请好友首购 | 应低于你的 CAC 的 30% | 500–2000 |
| 数据 | 完善画像/授权 | 一条精准标签的价值 | 50–150 |
| 迁移 | 首次使用小程序下单 | 渠道迁移一次的成本 | 100–300 |
| 跨品类 | 首次购买新品类 | 相当于一次品类种草成本 | 200–500 |
| 唤醒 | 沉睡后回访/回购 | 相当于一次召回成本 | 200–1000 |

**定价方法**：`该行为积分价值 ≤ 你原本为获得这个行为愿意付出的成本 × 60%`。
例如：一条真实好评在外部采买成本约 20 元，那么给 200 积分（=2 元）是极其划算的。

> **这张表是积分体系从"返利工具"升级为"行为引导系统"的关键。**
> 只发消费积分的体系，本质只是打折的另一种说法。

### 发行总量控制

```
月度积分发行预算 = 月 GMV 预测 × 目标积分成本率 ÷ 预计核销率

必设三道闸：
  ① 单用户单日积分上限（防刷）
  ② 单活动积分池上限（发完即止）
  ③ 月度总发行熔断（超过预算 X% 时自动下调倍率）
```

## 四、③ 消耗：出口决定体系生死

**积分核销率低于 20%，用户就会认定"这积分没用"，整个体系失效。**

### 出口设计的黄金结构（**至少要有三类出口**）

| 出口类型 | 作用 | 建议占比 | 例子 |
|---|---|---|---|
| **高频小额出口** | 让用户经常用到，形成"积分有用"的认知 | 40–50% | 积分抵现（限比例）、小额兑换券、运费抵扣 |
| **中频商品出口** | 主力消耗渠道，成本最优 | 30–40% | 兑自有商品、小样、周边、升杯 |
| **低频大额出口** | 提供"攒积分"的终极目标 | 10–20% | 大额商品、稀缺体验、限量款 |
| **兜底出口** | 消化零散积分，避免过期怨气 | 5–10% | 积分抽奖、公益捐赠、积分换机会 |

**兑换门槛设计**：
- 最低兑换门槛应设在 **用户 1–2 次消费即可达到** 的位置。门槛过高（如要攒半年）= 没有出口。
- 兑换品的**积分标价**要略优于现金价（体现"用积分更划算"），否则用户宁可付钱。

### 兑换比例与成本

```
兑换出口的实际成本 = 兑换品成本价 ÷ 所需积分 ÷ 单位积分价值

举例：售价 30 元、成本 9 元的商品，标价 2000 积分（名义价值 20 元）
     → 用户感知：省了 30 元，很划算（用 20 元的积分换了 30 元的东西）
     → 公司成本：9 元
     → 实际杠杆：用 9 元成本消化了 2000 积分（名义负债 20 元）
     → 负债消化效率 = 20/9 = 2.2×  ✅ 优秀

原则：优先选择「售价高、成本低、用户想要」的自有商品作为兑换品。
      这是把积分负债转化为营销价值的最高效方式。
```

## 五、④ 沉淀：积分负债五池模型（**本 Skill 的核心工具**）

```
┌─────────────────────────────────────────────────────────┐
│                     积分负债五池模型                       │
├─────────────────────────────────────────────────────────┤
│                                                          │
│   ① 累计发行池  ──────────────┐                          │
│      (Issued)                │                           │
│                              ▼                           │
│                        ② 流通池 (Outstanding)             │
│                        = 用户账上未使用的积分              │
│                        ★ 这就是你的积分负债 ★             │
│                              │                           │
│              ┌───────────────┼───────────────┐           │
│              ▼               ▼               ▼           │
│      ③ 已核销池        ④ 沉淀池          ⑤ 已清零池      │
│      (Redeemed)      (Breakage,        (Expired)         │
│      真实成本发生      预计永不使用)      转回收益          │
│                                                          │
└─────────────────────────────────────────────────────────┘

积分负债 = 流通池积分数 × 单位积分价值 × (1 − 预计沉淀率)
```

**必须每月盘一次这五个池子。**没有这张表的积分体系，是在盲开。

### 沉淀率（Breakage）估算

沉淀率 = 最终永远不会被兑换的积分占已发行积分的比例。

**估算方法（按数据成熟度选）：**

1. **历史队列法（最准，有 ≥18 个月数据时用）**：取 18 个月前发放的积分，看其至今的最终核销率，`沉淀率 = 1 − 最终核销率`。
2. **衰减外推法**：观察积分发放后 1/3/6/12 个月的累计核销曲线，拟合渐近线。
3. **行业占位法（无数据时）**：先用 `25–40%` 做基准，同时用 `15%` 和 `50%` 做敏感性测算。

> 行业研究反映，忠诚计划中存在大量长期未被使用的积分——沉淀是普遍现象，但**沉淀率高不等于好事**：
> - 沉淀率过高（>50%）→ 用户认为积分无用，体系失去激励作用；
> - 沉淀率过低（<15%）→ 成本压力大，且可能存在套利。
> **健康区间：20–40%。**

### 财务口径提示

在企业会计准则/IFRS 15 框架下，销售时授予的积分通常构成一项**单独的履约义务**：应按单独售价的相对比例，把交易价格分摊至积分部分，先确认为**合同负债/递延收益**，待用户兑换（或积分失效）时再转为收入。详见 `@references/points-accounting.md`。

> 这决定了积分不能只在管理口径当营销费用看待。方案中应给出负债估算模型，并**明确建议与财务确认口径**。

## 六、⑤ 退出：有效期、清零与合规

### 有效期设计

| 方案 | 说明 | 评价 |
|---|---|---|
| 固定期限（如获得后 12 个月） | 滚动到期，全年分散 | 🟢 **推荐**，避免年末集中清零引发舆情 |
| 自然年清零（12/31 统一） | 简单 | 🟡 集中清零易上新闻，需强力提前告知 |
| 有效期随活跃延长 | 有交易即延长全部积分有效期 | 🟢 兼具促活功能，航司常用 |
| 永不过期 | — | 🔴 负债无限累积，不推荐 |

### 清零的三条硬规则 🔴

1. **规则必须在用户获得积分之前就明确告知**，且以显著方式呈现（不能藏在长协议里）。
2. **到期前必须多次提醒**：建议 T-30 / T-7 / T-1 三次，并直接给出"一键兑换"入口。
3. **规则变更只能对用户更有利**，或给足过渡期。既有积分的价值不得单方面下调。

> **法律视角**：积分是消费者基于交易取得的既得利益。经营者单方面清零而未尽到提示说明义务的，相关格式条款可能被认定为不公平条款、侵害消费者权益。实践中的争议焦点通常是：**是否提前充分告知、条款是否公平合理**。
> 因此：告知留痕（站内信/短信/APP 弹窗记录）是必做的风控动作。

## 七、通胀治理：积分体系的长期杀手

**症状**：积分越发越多，兑换品越来越贵，用户觉得"积分越来越不值钱"。

**成因**：活动期无节制加倍 → 流通池膨胀 → 为控成本提高兑换门槛 → 用户感知贬值 → 参与度下降 → 为拉参与再加倍 → 恶性循环。

**治理手段（按优先级）：**

| 手段 | 做法 | 备注 |
|---|---|---|
| **锁死汇率** | 对外承诺"100 积分 = 1 元"永不变 | 汇率是信任基础，绝不能动 |
| **只调倍率不调基础** | 收缩活动倍率，保持基础系数不变 | 用户对倍率变化容忍度远高于基础规则 |
| **增加优质出口** | 引入高性价比兑换品，加速消化流通池 | 治标最快的手段 |
| **限时高价值兑换** | "本周积分兑换 5 折" | 集中消化，同时制造惊喜 |
| **积分池上限** | 单活动池发完即止 | 从源头控发行 |
| **成本熔断** | 月度成本率超阈值自动降倍率 | 必须写进方案 |

**绝对禁止**：直接下调用户既有积分的价值（如"原 100 分抵 1 元改为 200 分抵 1 元"）。这等于货币贬值，必然引发信任崩塌与投诉。要控成本，只能从**发行端**和**出口结构**入手。

## 八、常见反模式速查

| 反模式 | 后果 | 正解 |
|---|---|---|
| 只发不给出口 | 核销率 <10%，用户认为是假福利 | 上线前先把三类出口备齐 |
| 兑换门槛高到要攒一年 | 用户放弃 | 门槛设在 1–2 次消费可达 |
| 积分不可见 | 用户不知道自己有多少分 | 首页、订单页、支付成功页都要露出 |
| 只显示分数不显示价值 | 用户无法判断值不值 | 必须同时显示"≈XX 元" |
| 大促期无上限加倍 | 单月成本率暴增数倍 | 设活动池上限 + 熔断 |
| 积分可无限抵现 | 等于全场打折 | 抵现比例封顶 10–20% 订单额 |
| 退货不扣积分 | 必被刷 | 退货同步扣回，且要防负数 |
| 线上线下积分不通 | 用户体验割裂、投诉多 | 优先打通，至少做到可查询 |
| 积分永不过期 | 负债无限累积 | 设有效期 + 提醒 |
| 集中年末清零无提醒 | 舆情风险 | 滚动到期 + 三次提醒 |
