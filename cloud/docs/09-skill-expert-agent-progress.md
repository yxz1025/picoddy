# 技能、专家与 Agent 后续对齐

日期：2026-10-12。依据已批准的 full-desktop-parity-design，所有变更限 cloud/，不迁移桌面数据。

## 本轮执行顺序

1. 技能创建会话与用户级草稿：完整文件集、路径/大小校验、草稿 revision、校验结果绑定 revision。
2. 发布与修订：仅用户 HTTP 确认可发布；事务内复验、baseVersion 比较、不可变版本插入与指针切换。旧版本可以通过显式回滚选择恢复。
3. 草稿 Agent 工具：沿用 skill_draft_* 名称，只操作当前用户当前会话草稿，不提供发布工具；写操作校验任务租约，Ask/Plan/readonly 不获得写能力。
4. 桌面同款技能面板接真实云端接口，安装提交携带用户所见的草稿 revision，避免校验后内容变化却安装新内容。
5. 专家持久绑定：空闲会话绑定/清除，每轮取当前有效专家和技能版本，冻结运行中快照；不扩大工具权限。
6. 继续 P2 完成边界、持久问答与子任务，按各自行为测试验收；不能因 P5 基础完成就标记整阶段完成。

## 数据与授权

技能草稿使用 PostgreSQL JSON 文件清单，与既有不可变 skill_versions 一致；不在控制面执行包内代码。导入附件只允许本轮选择的 owner 文件。草稿属于 skill_creator 会话；草稿文件校验复用现有技能包约束。发布需要草稿有效且 revision 匹配，并拒绝会话运行期间发布。已安装状态只读；用户创建修订版后才能继续编辑。

专家为资源配置覆盖层，不是独立权限主体。会话绑定只引用同 owner 的有效 expert；刷新只影响下一轮。企业市场认证、专家包编辑/发布及其余 Agent 能力分别记录，不伪造市场数据。

## 验证记录

本轮代码落地（不是 P5/P2 全阶段完成）：

- `skill_creator` 会话与私有草稿、完整文件集修订、附件导入、结构校验、用户确认发布、不可变版本与并发比较；发布/修订不能在任务运行期间进行。Agent 只有当前会话草稿操作能力，没有安装/发布能力。
- 上传包和草稿统一按排序后的文件内容计算版本，不再按 ZIP 容器字节计算。回滚 API 使用 expectedVersion，尚无回滚选择 UI。
- 复用桌面技能草稿面板与编辑会话入口；安装确认携带所见 revision。二进制资源不会被简化文本编辑器截断。
- 专家会话绑定/清除/卸载持久化；普通选择器和召唤专家入口接服务端。每轮读取当前配置并冻结快照，旧浏览器选项不覆盖服务端绑定，运行中不能换专家。
- `ask_user_question` 独立持久化问题/答案，owner/run/tool-call 绑定、一次性幂等提交、5 分钟过期、取消/租约检查；无人值守任务不能等待问答。SSE 与重连恢复接桌面问答弹窗，提交失败保留重试，不视为权限审批。

验证使用临时 PostgreSQL 17 容器、云端专属测试，未操作现有开发/生产库：

- `TEST_DATABASE_URL=… npm test`：190 项通过，0 失败、0 跳过。
- `npm run build`：通过，包括服务端与 Web TypeScript 检查；Vite 仍提示主包超过 500 kB。
- 覆盖草稿归属/租约/版本冲突/完整包发布与回滚、专家绑定与下一轮快照、UI 绑定失败状态、问答持久化/幂等/取消/过期。

审查修复了草稿/上传版本算法不一致、Agent 服务权限过宽、修订元数据残留和专家仅本地绑定问题。后续独立复审因模型容量不足未能完成；不能标记独立审查通过。
