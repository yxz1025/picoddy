# Web 桌面界面对齐与存储调整

## 背景与确认

用户要求浏览器端沿用桌面端全部页面样式和交互，只维护 `cloud/` 内独立代码，不修改桌面目录；并确认实施。此前云端基础工作台不是桌面界面的复刻。本次以桌面源组件为基准，禁止用新的近似界面替代。

## 目标与非目标

- 独立复制桌面 React 组件、CSS、图标、状态模型至 `cloud/web/desktop/`，不运行时依赖桌面源码。
- 浏览器入口使用同一侧栏、欢迎页、聊天、设置、专家、项目与自动化布局。
- 用浏览器 HTTP/事件流适配替换 IPC；认证沿用云端账号，执行仍在 OpenSandbox。
- 文件默认保存在服务器本地持久目录，S3 为可选配置，不是本地启动必需项。
- 不恢复本地机器访问，不在浏览器伪造 Electron 对象；本地目录选择等动作按云端语义调整。
- 企业认证、TAPD、SkillHub 等未实现领域仍按 05 文档分阶段接入，不能仅复制 UI 就声称业务完成。

## 方案与影响范围

全部改动位于 `cloud/`。桌面源复制后两套独立维护；页面组件优先不变，在 API 边界转换云端资源模型。会话、附件、模型、技能、工作空间、审批和任务流使用现有鉴权接口。不存在的云端操作必须返回明确错误，不能返回模拟成功。

文件存储保持 Storage 接口，新增 local 实现，校验存储键与路径边界并原子写入。API 与 Worker 必须共享持久目录；多主机部署选择共享存储或 S3。S3 模式才要求对应凭据。

## 阶段任务

1. 迁入桌面组件/CSS/依赖，浏览器认证和入口适配。
2. 资源 API 映射与附件上传，移除运行时桌面源码依赖。
3. 会话事件流、审批和恢复逻辑接入。
4. local/S3 配置、共享卷与运维说明。
5. 类型与差异检查，记录未完成业务能力；测试和构建须另获授权。

## 风险与验证

桌面与云端模型不完全一致，重点检查模型配置、技能选择、事件恢复及文件鉴权。复制源码不代表业务接口已移植。禁止将未知 API 的空数据解释为成功。保留桌面已有改动。默认只运行 TypeScript/语法及 diff 检查；真实登录、视觉比对、沙箱执行、Windows 启动与构建尚需环境及测试授权。
