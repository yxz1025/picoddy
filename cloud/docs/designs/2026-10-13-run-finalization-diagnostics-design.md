# 云端任务收尾失败诊断设计

## 背景与目标

普通会话“查询今天AI科技的新闻”已输出完整答案，却以 RUN_EXECUTION_FAILED 结束。目标是定位并修复真实收尾异常，保留模型输出、文件完整性和用户隔离约束。

## 已确认现状

- 任务 1ae21073-f268-438e-a725-e1bed62d497d 最终 assistant 消息 stopReason=stop；中途 Connection error 后已有成功重试。
- 实际联网工具为 browser，通过 cloud/runtime/browser.mjs 在沙箱运行 Playwright Chromium，并访问新闻频道及 Bing 新闻搜索页。Cloud 未加载桌面精选插件 pi-web-access。
- 工作区版本已进入 staging，清单包含 output/browser.png（239501 字节），未产生 workspace_sync 事件；对应 OSS 对象不存在。
- 原任务日志显示清单与截图下载接口均返回 HTTP 200。HTTP 成功不证明下载字节满足清单大小与摘要校验。
- 当前 OSS 随机小文件上传、删除成功；不据此排除原任务的瞬时存储异常或特定对象操作异常。
- 临时沙箱读取复现尝试在健康检查阶段超时，没有进入文件读取；不能用该次失败证明原任务失败原因。
- Worker 将未知异常统一映射为 RUN_EXECUTION_FAILED，只记录 errorType，无法从现有记录区分下载、完整性检查、上传和提交异常。

## 非目标

不把错误任务强制改成成功；不删除业务记录；不跳过文件校验；不将模型或工具原始异常、密钥、对象路径发送到浏览器；本次不替换联网搜索方案。

## 方案（待确认）

1. 为工作区回写的扫描、文件读取、完整性检查、上传和数据库提交提供明确阶段与固定错误码。Worker 对这些已知错误保留安全分类，服务端仅输出阶段、异常类型及可安全枚举的状态码，不输出原始异常字符串。
2. 用临时独立沙箱重放截图生成、清单扫描、字节读取、摘要比对及受控 OSS 上传流程，销毁沙箱并清理诊断对象。不得重跑原任务的业务操作或改变原任务状态。
3. 证实根因后完成针对性修复；若需要改变浏览器截图保存位置或持久化语义，先补充该设计并取得确认。不以隐藏错误代替修复。

## 影响与风险

修改限 cloud 的工作区领域、Worker 错误分类与回归用例；不修改桌面代码、不迁移数据库。API 控制面使用平台无关的 TypeScript；Linux 沙箱边界保持现状。错误分类不得泄露用户内容或凭据。

## 验证

进行 TypeScript 与差异格式检查；经授权在隔离环境验证二进制摘要、不同失败阶段及成功收尾。检查正常完成的文字答案、截图回写和失败分类，不依赖真实模型重复生成新闻。Windows 实机未验证，不宣称已通过。
