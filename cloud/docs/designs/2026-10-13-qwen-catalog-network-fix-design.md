# 通义千问目录请求失败修正

## 现状与根因

用户报告云端通义千问配置页无法加载目录。当前本机 DNS 将 dashscope.aliyuncs.com 解析为 198.18.2.180，即本地代理的 Fake-IP。云端 transport 将整个 198.18.0.0/15 作为保留地址拒绝；桌面式 fetch 在同一官方地址能够完成 TLS 并收到 401（该验证未携带 Key），云端请求则在发出前失败。目录路径与桌面相同，但云端遗漏了 language=zh-CN。

## 修正范围

- 仅当服务端 PUBLIC_ORIGIN 为 loopback 开发地址，且请求域名属于内置的精确官方模型域名集合时，允许代理 Fake-IP 范围 198.18.0.0/15。其余私网、loopback、metadata 地址继续拒绝；自定义域名不得使用此例外。生产 origin 不启用该例外。
- 例外由服务端配置的 origin 决定，不从请求体或浏览器 Origin 读取；继续在实际 socket DNS lookup 检查全部地址，保留原域名 TLS/SNI 校验、443、超时、体积限制和禁止重定向。
- 将已知 DNS 拦截、请求超时、响应过大及响应格式错误区分为固定安全提示，不回显 Key 或上游原始错误。
- 补齐通义千问目录 language 参数，沿用桌面 UI 和保存操作。

## 验证

测试本地官方 Fake-IP 可用、生产和自定义域名仍拒绝、私网及混合地址不被放行；测试错误脱敏及 Qwen URL。真实不带 Key 请求从网络失败恢复为官方 401，证明连接链路恢复；未使用或读取桌面模型 Key，用户本次尚未保存的 Key 需在页面重试目录来验证权限。

## 实施结果

- 新增请求工厂，诊断服务传入服务端 PUBLIC_ORIGIN；默认通用请求保持严格公网检查。实际 socket lookup 回归验证了本地官方 Fake-IP 成功、生产/自定义/混合私网拒绝。
- 真实本地请求已经收到官方 401；严格模式仍返回 MODEL_DNS_BLOCKED。明确无效测试 Key 经过真实云端目录服务返回“身份验证失败”，不再误报网络目录失败。
- DNS、超时、响应体积及格式错误已使用固定脱敏 code/message；Qwen URL 已补 language=zh-CN。
- 全量专用测试库回归 330 passed、0 failed、0 skipped；类型检查及构建通过。构建仍保留现有主包体积警告。
- 已更新本地 API。未读取用户本次尚未保存的 Key、未发起真实计费推理，目录权限由用户保留在页面中的 Key 重试验证。
