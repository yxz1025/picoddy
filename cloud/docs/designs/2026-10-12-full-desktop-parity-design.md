# 浏览器云端全量桌面对齐：范围扩展设计

日期：2026-10-12。状态：用户已批准。本文件扩展已批准的核心后端对齐设计；不是已完成清单。

## 背景与判断

用户要求“请全量对齐”。此前设计的非目标明确排除了全部桌面领域迁移、OSS、工作目录同步及企业集成。只拆 HTTP/领域目录，或保留桌面组件但让接口返回 unsupported，都不满足新的要求。

已核对桌面工具装配、prompt tool-policy、领域服务、云端 HTTP 和 Web adapter。桌面工具集合由 mode/category/权限决定；云端仍是固定集合。桌面来源 Web 仍有显式未接入的企业市场、技能草稿、分支、模型管理、连接器生命周期等入口。不能把“页面长得一样”“类型检查通过”作为全量验收。

## 目标与不变边界

2026-10-12 追加确认：用户要求完整保留桌面业务能力，仅替换云端必须的环境边界，并明确授权自动化测试。云端移除“项目”功能（TAPD 项目/需求工作流与项目面板），保留个人空间、会话及文件。用户进一步明确：这是全新项目，无历史数据；云端和桌面数据不打通。统一采用 workspace/workspace_id/workspaceId 和 /api/workspaces；不保留历史字段、升级迁移、桌面导入或同步。桌面目录保持不变。

- 所有开发只在 `cloud/`；两套独立维护，不运行时 import 根目录源码，不改桌面行为。
- 沿用 application → agent/domains → platform/infra 的职责，复制可移植业务规则并记录来源；保留云端 PostgreSQL、owner、持久队列、租约、审批和 SSE。
- 浏览器是唯一用户入口；用户技能、脚本、插件和 CLI 均在 OpenSandbox，绝不在 API/Worker 宿主进程执行。继续不采用 Kata。
- 桌面的业务交互、字段、校验和工具结果以当前可达代码为准；本机路径改为私有空间路径，系统打开改为浏览器预览/下载，企业凭据改为服务端按用户加密保存。
- 用户电脑截图、鼠标键盘控制、系统权限、托盘/悬浮窗/更新器、钥匙串、打开本机目录不迁移。远程浏览器操作属于沙箱能力，不等于恢复用户本机能力。
- 不把桌面 `connect_cloud_service` 的 token 输出给模型行为迁入云端。
- 不使用示例数据、空数组或固定成功值代替实际业务。未部署或未配置时返回结构化 unavailable 原因，页面保留真实状态。

## 关键方案

### 1. 工具合同、授权与提示词

桌面入口：`src/agent/tools/index.ts`、`prompt-runtime/tool-policy.ts`、`engine.ts`、`provider.ts`。

工具名和参数直接对齐，但不是照搬宿主 fs/spawn。优先采用 Pi 工具的 operations 注入；没有可注入接口的纯算法迁入云端，由 OpenSandbox 负责实际读写/命令。read 支持分页/图片，edit 保留精确替换和 diff，文档生成/编辑保留结构化结果。所有子工具、动态发现和插件也必须过统一权限门禁。

mode/category/tool-policy 在提交时验证并冻结；不能仅修改提示词来实现只读。ask 不注册工具，plan 不允许 bash、文件写入或未知副作用 MCP。未声明只读的第三方工具不能自动视为只读。任意用户代码的 codemode 不能在控制面执行，需沙箱 RPC 调用已授权工具。

### 2. 持久交互与完成边界

问题、答案、审批和父子 run 使用不同业务类型，均匹配 owner/run/调用 ID。答案只能提交一次，取消后拒绝继续，超时清理，恢复不自动执行不确定副作用。不得把自由问答伪装成 boolean approval。

`goal_complete` 是独立工具调用，混合批次拒绝；最近交付文件及摘要复验后才能确认文件任务成功；确认后冻结工具，仅允许最终解释。云端交付使用不可变下载对象；如沙箱源内容后续变化，要求重新交付，不静默覆盖旧批次。纯文本任务正常结束。

### 3. 存储、预览与恢复

沿用独立 OSS/桌面预览设计，不让模型或用户通过任意 URL 指定服务端取件。对象 key 由服务端生成，元数据按 owner/workspace/version 鉴权。工作空间权威清单在数据库，文件字节在 OSS；沙箱仅为执行副本，不能作为唯一持久存储。

提交运行冻结输入清单；结束前上传新增/变更内容并以 expectedRevision 比较后提交，冲突返回明确状态。删除采用可恢复标记与后台对象回收，不能把数据库和 OSS 删除假装成跨系统原子事务。大文件上传和预览需要流式/配额限制。

预览复用桌面真实方式：DOCX 转 HTML、XLSX/CSV 表格、PPTX 文本/页面模型、PDF 浏览器渲染。并非默认引入高保真 Office 在线编辑。HTML/脚本站点使用隔离域或严格 sandbox iframe；外部 URL 不自动访问用户网络。

### 4. 企业身份和凭据

用企业 Web 回调替代桌面 loopback 登录，不复用桌面本地 token 文件。stable subject 与本站 user 绑定；账号禁用撤销站内 session。SkillHub 的共享认证密钥仅管理员配置，不允许任意普通用户改全局密钥。第三方 token 按 owner/服务加密存储，日志、模型上下文和技能包不得包含秘密。

TAPD、零售和 Filez 保留具体领域 API 与前端合同，后端固定上游、验证组织权限、审计真实写操作；需要生产写入时另取执行授权。

### 5. 数据与接口演进

新增表按阶段设计并合入 database/schema.sql：会话模式/分支、用户设置、工作记忆、空间文件版本、草稿/发布记录、问题答案、父子运行、企业账号连接、RAG 索引与任务。每张表必须有可验证的 owner 关系；资源引用不只检查 UUID。使用独立 PostgreSQL，不连接桌面 SQLite。db:init 只初始化空 schema，同一结构可重复执行；结构指纹不匹配或非空未知库明确拒绝，不自动清空或升级。API/管理员启动只检查初始化状态。

HTTP 层只做协议适配；云端持久调度与桌面同步代码不强行同形。Web adapter 只在真实领域合同落地后删除对应旧映射，避免组件提前依赖不存在的能力。

## 影响与风险

- 仅 `cloud/src`、`cloud/web`、`cloud/runtime`、`cloud/database`、`cloud/test`、`cloud/docs` 和云端依赖/部署配置变化。
- 不可避免有新 schema、API 与运行状态，而不是“只移动现有代码”；这是本扩展设计需要确认的实质变化。
- 任意技能/插件和网络访问必须受沙箱出网/配额/进程限制约束；OpenSandbox 本身不等于所有租户安全问题已解决。
- 跨对象存储/数据库提交有不确定窗口，需幂等收据、版本及回收机制，不承诺任意外部副作用 exactly-once。
- 预览同源执行、企业身份串号、索引漏过滤、子代理递归和后台任务泄漏都是发布阻断项。

## 验证规则

先写行为回归源码。用户现已明确授权自动化测试与本次改造验证；使用独立临时测试数据库运行迁移/集成测试，不操作开发或生产数据库。真实 OpenSandbox、OSS 和企业系统联调仍需实际部署配置，未执行不得标通过。

全量验收用桌面实际注册表与前端可达 API 生成基线，记录每项：桌面入口、云端实现、保留差异、授权规则、回归证据、部署依赖。任何非本机能力的 unsupported 必须仍列为未完成。安全阻断不能用“桌面也是如此”豁免。

## 批准记录与 RAG 范围澄清

用户已批准按上述 P0–P9 扩大实施范围，在 `cloud/` 内新增所需数据表、状态和接口。企业联调仍需 Web 登录/第三方测试配置。

RAG 基线是桌面内置实现，不代表已接企业知识库：`src/agent/tools/rag.ts` 的四个工具由 `tools/index.ts` 注册；`provider.ts` 在实际激活 rag_query 时调用 withRetrievedDocuments；`domains/rag/node/store.ts` 使用 FTS5/BM25 与向量混合检索，`embedding.ts` 使用本地 Xenova/all-MiniLM-L6-v2，失败时降级关键词检索。迁移需隔离 owner/workspace/file 和索引版本，解析与本地模型推理在受控沙箱执行；不默认接外部 embedding API，不外发文档。模型资源获取与云端依赖/运行验证仍需单独落实。

P1 已恢复桌面静态提示词规则，独立复制到 cloud/resources/prompts/v2；身份改为云端，追加真实沙箱边界。已接入 assistant 的 Ask/Plan/Craft 与实际工具策略，Creator category 尚待工作流实现。每次 manifest 记录已加载片段的路径、哈希、字节数。用户自定义 agent_system_prompt 已通过用户设置、提交冻结和运行时投影接入，存储任务缺失这些冻结字段时拒绝执行。

无需改变已确定的 OpenSandbox、OSS 目标、浏览器唯一入口和不修改桌面目录四项选择。
