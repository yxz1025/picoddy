# OSS 持久化与桌面同款文件预览

日期：2026-10-12。状态：已纳入用户批准的全量对齐方案。OSS 驱动和鉴权内容接口已接入；Office 预览队列、前端渲染及完整空间持久化仍待实施。

## 背景与目标

用户要求所有云端代码独立维护在 cloud/，文件持久化使用 OSS，预览保持桌面端的组件、交互和解析能力，不引入 IMM/WebOffice，不使用 Kata。用户已确认“OSS → 用户隔离空间 → 解析 → 浏览器展示”的方向。

本设计覆盖已上传文件、已发布交付物，以及后续工作空间文件统一使用的存储和预览入口。OSS 保存原件；数据库保存归属和文件版本；OpenSandbox 提供临时隔离解析环境；浏览器负责最后的展示。私有空间指服务端隔离空间，不是用户电脑。

## 现状证据

- cloud/src/storage.ts 提供 put/get/remove/ready，支持 local 与 s3；OSS 尚未实现。
- cloud/src/files-api.ts 通过 id + owner_id 查询文件后代理下载，客户端不能指定对象 key。
- cloud/web/desktop/src/components/PreviewPanel.tsx 当前统一调用简化的 CloudFilePreview，并未接上桌面完整预览分支。
- 桌面 application.electron.ts 的 /api/preview：DOCX 用 mammoth 转 HTML，XLSX 用 exceljs 返回每表前 100 行，PPTX 用 readDoc 提取文本。
- 桌面 PdfPreview 使用文件接口和 iframe；BrowserPreview 使用 Electron webview，不能直接用于普通浏览器。
- cloud/src/sandbox.ts 已有隔离读写、命令执行和销毁能力；预览任务还没有独立生命周期记录。
- 当前 projects 只有空间业务元数据，任务使用新沙箱；不存在完整工作目录自动同步机制。

## 方案选择

1. 采用：原生 OSS 驱动 + 桌面解析协议 + 原有预览组件。与现有能力一致，变更集中在云端文件边界。
2. 不采用：OSS + IMM/WebOffice。会改变 Office 预览效果、交互和费用，超出本次一致性要求。
3. 不采用：将 OSS 挂载为普通磁盘。对象存储不承担运行目录的文件系统语义，也不解决用户鉴权。

## 存储与配置

- 新增 STORAGE_DRIVER=oss，保留 local 开发模式与现有 s3 模式；显式配置驱动，不自动跨驱动降级。
- OSS 使用官方 Node SDK；实施时核对 SDK 版本与官方接口，更新 cloud/ 内的依赖锁。配置包含地域、Bucket、HTTPS 端点及服务端凭据；采用独立 OSS 配置项，避免误用 S3 参数。
- 密钥仅在服务端环境或部署 secret 中配置，不传浏览器、Agent 或解析沙箱，不提交 .env。支持的凭据模式及临时凭据刷新约束必须明确记录，不将固定 STS token 描述成永久凭据。
- Storage 接口尽量保持稳定；补充有界读取能力，预览同时检查数据库大小和实际读取字节数，防止异常对象耗尽内存。
- 默认不创建 Bucket、不修改 ACL。按用户最新要求，这是全新独立系统，不做旧对象迁移，也不与桌面同步。缺失对象明确报错。

## 文件与预览接口

- 浏览器以 fileId 请求，不接受服务器绝对路径、任意 OSS key 或远程 URL。
- 保留 GET /api/files/:id/download 的下载语义。
- 新增 GET /api/files/:id/content：逐请求鉴权，安全格式按可信扩展名映射 Content-Type，支持 PDF/视频所需的 Range；HTML/SVG 不直接作为主应用同源活动页面返回。
- 新增 POST /api/files/:id/preview 创建或复用预览，返回 ready 或任务 ID；GET /api/files/:id/preview 返回该用户可读的解析结果或处理中/失败状态。所有写接口沿用 Origin 校验。
- 返回与桌面组件相符的数据形态：DOCX html、表格 sheets、PPTX text、文本 text。前端调整取数方式而非重新设计组件。
- 预览任务使用数据库持久队列，由 Worker 执行，API 不直接执行文件解析。新增预览任务表保存 owner_id、file_id、内容 SHA-256、解析器版本、状态、租约、沙箱 ID、结果对象 key、错误码。
- 缓存键包含用户、文件 ID、内容 SHA-256、解析器版本；缓存命中也必须重新鉴权。相同键并发请求合并，失败允许明确重试。

## 隔离解析与缓存生命周期

1. Worker 领取任务，重新校验文件归属与存在性，按上限读取原件并核对 SHA-256。
2. 新建独立 OpenSandbox，只写入当前文件及明确关联的资源，不附带用户技能、模型/MCP 密钥或整个用户文件集。
3. 使用镜像内只读解析脚本执行；输入路径由服务端生成，参数经 JSON 文件传入，不拼接用户文件名进入 shell。
4. 将有界结果保存为私有派生对象，再提交任务成功状态；保存失败不得标记成功。
5. 正常结束和异常路径都回收沙箱。清理失败可追踪并重试；租约过期不直接假定环境已销毁。新预览任务不能误用 Agent run 的回收标识。
6. 原文件删除时使预览失效并回收派生结果；任务完成前再次检查删除状态，避免留下可访问的孤立结果。长期失败或孤立结果由对账清理任务处理。

初始输入预览上限 25 MiB，解析结果上限 5 MiB，解析超时 60 秒；全局并发默认 2，每用户同时解析 1 个，排队有上限，配置可调整。沙箱受 CPU/内存限额保护；不在控制面解压 Office 包。文档解析环境不需要公网，部署须为解析任务实际限制出网，不能只声明代理环境变量。

## 各格式与前端一致性

| 类型 | 实现与边界 |
| --- | --- |
| DOCX | 沿用 mammoth 转 HTML；进入页面前进行允许列表净化，移除脚本、事件属性和危险 URL。复杂排版不承诺 Office 原样还原。 |
| XLSX/CSV/TSV | 桌面同款工作表标签与表格；XLSX 保持 100 行展示上限并明确提示截断，CSV 使用正确引号解析；增加列数及单元格长度上限。 |
| PPTX | 保持桌面文本分页，不冒充幻灯片截图或高保真预览。 |
| Markdown/代码/文本 | 使用现有 Markdown/文本组件，禁止原始 HTML 绕过净化；图片资源经授权地址适配。 |
| PDF/图片/视频 | 鉴权内容接口 + 现有 iframe/img/video 组件，无需为普通读取启动解析沙箱。 |
| HTML | 保留预览面板，使用独立预览源和受限 iframe 替换 Electron webview，不暴露主应用 cookie。 |

HTML 预览需配置与主应用不同源的 PREVIEW_ORIGIN。预览访问票据仅绑定用户、文件版本和短期预览会话，不授权任意文件；不得在 URL 暴露长期登录凭据。配置缺失时明确显示无法启用活动网页预览，不回退到同源脚本执行。

关联资源采用显式的站点文件清单，路径标准化后只在清单中查找，拒绝穿越、符号链接和任意宿主机读取。现有单文件交付物只能提供单文件预览；多文件站点必须发布入口及依赖资源包，增加发布工具可选资源清单，使用同一归属和版本鉴权。不能假定 OSS 中存在未发布的相邻文件。浏览器页面的外链嵌入限制仍然适用，不承诺等同 Electron 浏览任意网站。

## 范围与非目标

所有实现、依赖、数据库变更、回归测试源码和文档仅在 cloud/；不修改桌面目录，不从桌面目录建立运行时依赖。

本次不新增高保真 Office 编辑，不接企业账号服务，不恢复本机文件系统，不自动部署云资源。完整用户空间目录同步、跨任务自动恢复及并行编辑冲突处理不等于预览缓存，属于独立改造；不能凭本次 OSS 驱动接入宣称其已完成。已发布文件的持久化和预览不依赖这一后续能力。

## 风险与验证

- 编写回归测试：OSS 配置与驱动、越权 404、大小限制、哈希不匹配、缓存隔离、解析超时、取消与清理失败、删除竞态、HTML/XSS、站点路径穿越、Range，以及 Office 展示数据契约。
- 项目目前仅允许默认执行语法检查、TypeScript 类型检查和 git diff --check。测试、构建、浏览器联调及真实 OSS/OpenSandbox 读写需获授权后执行，未执行不得声称通过。
- 云端 API/前端代码保持 Windows/macOS/Linux 兼容；解析镜像为 Linux，Windows/macOS 部署通过 Linux 容器环境，不依赖宿主机 Office。
- 真实接通依赖用户配置 OSS、OpenSandbox 与可选 HTML 预览域名。凭据不要求在聊天中提供；配置完成前只能交付代码，不能宣称生产可用。
