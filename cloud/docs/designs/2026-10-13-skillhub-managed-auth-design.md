# 云端 SkillHub 自动认证修正

## 背景与目标

用户要求与桌面端市场交互一致，共享密钥由应用统一管理，普通用户不填写。截图中的失败来自 cloudAdapter 对整个 SkillHub 路由的 501 拦截和迁入的桌面密钥表单。桌面当前使用环境变量或系统安全存储，并不存在源码中的共享密钥常量；本机安全存储已确认有有效格式的既有共享密钥。

## 方案与边界

- 云端后端持有共享密钥，使用当前已认证企业用户真实邮箱签发与桌面相同的短时 AES-GCM 登录凭据，自动换取 SkillHub Session/CSRF Cookie 和用户级 API Token。浏览器仅收到认证状态和市场数据。
- 本地部署一次性复用现有系统共享密钥，生成由云端 ENCRYPTION_KEY 加密的服务器密钥文件，权限 0600；运行时独立读取该文件或服务端环境配置。普通用户无需配置，不读取或共享桌面模型 Key、桌面个人会话或用户产物。
- SkillHub 用户凭据附加保存在现有云端 sessions.gateway_secret 加密字段，保留原企业 accessToken，按 owner+session 隔离，token 名称包含云端 session 标识，避免与桌面或其它用户轮换冲突。凭据失效可重新认证，网络失败不当作凭据失效。
- 补齐认证、技能/专家目录、namespace 和专家详情云端路由；市场安装沿用现有用户级技能/专家持久化与包校验。错误固定脱敏，禁止浏览器设置共享密钥或指定认证身份、服务地址。
- 前端移除共享密钥填写组件，接通真实云端市场路由，沿用桌面市场列表/详情/安装交互。
- 真实归档下载先由 registry 重定向到明确版本接口，再到企业 OSS 签名地址。下载仅允许固定 registry 版本路径和管理员许可的 HTTPS OSS 域名，最多三跳；离开 registry 时去掉用户 Token/Cookie。签名参数只供服务端下载，不记录或返回浏览器。

## 验证与风险

测试自动认证、有效凭据复用、用户/会话隔离、Cookie/Token/共享密钥不回传、错误恢复和目录/安装行为；类型检查和构建；浏览器验证不再显示密钥表单。真实 SkillHub 登录可能创建当前用户的远端读取 Token，使用现有授权的登录身份联调，不冒用测试邮箱。远端服务和账号权限决定最终市场返回内容。

本批次仅修改 cloud/；不写入共享密钥明文源码或浏览器包，不改桌面代码与用户已有数据。部署到另一台服务器须由部署系统提供同一服务器共享密钥文件或环境配置。

## 实施与验收结果

- 服务端共享密钥已从既有系统配置导入独立加密文件，0600；运行时同一文件句柄校验类型、权限并有界读取，浏览器不再显示密钥填写表单。
- 真实当前企业用户会话自动认证成功，读取 23 个技能、11 个专家、4 个 namespace。
- 真实技能与专家归档可经受控重定向下载；专家完整验证及运行快照准备成功，包含 3 个包内技能、9 个文件。安装验证写入内存测试存储，未向真实用户空间添加测试资源、未执行下载代码。
- 市场技能安装使用已有 owner-scoped 不可变技能版本；专家完整包事务内保存，升级保持资源 ID。运行时冻结包与技能，去除重复副本，完整 run JSON 上限 64 MiB。
- 专用测试库全量回归 327 passed、0 failed、0 skipped；前后端 TypeScript 和 Web 构建通过。保留已有主包大于 500 kB 的体积警告。
- Chromium 模拟接口回归通过：无密钥配置入口，专家、技能和 namespace 列表显示正常。截图 `/tmp/skillhub-managed-auth.png`。

当前企业 registry 使用桌面已有 HTTP 地址；探测该域名 HTTPS 时连接被重置。外部 OSS 下载采用 HTTPS。生产认证链路需要企业服务提供 HTTPS endpoint 或受控加密网络，配置 `SKILLHUB_BASE_URL` 指向该受保护服务后部署；本次本地联调不代表生产传输安全或 Windows 实机验收。
