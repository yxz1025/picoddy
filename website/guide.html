从源码启动 PiCoddy

先运行桌面工作台，配置模型，再接入任务需要的工具。本项目采用 MIT License，源码已在 GitHub 开放，可按以下步骤启动。

桌面端检查与构建云端部署参与贡献

桌面端快速开始

1. 获取源码与安装依赖

准备 Git、Node.js 24+ 和 npm，推荐在 macOS 或 Windows 上开发。Node.js 版本同时覆盖当前前端工具链与云端要求。从 GitHub 仓库获取源码，在包含 package.json 的项目根目录执行：

npm ci
npm --prefix frontend ci

安装需要访问 npm 与 Electron 下载源。此阶段无需填写云端 .env，不要复制维护者的服务凭据。

2. 启动桌面开发环境

终端一（项目根目录）：

npm --prefix frontend run dev

确认 Vite 在 http://localhost:5173 启动；端口被占用时先释放该端口，Electron 开发模式固定加载此地址。

终端二（项目根目录，macOS / Linux shell）：

npm run electron:dev

Windows PowerShell 使用：

$env:NODE_ENV = "development"
npm start

保持两个终端运行。仅启动 Vite 不等于启动完整桌面应用；本地 API 和工具由 Electron 主进程提供。

3. 配置模型并完成第一个任务

1. 打开桌面工作台，进入设置中的模型配置，填写自己的服务商、模型、API Key；自定义服务还需填写对应 Base URL。
2. 选择已配置的模型，先发送一条普通消息，确认模型可达。
3. 选择测试文件夹，尝试“列出这个文件夹中的文件，生成一份摘要”。按实际需要授权文件和命令操作，检查工具结果与交付文件。
4. 需要浏览器、MCP 或业务连接器时，再安装相应依赖并完成授权。

桌面端使用本地账户，不需要企业 CAS 登录。模型调用、联网工具和远程连接器会访问所配置服务；本地运行不代表所有数据都不会离开设备。模型费用由对应服务商收取。

检查与构建

在项目根目录执行：

# 主进程类型检查
npx tsc --project tsconfig.electron.json --noEmit
# 前端类型检查与生产构建
npm run build:frontend
# 后端测试
npm run test:backend

按目标系统选择打包命令，建议在对应系统上构建：

npm run build:mac          # macOS .app
npm run build:mac:release  # macOS dmg / zip
npm run build:win          # Windows x64 安装包

打包会下载 Python 等资源并准备仓库内的 Office 运行时，需要网络和足够磁盘空间；产物目录由 electron-builder.yml 配置，当前是项目上一级的 build/picoddy/。当前 macOS 配置未启用签名与公证，本地打包不等于完成正式发布。发布渠道与签名需由维护者自行配置。

云端部署

云端不是桌面端的一个启动开关。先阅读 cloud/README.md 与 部署运维，准备 Node.js 24+、独立 PostgreSQL、OpenSandbox、存储和企业 CAS。模型由用户登录后配置。

在 cloud/ 目录安装依赖并按文档配置自己的 .env，初始化独立数据库，再分别启动 API、Worker、Scheduler 与 Web。db:init 不负责迁移或清空已有业务库。现有企业登录依赖尚需适配自己的环境，不能按匿名公共服务直接部署。

参与贡献与发布状态

通过 GitHub 仓库的 Issue 报告问题、讨论需求，通过 Pull Request 提交修改。报告问题请附操作系统、Node.js 版本、复现步骤、预期与实际结果，日志应移除密钥和个人信息。

提交前保持改动聚焦，按涉及模块运行检查：桌面端使用上面的类型检查、构建与后端测试；云端在 cloud/ 执行 npm run typecheck 和 npm test；官网按 website/README.md 预览。说明验证结果和已知限制。不要提交 .env、服务令牌、企业数据或本地产物。

发布状态与许可

源码已在 GitHub 开放。二次开发或部署前，请按自己的环境配置企业集成与默认服务，检查凭据、内部地址和第三方资源许可。
