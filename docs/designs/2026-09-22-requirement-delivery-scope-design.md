# 需求交付收集遇到会话外文件的处理

状态：用户已确认并要求不改启动及会话逻辑；已完成最小代码调整，待原场景运行验证。

## 背景

用户反馈暂停或打断需求会话后出现“交付文件不在当前会话目录：VocDetailDrawer.vue”。当前仅有截图和源码证据，未取得该设备的会话消息与文件路径，不能认定打断修改了会话目录。

## 目标与非目标

自动刷新阶段状态及资产时，已展示的会话外源码不应使整个收集失败；合法会话文档继续可提交。保留账号隔离、目录边界、文件大小及版本校验。不修改暂停协议，不将关联仓库整体纳入交付目录，不自动复制或上传外部源码。

## 现状与证据

- `present_files.ts` 支持展示可读取的绝对路径文件，包括关联仓库的源码。
- `delivery.ts` 将所有历史成功 `present_files` 文件及 artifacts 记录加入候选；候选只要有一个真实路径不在当前工作空间或会话产物目录，便抛错，阻断整批收集。
- `RequirementChat.tsx` 在 busy 结束时自动请求阶段完成信息与资产；两个接口都会调用 collect。因此正常结束与打断都可能触发相同检查。
- 阶段完成信息请求的异常进入顶部 completionError，符合截图位置；无需用户主动提交即可发生。
- 现有测试覆盖目录扫描与显式展示，但未覆盖“会话文档 + 仓库外部源码”混合历史。

## 待验证假设

1. 最可能：仓库源码经 present_files 展示成功，随后自动资产收集错误地把它作为必须归档的阶段文档。
2. 次可能：用户切换过工作空间，旧交付路径不再属于当前目录。
3. 其他：符号链接解析后落在目录外。需保持此类路径不能被自动读取归档。

前两项均能解释为何重试仍失败；只有真实消息及路径才能确定截图对应哪一种。

## 方案

1. 将收集候选与合格交付物区分：真实路径不在当前允许目录、或包含隐藏路径段的历史展示项不入库，不因其存在使整批收集抛错。
2. 对目录内交付物继续执行普通文件、非空、10MB、哈希和版本规则；真实文件系统错误仍上报，不使用笼统 catch 吞错。
3. 使用 node:path 的 relative/isAbsolute 与路径段判断边界，覆盖 Windows 分隔符及跨盘路径；在读取内容前完成边界检查。
4. 提交仅使用筛选后的合格产物；若全为会话外文件，返回现有“尚未生成可提交产物”提示，不上传、不推进 TAPD。
5. 检查前端错误生命周期：成功刷新清除对应旧错误，进入新一轮时不保留上一轮完成检查错误；仅在确认现有逻辑存在残留时作局部调整。

## 影响范围

主要为 `src/domains/requirement/node/delivery.ts` 和对应回归测试；必要时调整 `RequirementChat.tsx` 的完成检查状态。同步更新交付物专项文档，说明聊天展示范围与阶段归档范围不同。无数据库迁移、无新增依赖、无 IPC 协议变更。

## 风险

用户在目录外生成的正式文档也不会自动归档，需放到会话输出目录后交付；不通过扩大目录权限解决。已有外部历史记录保留，聊天预览不受影响。截图来自其他设备，代码级修复仍需在原会话复核。

## 验证方式

- 编写回归：内部文档与外部 Vue 混合展示、仅外部文件、重复收集、历史工作空间文件、目录外符号链接、跨账号拒绝、Windows 路径边界。
- 校验不合格文件不读取归档，合法文档继续收集，空交付不上传和流转。
- 暂停、正常结束、恢复后再结束均验证自动刷新；确认成功刷新移除旧错误。
- 遵守项目约束：未获测试授权不执行测试套件；实现后默认仅类型检查与 git diff --check。Windows 实机验证未完成时明确记录，不声称通过。

## 实施记录

- 未修改启动、会话、前端、IPC 或 TAPD 上传逻辑。
- 补充混合文件正常提交、仅外部文件禁止提交、内部空文件仍报错、工作空间切换与目录链接越界用例；使用跨平台路径 API，Windows 链接用 junction。
