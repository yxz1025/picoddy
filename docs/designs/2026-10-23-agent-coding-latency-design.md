# Agent 编码耗时逐项优化

日期：2026-10-23。状态：用户已确认，源码修改已落地，运行验证待做。用户后续明确“不要测试先写代码”，本轮不运行测试、构建或真实模型请求。依据：`docs/2026-10-23-requirement-coding-latency-investigation.md`。

## 背景与目标

需求 1140830665001025206 的编码轮耗时约 74 分 44 秒，其中模型侧区间约 57 分 53 秒，工具执行约 16 分 51 秒。两次 npm 安装占约 15 分 51 秒；模型累计返回 43893 个推理 token，预览配置和交付连续失败六次。

目标：逐项消除配置错误、参数错误和可避免的等待；保留必要的源码分析、验证、权限隔离与真实失败反馈；以可重复的请求和执行记录证明改动效果。

非目标：替换 Pi 原生循环、升级依赖、重写权限系统、自动修改本次业务仓库、提交或发布应用。不承诺未经对照验证的速度比例。不把所有模型强制切成无思考模式。

## 现状

- `engine.ts` 使用 Pi 1.0.4 原生 AgentSession，`tools/index.ts` 使用原生编码工具；应用追加模型注册、专家提示词、权限、交付和完成协调。
- `models.ts` 将模型统一注册为 reasoning=false，导致 Pi Qwen 适配器无法按思考级别发出 enable_thinking。
- `requirement_preview` 的 target 使用 Type.Any，configure 必需的 repositoryId 未体现在 schema；deliver 的 targetId 为全局可选，错误最终表现为归属问题。
- 安装命令通过普通 bash 执行，模型在失败后提高 npm 重试次数；没有专门的依赖网络失败执行约束。
- 上下文预检仅诊断，压缩由 Pi 负责。既有设计禁止应用再实现一套近似 token 硬拦截和恢复循环。
- goal_complete 已有必填参数和交付验收；提交声明后另跑一次无工具最终回复。

## 方案选择

采用“保留原生 Pi、修正产品层配置与协议”的方案。单纯更换模型无法解决错误参数和安装等待；重写循环会引入重试、持久化与压缩的重复实现。

按以下顺序实施，每项维护对应回归用例和验证记录，不混入无关重构。

### 1. 模型能力与思考参数

- 分离“模型支持推理”和“本次启用推理”，取消统一 reasoning=false。
- 优先复用已安装 Pi 的模型能力、兼容参数和思考级别；明确匹配已知 provider/model，未知自定义端点不凭名称强行注入参数。
- 保留已有显式思考级别，未设置时沿用当前 off 语义；对支持关闭推理的已知 Qwen 适配，确保实际出站参数明确关闭，而非仅修改本地标记。
- 模型切换和恢复会话必须应用同一规则。能力不可关闭时如实反映，不伪称关闭。
- 用原生适配器与本地模拟服务验证请求字段；不把模型请求体、密钥或用户正文写入日志。

### 2. 预览与交付工具参数

- 用明确的对象 schema 描述配置输入，复用 PreviewTarget 契约，列出 repositoryId、name、kind、projectPath 和嵌套命令等字段；服务端生成字段不交给模型猜测。
- 按 action 校验必填参数：configure 要求对象与 repositoryId；deliver/readDesign/designTools 要求 targetId；readDesign 要求 tool。
- 字符串 target 在参数层直接拒绝，具体说明需要对象；不自动解析错误格式形成兼容分支。
- list 返回本轮可用仓库和目标的关联关系，错误清楚区分缺失字段、目标不存在、仓库未选中和跨阶段操作。
- 多仓库交付按目标分别登记相对路径；后端无可运行预览目标时不要求为了完成编码伪造 web 预览目标。
- 保留账号、阶段、仓库范围和 Figma 读取凭据检查。

### 3. 依赖安装网络等待

- 在编码执行规则中明确：先检查依赖是否已安装；网络失败先诊断原因，不直接重复完整安装或调高重试次数。
- 对 Agent 启动的 npm 安装通过现有受管 shell 环境设置有界网络默认值：fetch retries=1、fetch timeout=30 秒、重试间隔 1 至 5 秒；不修改用户全局 npmrc。
- 只对明确识别的依赖安装调用设默认 120 秒执行预算；用户明确要求长安装可以覆盖。普通构建、测试和其他 shell 命令不套用安装超时。
- 同一任务内相同安装已出现网络失败时，拦截未改变条件的重复安装，返回上次失败原因及恢复条件。取消/超时沿用原生进程清理，不新增平台专用 timeout 命令。
- 命令识别复用已有解析能力；不能可靠识别的复杂 shell 不改写命令，仍遵循执行规则并准确记录限制。
- 前端依赖无法安装时保留“验证阻塞”，不能把管道最后一个命令的退出码当作编译或安装成功。

### 4. 上下文成本

- 优先消除本轮注入中的完全重复需求、资产与指令，按来源和内容版本精确去重；不删除原始日志或改写用户历史。
- 源码和大文档保持按需读取与分页，不把完整设计文档反复拼入每轮用户输入。
- 保持真实模型容量；不通过伪造 contextWindow 提前触发压缩。
- 先记录真实 usage、缓存命中与压缩成本，再通过 Pi 自身的压缩设置调优，不另建摘要引擎或 prompt 重试循环。对于未能证明净收益的压缩阈值变更，不作为“优化成功”上线。
- 编码续接必须保留需求约束、已批准设计、实际修改、待验证项和产物路径；不因提速丢失工作状态。

### 5. 完成与失败重试

- 完成工具描述给出单次完整调用示例，明确 success、summary、proof 和 waiting 状态；保持证明与验收要求。
- 同样参数、同样确定性错误不重复调用；字段校验错误一次返回全部缺失字段及修正格式。
- 保留最终无工具回复与交付后的验收边界；不直接删除该轮，以免影响会话持久化、最终状态与失败恢复。先应用正确的思考参数和简洁回复约束，独立测量其成本。
- 模型超时继续由 Pi 处理；核对 provider 超时与原生 retry 配置，用本地可控延迟定位 10 秒错误来源，不靠盲目延长超时掩盖问题。

### 6. 诊断与效果验证

- 使用 Pi 请求钩子和 session 事件记录会话/轮次标识、模型、请求开始、首个内容事件、完成、重试、工具起止、token usage、压缩事件。
- 区分墙钟总耗时、模型请求耗时和并行工具区间；不能简单相加重叠事件。首个内容事件不是服务端真实首 token，命名保持准确。
- 日志仅含结构化计时、工具名、状态和计数，不含命令正文、业务源码、凭证或完整请求载荷。
- 与修改前基线对照：实际思考参数正确；有效预览参数一次通过；无效参数一次说清；安装网络失败受限且不重复；上下文减少不丢失约束；取消和最终验收保持有效。
- 真实 Pi CLI 速度比较必须使用相同模型、端点、输入、工具及思考配置，单独授权外部模型请求后执行，不把本地模拟结果当真实提速数据。

## 影响范围

主要为 `src/agent/models.ts`、模型能力解析、`engine.ts`、工具包装、受管 shell 环境、`long_task.ts`、提示词资源、`src/domains/preview/node/tools.ts` 与相关 shared 契约、对应 `test/` 回归源码及专项文档。复用当前 operation logger，不新增独立遥测服务。

保留当前 frontend 项目组件的既有未提交修改；如必须涉及其接口，先核对差异后作精确增量修改。

## 风险与验证方式

- 思考关闭可能改变复杂任务质量，因此服从显式级别并对已知模型做请求契约验证，不全局降级。
- 安装预算可能不足以完成首次冷安装，需提供明确原因和用户覆盖方式。
- 上下文压缩有成本且可能损失细节，先处理重复注入，再以原生机制和证据决定阈值。
- 全部运行时实现使用 Node 跨平台 API；覆盖 Windows 路径与进程取消行为，当前 macOS 不能代替 Windows 真机验证。
- 默认仅执行 TypeScript、语法与 git diff --check；按项目规则，定向自动化测试、构建和打包需用户明确授权。回归测试优先使用本地 mock，无付费模型调用和生产业务写入。
- 每项完成报告修改、验证结果与未验证范围。完成源码修改不等于已安装应用已更新，不自动替换或发布桌面包。

## 实施记录与边界

1. **模型参数**：新增 `model_reasoning.ts`，仅对已知官方 Qwen 端点和 Pi 目录中精确匹配的模型复用 reasoning、compat 和 thinkingLevelMap。未知端点不猜协议。新会话未显式配置时请求 off，由 Pi 映射到支持的级别；恢复会话保留历史设置。Pi 1.0.4 目录把 qwen3.8-flash 的 off 标为不支持，实际最低级别是 low，不能宣称关闭推理。其他模型未做无证据的能力推断。
2. **预览契约**：配置 target 改为明确对象 schema；一次检查动作必填字段，返回具体纠正信息。projectPath 为相对路径；目标/仓库 ID 分开说明；纯后端任务无需伪造预览目标。已有账号、阶段、仓库和 Figma 校验保留。
3. **安装等待**：直接 npm install/i/ci（含字面量 cd 前缀）默认 120 秒，网络重试默认 1 次、请求超时 30 秒；不改全局 npmrc。禁止这类安装接 tail/echo 等后续命令，保留退出状态。同轮同目录网络失败或超时后，重试必须提供恢复依据。显式 timeout、环境和 npm 参数仍可覆盖默认值；复杂 shell 不做不可靠改写，因此不是所有包管理命令的强制全局上限。重试依据是执行约束，不冒充网络已由运行时验证。
4. **上下文**：资产按 id+hash 去重，正文片段每份最多 8000 字符、总计 24000 字符，版本路径和 truncated 保留；提示词完全相同的片段去重；引用对象按规范化 JSON 精确去重。没有删除历史、修改真实模型窗口或设置未经性能验证的压缩阈值。
5. **完成与取消**：完成工具补全一次调用示例和失败语义，不再向普通日志打印 proof 正文。保留最终回复及验收流程。Windows shell 将 AbortSignal 传至执行器，超时/取消用 taskkill /T 终止进程树；Windows 真机行为尚未验证。
6. **观测**：`runtime_metrics.ts` 接入 Pi 原生请求钩子和事件，记录模型/实际思考参数、首个内容事件、usage、工具、重试和压缩；并行工具不累加为总墙钟耗时。不记录请求正文、工具输入或凭证。记录有效 HTTP 与 provider retry 设置；Pi 默认 HTTP idle timeout 为 300000ms，原日志约 10 秒超时尚无确证来源，未盲目修改默认值。SDK 内部 HTTP 重试可能不逐次触发钩子，指标不冒充每一次底层网络尝试。

静态检查：后端 TypeScript `--noEmit` 已通过；最终差异格式检查见交付说明。按用户要求未运行任何测试。未打包、重启或替换已安装桌面应用；真实提速幅度、Windows 进程树回收、真实模型请求参数均仍需运行验证。
