# 长任务执行、恢复与交付验收

> 文档定位：2026-09-07 第一版实现说明，描述当前工作区的请求内续跑方案，不代表目标架构已经完成。
> 后续架构设计以 [任务运行时架构设计](./2026-09-07-task-runtime-architecture.md) 为准。该文档明确任务生命周期、持久化、恢复、验收及分阶段演进；本文保留作为现状对照。
> 文末“验证范围”是第一版变更的历史记录，不是后续工作的执行指令。
> 2026-09-07 架构修订：目标改为直接采用 pi-coding-agent AgentSession。本文的 Harness context hook、自定义压缩调度和强制摘要属于待替换的旧实现，不是新方案要求；旧实现使用 core 压缩原语，不代表 Harness 内置自动压缩。

本次变更复用 pi-agent-core 0.83 的 AgentHarness 工具循环，在一次用户请求外增加 LongTaskRunner。一个模型运行结束不再直接代表用户任务结束。

## 执行边界

Provider 创建请求级 AbortController，并保持 PromptAwareHarness 的同一份系统提示、工具集和权限，直到恢复及验收结束。每个模型请求前的异步 context 钩子负责检查预算；该时点上一批工具的消息已经落盘，没有模型请求或工具并发执行。无需操作 Harness 私有状态，也不在 busy 状态调用 harness.compact()。

压缩使用公开的 prepareCompaction / compact / Session.appendCompaction 接口。按当前系统提示、工具描述、历史消息估算预算；若存在压缩后新响应，则同时参考其真实 usage。保留摘要前的原始 usage 用于记账，不用于估算新上下文。

准备连续压缩时，把上次 compaction.retainedTail 展开为仅用于计算切点的临时 entry；保存时仍使用真实 entry 引用和 retainedTail，避免最近工作在第二次压缩时被漏掉。生成摘要后检查 leaf 未变，再保存；摘要失败或取消时不覆盖原历史。

默认预留空间为 min(窗口的 50%, max(16,384, 窗口的 20%, 模型 maxTokens))。摘要单次超时 120 秒；一次用户请求最多 80 次模型请求、8 次压缩。超限、不可压缩、压缩后仍超预算时明确失败并保留历史，不无限重复摘要。

## 恢复与取消

- `length` 最多自动恢复 2 次；相同工具结果或相同部分正文不计为新进展。恢复后没有新进展则提前停止。
- 恢复以新的内部继续消息进入同一 Harness；首次技能展开和文档检索不重复，权限不升级。内部恢复消息写入 core session，恢复原因另存为 task_recovery 自定义记录。
- 第一次 context 钩子确认用户消息落盘后即发布 core session 路径，不等长运行结束才提交映射；后续工具结果沿用 Harness 自身的逐条持久化。
- 自动恢复不会直接重放工具。恢复阶段对同工具、同参数的已有副作用操作增加重复调用拦截；白名单只读工具和交付/提问工具可再次调用。不同参数或不同 shell 写法无法靠此去重，因此恢复指令仍要求先核实外部操作状态。
- `error`、明确取消不自动恢复；API 自带的请求重试保持原行为。
- 用户插话、取消、销毁及专家卸载会取消请求级 controller，包括摘要和验收。交互提问的等待也响应取消。
- 内部 agent_end 不直接转发；Provider 在整次请求终结时发送一次 agent_end。前端显示整理上下文、恢复和验收状态，恢复期间保持 busy。
- 任务运行期间，bash 中用于打开系统浏览器或系统默认应用的常见命令会被拦截，并要求回到 present_files；交付事件由客户端内置预览面板消费。

## 文件验收

调用方可通过 PromptOptions.artifactRequirement 提供文件交付约定；没有结构化约定时，文本识别仅提示需要交付文件，不推断格式、数量或解析器。逐个检查输出动作，支持后续句子的文件请求。“确认/继续”会回溯最近用户消息中的文件要求。此识别不是完整的自然语言需求解析器，也不代替模型核对用户要求。

present_files 对任意类型的本地文件执行存在性、普通文件、非空及读取稳定性检查，并保存 SHA-256。不设扩展名白名单，没有后缀或没有专项解析器的文件也能交付。默认使用分块读取，不因文件扩展名自动套用结构检查或 32 MB 限制。

文件约定的 extensions 是全部必需的扩展名；anyOf 是候选组合，满足任一组合即可，但组合内部必须全部满足，且不免除 extensions 中的共同要求。minFiles 指定至少交付的不同路径数量，默认为 1。例如 extensions=["csv"]、anyOf=[["pdf"],["html"]] 表示 CSV 加 PDF/HTML 中任一种。未指定这些条件时，任意非空可读的本地文件均可满足通用文件交付检查。

validators 是按扩展名配置的可选结构校验器，与 extensions 独立。例如 validators={html:"html-document"} 才要求完整 HTML 文档，而 HTML 片段或模板默认仅做通用文件检查。不再把报告模板占位符作为所有 HTML 的禁用内容。现有校验器包含 HTML 文档、JSON、PDF 和 Office 容器；可以继续增加，不影响其他文件的交付。专项结构读取上限 32 MB，Office 展开上限 128 MB。展示入口和最终验收复用同一约定及校验器。

任务结束前再次读取交付文件，检查可读性、摘要一致性及显式约定。扩展名匹配只证明文件命名符合约定，不证明内容格式正确；需要内容格式检查时启用对应校验器。交付后修改必须重新 present_files；交付失败或约定未满足不能标记 done。验收失败最多补齐 2 次，无新进展时提前停止。

结构验收不等于内容正确、视觉布局合格或业务计算正确。模型仍需提供内容验证依据。URL 保留原有展示行为；外部 URL 不宣称已验证内容，也不替代明确的本地文件交付要求。

本模块只承担本地文件约定，不把代码修改、纯文本回答、链接展示或外部操作转成文件任务。非文件成果沿用对应工具的执行反馈和任务完成依据；当前没有新增通用的链接内容验证或外部操作真实性验证器。未知本地文件类型显示文件信息和路径，不自动调用系统默认应用。

确实需要用户补充时，goal_complete 可声明 status=waiting_for_user、success=false，并提供具体缺口；Provider 使用 pending，而非 done。goal_complete 成功声明也经过同一个文件验收入口。

子代理、连接器子会话与自动化仅把会话的 done 状态映射为成功；pending、failed、cancelled 或缺失状态都不会报告完成。自动化遇到等待用户时以失败结束，并说明需要补充信息。

## 2026-09-08：完成声明与原生收尾

修正 `goal_complete` 校验成功后模型仍继续执行工具的问题。完成声明由请求级 TaskRunCoordinator 接收；成功声明先校验已有文件约定，等待用户或失败声明则记录对应结局。声明被接收后禁用本次执行的业务工具，通过 Pi 原生 `AgentToolResult.terminate` 正常结束当前工具执行，不调用 abort，也不直接写入 done。

Pi 的 terminate 要求同批全部工具结果都设置停止标记。因此 goal_complete 必须单独调用；原生 beforeToolCall 入口拒绝与其他工具混合的完成声明，保留其他工具的原生执行和权限检查。被拒绝的声明不会关闭任务。

协调层等待 prompt 和原生 idle 后重新验收。通过后只提交一次不携带工具的最终答复请求；工具关闭状态覆盖收尾过程。收尾截断、错误、取消或空答复不会因先前声明成功而被当成正常成功，也不会重新开启业务操作来修补答复。文件任务在最终答复后再检查交付哈希，期间文件变化不能提交成功。原生停止后的首次验收失败仍可在既有预算内重新开放工具，进行局部补齐。退出时恢复工具配置，供下一次用户请求重新计算和使用。

普通回答和无文件操作任务仍可自然结束，不强制 goal_complete 或 present_files。已有文件交付约定继续约束完成声明和最终验收；waiting_for_user 不要求先补齐缺失文件。非文件任务仍依赖已有工具反馈及完成依据，没有新增通用代码正确性或外部业务真实性验证器。

本变更完善请求内完成生命周期，不宣称已实现目标架构阶段 C 的持久 Task/Run、revision、ownerEpoch 或跨进程恢复。

验证使用真实 createAgentSession、内存 SessionManager 和可控 faux 模型覆盖原生工具循环、单独/混合声明、有文件/无文件、等待/失败/取消、文件变更及收尾异常；不调用真实模型服务或外部业务接口。

按用户要求不运行测试、不调用技能。同步更新受行为变更影响的既有测试断言，但不执行。使用 TypeScript 静态检查及 git diff --check；该变更没有进行真实模型端到端或界面运行验证。自动恢复仅覆盖同一次请求内的运行，不包含进程崩溃后的自动重启。
