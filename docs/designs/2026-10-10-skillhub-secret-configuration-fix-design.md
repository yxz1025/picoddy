# SkillHub 共享密钥配置缺失修复设计

> 2026-11-03 更新：凭据保存与部署配置以 [通用部署配置与凭据存储清理](./2026-11-03-neutral-config-and-secret-storage-design.md) 为准。安装包不再携带 SkillHub 密钥；桌面 MCP 配置整体加密保存，旧明文文件拒绝加载。

## 背景与现状

专家市场提示“请配置 SKILLHUB_AUTH_ACCESS_TOKEN_SECRET”。登录凭据签发要求与服务端一致的标准 Base64 编码 32 字节共享密钥。当前客户端读取主进程环境变量或安全存储，但没有专用配置入口；启动脚本没有自动加载项目 .env 文件。只读检查显示当前工具进程、Windows 用户和系统级环境变量均未设置该变量；这不代表已读取正在运行的 Electron 进程环境或安全存储内容。

现有读取使用 ??，空白环境变量经过 trim 后仍阻止回退。前端认证失败后跳过列表请求，却继续显示“暂无匹配的专家”。

## 目标

提供可操作的密钥配置闭环；空白环境变量允许回退至安全存储；区分配置缺失与格式错误；认证失败不显示成功加载后的空状态。

## 非目标

不生成替代服务端密钥，不绕过认证，不恢复源码固定 Token，不改变 SkillHub 登录协议和 Token 有效期，不将密钥写入仓库或普通配置文件。

## 方案

1. 在 SkillHub 主进程领域服务中集中校验及解析密钥。非空环境变量保持优先；空白变量视为未配置；非空但格式错误时明确提示修正环境配置，避免静默掩盖错误。
2. 增加专用配置状态读取和密钥保存接口，仅返回是否配置、配置来源及可展示的错误状态，绝不返回密钥。保存前严格校验标准 Base64 和解码后的 32 字节长度，复用现有 setApiKey("skillhub-access-token-secret", value)；Windows 使用现有 DPAPI 安全存储，macOS 使用钥匙串。
3. 同步 HTTP、IPC handler、preload 白名单及前端路由映射。通过领域服务处理校验和存储，接口沿用现有本地访问保护，不记录请求密钥。有效环境变量生效时明确说明其优先级，避免用户误以为保存即可覆盖它。
4. 专家/技能市场提供“配置技能市场”入口，使用密码输入框填写管理员提供的共享密钥，提交后清空输入。保存成功后重新检查认证并加载当前列表；存储错误、格式错误保留可操作提示。普通连接器和本地专家不增加额外阻断。
5. 认证检查中或失败时不展示专家/技能市场“暂无匹配”空状态；仅在列表加载成功且无结果时展示。保持现有错误重试能力。

## 影响范围

src/domains/skillhub/node/auth.ts、auth_service.ts、application.electron.ts、src/electron/ipc-handlers.ts、src/electron/preload.cjs、frontend/src/api/client.ts、frontend/src/store/useSkillStore.ts、frontend/src/components/ExpertPanel.tsx 及所需样式、相关回归测试源码与技能领域文档。

## 风险与前提

实际登录仍需要 SkillHub 管理员提供与服务端一致的真实密钥；仅凭报错无法恢复它。服务端开关、账号邮箱和接口可用性仍须在配置完成后验证。继续沿用当前已确定的客户端持有共享密钥方案。保留用户当前 package.json、package-lock.json 和生成资源中的无关修改。

## 验证方式

补充密钥缺失、空白回退、非法格式、安全存储调用、配置接口不返回密钥及认证失败空状态等针对性回归测试源码。按仓库约束默认只运行前后端 TypeScript 类型检查、preload 语法检查和 git diff --check；未经用户明确授权不运行测试套件或构建打包。实际 Windows 登录与加载需在拿到服务端真实密钥后验证，不能仅凭静态检查宣称登录恢复。

## 确认状态

用户已确认修复并要求本地启动，开始实施。回归测试源码可补充；按仓库约束未经明确测试授权不运行测试套件。

## 实施与验证结果

- 已实现专用配置状态/保存接口、IPC 和前端安全配置表单，复用系统安全存储；保存响应仅包含状态、来源及错误。
- 已修复空白环境变量回退，并明确识别既有通用环境变量别名；非空环境配置生效期间拒绝面板覆盖。
- 已区分缺失和格式错误，认证失败或检查期间隐藏市场无结果提示。
- 后端与前端 TypeScript 类型检查、preload 语法检查、git diff --check 均通过；补充配置解析、安全存储和路由回归测试源码，未执行测试套件。
- Windows x64 源码版已成功本地启动。先正常关闭占用单实例锁的已安装版；开发启动遇到 esbuild worker 服务退出，使用项目打包已有的直接执行模式（ESBUILD_WORKER_THREADS=0，显式指定本机 esbuild 二进制）后启动完成，日志出现 PiCoddyClaw ready。前端开发服务位于 127.0.0.1:5173，后端位于 127.0.0.1:8000；本次未构建安装包。
- 本地运行中的 GET /api/skillhub/auth/config 返回 configured=false、source=none，说明当前应用没有配置有效共享密钥；新增配置组件经开发服务返回 HTTP 200。尚未获得服务端真实密钥，因此未验证远端登录成功和市场列表恢复。
