# 移除 PICODDY 专用集成

## 已确认范围

桌面版改为本地账户，移除 CAS 登录、零售微应用发现和脚手架、PICODDY 组件技能、Filez 专用工具、专用知识库 OAuth 预设及企业 TAPD 授权网关。保留通用 MCP、标准 OAuth、自定义配置、Figma、GitLab、Jenkins、钉钉、ClawHub、项目/会话/模型与完整专家包。

## 桌面实现

- 本地身份使用 SQLite settings 中固定的 desktop_local_account；首次沿用最后一次企业账号 ID，仅作本地记录归属键，不暴露或复用旧令牌。历史项目及模型配置不迁移、不删除；历史需求记录可保留，企业授权流程明确不可用。
- HTTP 服务继续只绑定 loopback，并校验本地 Host / Origin 与跨站请求。云端认证保持独立，未变为本地无认证模式。
- 删除企业集成源文件、UI 入口、授权服务 server/、对应专用脚本和测试；Filez 注册、能力提示与权限项同步移除。
- 专家库展示系统内置及已安装专家，不自动访问内部市场。原专家包及声明技能保持完整。
- 内置技能压缩包和桌面前端静态资源重新生成。打包前后不再要求企业 SkillHub 登录密钥。
- 旧企业 MCP 配置只在有效配置视图中过滤，不主动删除磁盘配置；旧技能 manifest 文件名只读兼容，以免升级损坏已有安装。这两处保留旧标识用于禁止旧集成恢复及读取历史格式。

## 云端实现与部署注意

移除云端知识库和 TAPD 企业预设/沙箱授权中转，保留通用连接器和认证。CAS_LOGIN_URL / CAS_EXCHANGE_URL 改由部署显式提供，缺失时登录返回 AUTH_NOT_CONFIGURED；自定义专家市场地址和允许下载域名也不再有企业默认值。沙箱运行目录改为 /opt/picoddy，必须重建镜像后部署。

新库身份 provider 为 cas。旧企业身份迁移脚本已移除，不再提供兼容迁移；本次未修改现有数据库。

已有部署必须沿用原 CLOUD_PROJECT_NAME、持久卷和数据库账号，通过 POSTGRES_USER / POSTGRES_DB 明确指定原值，不要用新版默认项目名创建另一套卷。现有 .env、凭据文件、用户项目仓库没有改写。历史设计文档及专家来源署名保留事实记录，不作为运行时配置。

## 验证与限制

只执行前端构建、云端类型检查、主进程类型检查、源码引用检查、资源生成及 JS 语法检查。未启动前端、客户端、自动化测试、第三方技能执行或云端数据库迁移。主进程仍有 context_budget.ts 原有三处 unknown 类型错误；本次无新增类型错误。运行时交互与打包安装未验证。

## 专家页数据来源收敛

专家列表仅合并 `/api/experts` 中 catalogSource=builtin 的摘要及 `/api/experts/installed` 返回的本地已安装专家，不展示 catalog/市场条目。移除侧栏进入时的 SkillHub 登录调用，以及桌面专家页的市场列表、远程详情、召唤和登录 UI/Store 方法。保留本地专家详情、阶段选择、会话和“添加专家”创建入口。普通技能页仍独立使用 ClawHub。前端构建通过，未启动客户端或自动化测试。
