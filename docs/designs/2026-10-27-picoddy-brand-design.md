# PiCoddy 品牌替换方案

状态：用户已确认，桌面端和云端品牌替换已完成；按用户要求不继续启动检查。

## 品牌图标

采用 π 作为主体，象牙白符号搭配炭黑圆角底，两颗圆点形成伙伴表情，薄荷绿方块代表光标。原始设计稿位于 `resources/brand/picoddy-icon-concept.png`，由 imagegen 生成。

备选方向：纯 P/C 字母标志更严肃，但与 Pi 的关联较弱；完整角色吉祥物更活泼，但任务栏尺寸下细节容易丢失。推荐当前 π 伙伴方案。

最终导出需要覆盖应用 PNG、Windows 多尺寸 ICO、macOS ICNS/iconset、网页 favicon 和对话头像。初稿的白色外边缘已通过 imagegen 处理为透明边缘，正式母版为 `resources/brand/picoddy-icon.png`。

## 欢迎语

- 主标题：你好，我是 PiCoddy
- 副标题：从一个想法开始，一起把事情做成。
- 产品说明：你的开源 AI 工作伙伴

欢迎页沿用现有居中布局，加上品牌图标；窄窗口下标题允许自然换行。桌面端与云端保持同一文案。

## 替换范围

1. `frontend` 与 `cloud/web`：侧栏、欢迎页、助手名、登录、设置、悬浮窗、加载提示、窗口标题、页面元信息、头像与网页图标。
2. `resources`：启动页、恢复页、各平台应用图标。
3. 主进程、平台层：窗口与托盘名称、Windows 应用标识。
4. 包元信息、electron-builder、发布与验证脚本：产品名、安装包名、应用标识及其匹配逻辑。
5. README 与当前部署说明：统一 PiCoddy 名称，同步适用的示例及测试断言。

## 企业集成边界

项目存在 PICODDY 专属 CAS 登录、知识库、零售服务、微应用 Git 仓库和组件技能。这些是功能依赖，不能将其真实域名直接改成虚构的 PiCoddy 域名。需要确定开源版移除这些默认入口，还是保留通用实现并由部署者配置。

历史设计记录与第三方版权不应通过机械替换重写事实；生成文件应由其源文件重新生成。现有用户目录与应用标识的变化需明确说明，不宣称自动迁移已有数据。

## 验证

执行桌面前端构建、主进程类型检查、云端类型检查及受影响的现有测试。核对各平台图标格式与尺寸、发布脚本中的应用名匹配；检查桌面及云端欢迎页效果。最后扫描旧品牌残留，逐项区分历史记录、企业功能依赖与遗漏。没有 Windows 运行环境时明确标注未完成 Windows 实机验证。
