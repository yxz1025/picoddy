# 移除小模型关键词工具裁剪

## 背景与目标

用户已授权优先修改小模型关键词筛选，并要求专家技能不受影响。现有 provider 在 RuntimeProfile 和专家/技能意图解析后调用 compactRuntimeProfileForModel，以 32768 输入容量及 6000 工具预算为条件，用用户文本匹配工具描述并删除未命中的工具。这会让原生工具发现也无法访问被删除的能力。

## 方案与影响范围

删除 provider 中该裁剪调用及仅为该调用计算的模型容量；删除 context_budget 中关键词排名、工具优先级、裁剪函数和对应依赖。保留上下文诊断估算及其他预算逻辑。

继续使用现有 resolveToolPolicy 决定模式和类别允许的工具。engine 已接入 Pi createToolSearchExtension 和 Codemode，保持原有 exposure/default active 语义：普通工具仍可直接调用，deferred/codemode 工具由原生机制发现。不是把所有工具一律改成延迟加载，也不另写发现算法。

专家绑定、专家选定技能、技能资源加载、技能指令展开、显式 MCP 选择、权限检查、工具执行守卫均不修改。原裁剪已跳过专家和显式技能场景，本次移除裁剪不会改变这些场景的工具集合。删除仅针对被移除算法的旧测试源码，其他测试保留。

## 非目标与风险

不改模型目录、Windows Shell、MCP 生命周期、历史压缩、资产管理。普通小模型首轮可能暴露更多非延迟工具，不能宣称一定降低 token 或加速；本次目标是消除错误删减并统一现有发现路径。工具发现不扩展权限。使用现有 TypeScript/Pi 跨平台路径，不新增平台依赖。

## 验证方式

按用户要求不运行测试。静态检查调用与旧符号清理、专家技能路径未修改，执行 TypeScript 和 git diff --check。运行表现尚未验证。

实施记录：已删除关键词裁剪调用、算法及三项仅覆盖该算法的旧测试；专家和技能实现文件未修改。TypeScript 类型检查通过，未运行测试。
