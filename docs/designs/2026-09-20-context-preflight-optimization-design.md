# 上下文预检与连续任务两阶段优化

## 背景与目标
近似 Token 超限被作为硬错误，导致正常确认轮失败。目标是让近似值只用于诊断，模型容量由服务端及 Pi 原生恢复判断，并保留连续任务能力。

## 第一阶段
移除 Provider 基于近似值的手动压缩及硬拦截；已有输入字节保护继续有效。只记录模型、能力来源、四类占用，不记录正文。自动压缩、恢复和重试由 Pi 唯一负责，应用不重复执行 prompt。
qwen-max 官方文档确认窗口 32768、最大输入 30720、最大输出 8192：https://www.alibabacloud.com/help/zh/model-studio/qwen-max 。自定义服务仍以显式配置优先，官方默认不代表网关实测。

## 第二阶段
工具低于预算时保持完整集合；超预算但存在历史、专家或显式技能时保留模式授权集合，避免一句“继续”裁掉必要能力。仅首轮无绑定任务使用现有相关性收敛。重复记忆和重复附件引用按完整条目精确去重，禁止模糊去重或删除不同版本。文档路径与历史继续由原生会话保留。

## 边界与风险
不自动切换模型，不改变用户权限或删除历史。大工具结果持久化及分页需保持工具协议和完整来源，本轮先核对已有能力，不对历史统一截断。允许估算超限请求可能增加一次服务端拒绝的延迟。

## 验证
后端类型检查和差异检查；维护连续任务工具保持、重复引用去重的回归源码。未授权执行测试套件或真实付费请求时，不声称端到端验收通过。

## 实施补充
复用现有 artifacts 表，每轮注入当前会话最近 8 个成果的路径，不注入正文。read_doc 增加字符 offset/limit，默认返回 8000 字符，单页最高 12000，并明确下一页位置和提取器自身的上限；原文件保留，未实现全格式无限分页。服务端容量错误提示保留文档和会话，避免要求用户重复上传。
