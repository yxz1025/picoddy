# 需求工作台：多仓库与会话上下文交互方案

状态：本地多仓库版本已接入产品代码；交互原型仍使用示例数据。

## 本轮已实现

- 顶部关联入口、仓库/资产独立页签、前后端/公共库多用途、系统目录选择及手工绝对路径输入。
- 需求级多仓库关联、按阶段保存引用与分析范围、资产版本固定、下一轮输入标签。
- 每轮重新校验 Git 根、分支、commit 和范围，复制所选范围的受版本管理文件及未忽略文件；每仓库限制 5000 个文件 / 32MB，超限明确要求缩小范围。
- Agent 同时收到原始工作目录、分析代码副本、版本信息和资产版本路径。权限机制保持原有行为；不自动切换分支、不自动提交或推送。
- 输入快照关联持久化用户消息；聊天支持折叠查看每轮仓库与资产输入。普通聊天保持默认行为。
- 新接口接入 HTTP 与 IPC，包括输入保存、读取和历史快照。解除关联保留磁盘源码与历史输入。
- 19 项相关后端测试通过（含真实临时 Git 仓库）；前端构建通过。后端全量类型检查仍报告技能存储 2 处、TAPD 状态映射 1 处既有错误；新增代码没有类型错误。

本轮边界：关联已有本地 Git 仓库。远程克隆与自动 worktree 准备仍按下文独立分期；未执行前端自动化测试，真实桌面点击与真实 Agent 跨仓库执行未作完整验收。

## 1. 页面结构

- 顶部保留需求标题、TAPD 状态、阶段与实际绑定的专家；架构阶段提供常驻「关联代码仓库」入口。
- 中间保留完整聊天记录和输入框，不按前端、后端拆成不同聊天页签。跨仓库架构分析需要同一阶段会话统一理解。
- 右侧使用「代码仓库」「资产」「需求」三个页签；架构阶段首次进入且尚未关联仓库时，默认打开代码仓库页签并突出关联入口。
- 输入框上方显示“本轮输入”标签：需求编号、前端/后端/公共库仓库名、资产名称与版本。点击标签打开对应详情；移除标签只取消下一轮引用，不删除需求关联。
- 窄窗口将右侧面板变成抽屉，输入框的引用标签与关联入口仍可访问。

## 2. 关联多个仓库

关联保存在需求空间内，每阶段维护自己的引用选择。支持多个前端、多个后端、公共库、其他用途；用途是标签，不限制数量。同一个 monorepo 可以用同一仓库关联加多个角色/范围表示，不重复克隆。

「关联代码仓库」打开抽屉或弹窗：

1. 来源：已有本地工作空间 / 选择本地目录 / 远程仓库地址。
2. 本地目录由系统目录选择器选择；保留可编辑绝对路径，方便桌面与 HTTP 开发模式。远程地址只能保存为待准备项，用户明确触发克隆并选择目标目录后，才变为可供 Agent 读取的本地仓库。
3. 展示名称、用途标签（前端/后端/公共库/其他）、本阶段重点分析范围、补充说明。
4. 后端校验目录存在、可读、Git 根目录与真实路径，读取当前分支、HEAD commit、工作树状态。路径按运行 Agent 的机器解析，不使用浏览器的虚拟文件路径。
5. 保存后仓库卡片显示名称、用途、本地路径、分支/commit、分析范围、校验状态，并默认加入当前阶段输入。

选择分支与切换本地分支不是同一个操作：首期展示当前检出分支；要分析其他分支时，单独选择准备 worktree，不在“保存关联”时隐式 checkout 或覆盖本地修改。

仓库卡片操作：引用到本阶段、编辑用途/范围、重新校验、打开目录、解除需求关联。解除关联不删除磁盘目录，不影响已发送轮次的历史记录。

## 3. 空状态与异常

- 尚未关联仓库：提示“关联代码仓库后可基于现有实现分析”，输入框保持可用，允许先澄清需求。
- 请求基于源码执行架构分析、但没有有效仓库：在发送前提示缺少代码输入；可以关联仓库，或明确选择仅讨论方案。不得声称已经阅读代码。
- 已选择但路径失效、未完成克隆、无权限：标红具体仓库；修复或取消该引用后再执行依赖它的分析，不能静默忽略。
- 工作区有未提交修改：显示变更数量，默认分析当前工作树。每轮记录基准 commit，并保存实际纳入读取范围的文件/差异快照与内容哈希；单记 HEAD 无法证明读到的未提交代码版本。
- 绑定新仓库不自动读取整个仓库；只登记范围和引用，实际读取遵循工具权限及上下文预算。

## 4. 阶段切换

- 第一次进入架构设计：推荐已确认的 PRD、需求基线，要求配置需要分析的代码仓库。
- 第一次进入开发：继承已关联仓库，推荐架构产物；用户确认本任务实际涉及的仓库子集和开发目录。
- 返回已有阶段：恢复该阶段原来的仓库、资产选择和会话；不能用其他阶段的选择覆盖。
- 仓库角色与当前阶段专家是两个维度：前端/后端标签不自动拆分专家会话。需要并行执行时，另建任务并绑定其仓库子集。
- 新增关联或资产版本只影响下一轮；运行中的一轮继续使用已冻结输入。

## 5. 资产与代码仓库分别管理

- 资产页：需求附件、已确认阶段产物；展示本地是否就绪、版本、来源阶段和 TAPD 同步状态。
- 仓库页：本地目录、代码版本、工作树和分析范围；不使用 TAPD 附件上传来同步源码。
- 资产标签引用不可变版本；编辑工作副本后提交新版本，再供后续轮次引用。
- 代码变更留在 Git 仓库；提交、推送与 PR/MR 是独立操作。
- 设计文档沿用“本地版本先保存、内容变化后按配置上传 TAPD”的链路。

## 6. 每轮自动携带的内容

前端发送消息、会话 ID 和明确选择的引用 ID。后端从持久化归属解析账号、需求、阶段和专家，校验引用归属与可用性，再组装：

- 需求快照与当前任务/阶段目标；
- 专家绑定与本阶段会话历史；
- repositories[]：关联 ID、用途、本地规范路径、Git 根、当前分支、基准 commit、工作树快照引用、分析范围；
- assets[]：资产 ID、版本 ID、内容 hash、本地版本路径、来源；必要的文本摘要在预算内注入；
- 本轮允许的操作范围：架构分析主要读取，开发修改仍遵循原权限机制。

不直接将整个代码库塞入提示词。为 Agent 提供经过校验的仓库路径、范围、摘要及资产引用，让工具按需读取。多个仓库不能挤进单一 workspaceId；保留主执行目录，同时扩展显式允许读取/操作的仓库集合。

工作树快照范围与真实工具读取范围必须一致：若 Agent 扩大读取范围，补充记录读取时文件哈希/版本。无法保留完整快照时应标记可追溯范围，不能宣称能重放整轮代码环境。

## 7. 聊天记录中的展示

- 输入框标签代表“下一轮将带上的资料”，随选择变化。
- 每条已发送消息下方展示可折叠“本轮上下文：2 个仓库 / 2 份资产”。展开可查看当时路径、代码版本、工作树状态与资产版本。
- 仓库/资产详情页签用于管理资料；不再为每个仓库增加聊天标签页。
- 不显示完整内部提示词、凭据或工具实现参数。

## 8. 数据与接口建议

在既有需求归属与资产服务上增量扩展：

- requirement_repositories：space_id、local_workspace_id（可选）、规范路径、远程标识、用途集合、显示名。
- requirement_stage_repository_refs：space_id、stage_key、repository_id、分析范围、是否选中。
- requirement_stage_asset_refs：space_id、stage_key、asset_id、asset_version_id。
- requirement_turn_contexts：conversation_id、turn_id、需求/资产/仓库输入快照引用。

新接口包括仓库查询/关联/解除、路径校验、阶段引用保存、本轮上下文预览。HTTP 与 IPC 必须同步接入；创建远程克隆任务单独分期，不把网络克隆塞进同步保存接口。

## 9. 验证重点

1. 架构阶段关联前端、后端及公共库，Agent 获得全部选中仓库的正确本地路径与范围。
2. 同用途多个仓库、monorepo 多用途不会覆盖彼此。
3. 切换阶段并返回，专家、会话和引用选择完整恢复。
4. 切换需求或账号后不出现其他空间的仓库/资产。
5. 路径失效、未克隆、Git 根变化、工作树变更明确展示，不能报告虚假的校验成功。
6. 发送后改变仓库或资产选择，历史轮次的上下文记录不变化。
7. 架构分析只读取；多仓库开发的写入权限仍逐仓库生效。
8. 已上传资产不变时不重复上传，修改后保存新版本；源码不上传为 TAPD 附件。

验证方法：后端单元/集成验证、前端构建、人工桌面交互验收；不新增前端自动化测试。

## 10. 会话产物与阶段提交（2026-09-16）

- 本地资产列表读取时登记各阶段会话的产物。独立会话目录扫描常见文档/图片格式（最多 500 个目录项、8 层、单文件 10MB）；绑定工作区时仅登记持久化的 `present_files` 成功交付和 artifacts 记录，不扫描代码仓库。
- 文件以会话与相对路径标识，同名不同目录不覆盖。生成的新版本显示“已交付，待提交”，已确认的历史上下文版本不变。资产工作副本已提交的修改不会被未变化的原始交付文件覆盖。
- “提交文档并完成阶段”不再弹出文件选择器。自动收集当前阶段会话产物，逐个上传到项目配置的 TAPD 附件字段；所有上传成功后，再校验并更新需求状态。失败保留本地版本和成功上传记录，重试跳过已上传的相同内容/目标字段。
- GET/POST `/api/conversations/:id/requirement-completion` 同步提供 HTTP 和 Electron IPC。校验需求账号归属、会话忙碌状态、工作流当前状态和流转目标；保存提交回执用于重复点击与状态更新响应丢失后的重试。
- 目标从 TAPD 项目实际工作流读取，唯一目标自动选择，多个目标由用户在按钮旁选择。流转成功才切换本地阶段；手动切换阶段仍不修改 TAPD。
- TAPD 官方提供 `POST /files/upload_attachment`、`GET /attachments/down`、`GET /workflows/all_transitions` 和 `POST /stories`。下载前获取临时链接，不依赖附件列表中的 URL。并行节点工作流暂不自动推进，明确提示，避免普通状态更新重置并行节点。
- 后端测试覆盖真实数据库迁移、产物登记/隔离、工作副本保护、部分上传失败、重试去重、状态冲突和响应丢失恢复。生产 TAPD 账号的字段权限、工作流附加必填项及桌面交互仍需实际项目验收；此次未上传真实需求附件或修改真实需求状态。
