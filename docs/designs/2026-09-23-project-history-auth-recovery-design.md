# 产研需求历史与授权恢复

> 2026-10-10 更新：项目授权改为跳转连接器中心的 TAPD 详情，授权期间保留项目页面，确认后返回并刷新。原地授权弹窗已移除，详见 [统一授权入口设计](2026-10-10-project-tapd-connector-authorization-design.md)。

## 背景与目标
用户已确认：提供账号隔离的最近需求入口，恢复项目/阶段/面板；TAPD 过期保留本地现场，在原页面重新授权，完成后刷新读取，不重放写操作。

## 现状
ProjectPanel 切走即卸载且仅持久化项目数据，无导航历史。需求会话、输入和本地资产入口先依赖远端 TAPD。RequirementsDesk 授权失败清空已有数据。

## 方案
账号命名空间保存最近进入产研的需求快照和导航信息，按最近访问排序，可固定/移除/展开更多。侧栏直接选择历史，ProjectPanel 从本地定位恢复，不经搜索。历史不是权限凭据；后端本地读取必须验证 requirement_spaces.account_id。首次建立需求空间必须先成功验证远端需求。已有空间允许本地输入管理、资产读取及会话恢复，远端附件下载、提交、状态流转继续走原授权校验。
项目页统一授权状态提示与原地授权弹层，复用已有 TAPD 授权卡片。定期及窗口聚焦检查状态，过期不卸载需求内容。恢复授权后广播只读刷新；禁止自动重放提交。需求列表保留最近成功数据并标注同步时间，无缓存时明确授权提示。

## 非目标与影响范围
不实现 token 续期、不改 TAPD 授权协议、不修改启动逻辑。只修改前端导航/授权提示及本地需求 API 的远端依赖边界，不新增 IPC 通道。历史保存本地非凭据数据；旧共享 demo 存储不自动认领给其它账号。

## 风险与验证
防止跨账号缓存串用、旧请求覆盖新页面、授权后重复写入。仅 TypeScript、语法、差异检查，不执行测试或构建。Windows/macOS 共用前端和 Node 实现。
