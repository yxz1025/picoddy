# 测试专家单端与跨端业务场景

## 背景与目标
用户确认单端用例、多端全流程、前置数据及按需子 Agent 分工，并要求修改本地专家。现有本地专家以单目标执行为主，交互只有生成后确认路径。

## 方案
更新本地专家包而非客户端内置流程：范围分为 single-target/cross-target，端与仓库为多对多映射。提供先生成用例再确认和直接授权启动两种入口；未授权执行时不造数或启动工具。统一定义场景、各端入口/角色、步骤依赖/真实 ID 传递、setup/teardown、运行报告。
复杂场景按需委派分析和脚本生成，主专家统筹范围与结果；统一业务仓库脚本负责执行，有依赖步骤顺序运行。只允许无依赖且账号和数据隔离的场景并发。新增场景配置示例与编排参考，专家根据真实仓库生成业务入口；现有 run-wechat.cjs 保持单端，不能冒称通用跨端执行器。

## 非目标与影响范围
不修改客户端、启动、会话、TAPD 上传、Excel 模板或现有单端 SDK 执行器。不执行测试或安装依赖。修改目标为本地缓存包，市场更新可能覆盖，保留更新前快照。

## 风险与验证
未知业务规则不自动推断；不重复创建未知结果的数据，依赖失败阻塞后续步骤；隔离各端身份，限制清理本轮资源，清理失败报告。仅静态 JSON/YAML/链接/差异检查与原有执行器字节比对；写入前校验目标未被并发修改，安装后逐文件校验。
