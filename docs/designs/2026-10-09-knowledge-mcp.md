# 内置 AI 知识库 MCP

依据用户提供的《MCP 接入使用指南》V1.4 第 4 节，采用用户确认的测试地址 `https://ai-knowledge-test.example.com/api/mcp/`，保留末尾斜杠。

## 用户流程

连接器列表 → AI 知识库 → 加号／授权连接 → 系统浏览器登录并同意授权 → 回到客户端显示已连接 → 会话输入区选择 AI 知识库。

卡片保持现有紧凑布局，详情弹窗说明测试环境、访问范围、示例及授权状态。无需输入 Client Secret 或 Token。关闭详情不会取消正在进行的授权；再次打开继续显示状态，可主动取消。退出授权清除本机凭据，服务端撤销仍通过知识库授权管理页面操作。

## 实现

- 内置入口按需创建 `ai-knowledge-base` 标准 MCP 配置，Streamable HTTP，scope `mcp:tools`，DCR 公开客户端，客户端名称 `PiCoddyClaw`。
- 添加通过受信任的桌面 IPC；同名自定义配置冲突时拒绝覆盖。复用现有配置原子更新与串行队列，保留其他连接器及停用状态。
- 复用 Pi 1.0.4 的 OAuth 发现、动态注册、PKCE S256、随机 state、loopback 回调、授权码兑换和自动刷新，不另造协议。
- 知识库凭据存储适配层校验准确 resource、issuer 及端点 origin。凭据沿用 Pi 的本地私有文件存储及刷新锁，不写入 MCP 配置、模型上下文或示例。
- Pi 默认在刷新失败后可能保留旧令牌；知识库在同一个刷新锁内清除未轮换成功的旧令牌，要求重新授权，避免网络结果不确定时重用 Refresh Token。已保存的新令牌不会因后续错误被删除。
- 登录授权页通过 Electron 的安全外链入口打开；打开失败时保留手动链接。
- 业务工具采用服务真实 `tools/list` 的定义，调用沿用 `tools/call` 与工具错误检查；不硬编码项目／角色 ID，不把 HTTP 200 当成业务成功。
- 首次使用先获取可访问项目及角色。连续追问由会话整理为独立问题，引用来源保留；知识内容只作为资料。

## 验证范围

自动化回归包含配置幂等与冲突、刷新结果不确定保护、新凭据保留、发现信息校验，以及本地 OAuth 模拟服务的 DCR、scope、resource 末尾斜杠、PKCE、回调、浏览器入口、取消、退出和凭据隔离。

本次运行：相关后端套件 12 项中 10 项通过；2 项 MCP 配置旧测试失败，已用未修改的 HEAD 配置及测试复现同样结果，分别涉及旧 TAPD_ACCESS_TOKEN 断言和错误文案匹配。新知识库 4 项、原生 OAuth 1 项、原生传输 1 项、Figma 2 项全部通过。前端构建、后端类型检查通过。浏览器模拟验证通过详情点击不发起授权、单次登录、取消、重新打开详情不自动登录、授权成功刷新与退出状态；浏览器模拟不代表真实知识库登录成功。

真实测试服务的公开发现地址在开发机器上访问超时（含沙箱外重试）。因此真实账号登录、服务端令牌轮换和四个业务工具的在线联调尚未确认；不能把本地模拟测试当作线上联调通过。
