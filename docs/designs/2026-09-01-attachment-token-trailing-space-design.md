# 输入框附件标签尾部空白、光标稳定性与可输入性优化设计

## 背景

输入框插入附件后，附件标签中文件名右侧原本存在一段明显空白。第一次优化将删除按钮改为绝对定位，并在悬停时动态增加右侧内边距；这虽然缩短了默认空白，但标签宽度会在悬停时变化，导致紧随其后的光标和正文横向跳动。同时，标签与光标之间只有 `2px` 右外边距，视觉距离过近。

宽度与间距修复后，附件位于空正文末尾时又暴露出更底层的问题：光标高度接近整行输入区、基线异常，并且虽然能看到光标却无法键入文字。这两个现象来自同一个空光标锚点实现，不是继续调整附件间距可以解决的视觉问题。

## 目标

- 缩短附件标签默认状态下的尾部空白。
- 保留悬停后删除附件的能力。
- 附件标签在悬停、聚焦和删除按钮显隐时保持宽度不变，避免光标和正文跳动。
- 在标签与光标/正文之间提供稳定、清晰的视觉间距。
- 附件后没有正文时提供真实、稳定的可编辑光标落点。
- 光标使用正文的 14px 字号与 1.5 行高，不再继承附件或输入区整行高度。
- 恢复附件后的键盘输入、中文输入法、粘贴和退格删除行为。
- 不影响附件锚点、光标位置、发送内容和消息回显。

## 非目标

- 不调整输入框整体尺寸、按钮栏或占位文案。
- 不修改技能标签和上下文标签。
- 不改变附件上传、删除和发送逻辑。
- 不把内部光标占位字符写入正文状态、发送请求或消息记录。

## 现状与根因

原始实现中，`.composer-attachment-token__remove` 使用 `opacity: 0` 隐藏但仍参与 `inline-flex` 布局，因此文件名后方始终保留约一个删除按钮的空白。

第一次优化把删除按钮改为绝对定位，但又在 `:hover` / `:focus-within` 时将标签右内边距从 `7px` 改为 `24px`，且为该属性添加过渡。内边距参与盒模型宽度计算，鼠标进入和离开标签时会持续改变整个行内标签的宽度，浏览器因此重新排布相邻的插入光标和正文，形成明显跳动。标签当前使用 `margin: 1px 2px`，右侧 `2px` 也不足以清晰分隔标签与光标。

附件和上下文标签在纯文本模型中长度为零，编辑器末尾是这类 `contentEditable="false"` 标签时，`rebuildEditorDOM()` 会追加 `.composer-token__text--caret-anchor`。当前锚点只包含 `TextNode("")`：

- 空文本节点没有可供浏览器稳定定位的字符边界；
- `setCaretOffset()` 在零长度节点上最终使用 `range.setStartAfter(...)`，把选区放到空锚点外部；
- 点击附件时也把 Range 放在不可编辑标签与空锚点之间；
- Chromium 可以在该边界绘制一个由外层行盒推算的高光标，但不能稳定接收文本输入；
- 输入区还包含 29px 高的附件标签、`minHeight` 和上下内边距，因此边界光标高度和基线进一步失真。

## 方案

- 将附件删除按钮改为绝对定位，使其在默认隐藏状态下不参与标签宽度计算。
- 附件标签增加 `position: relative`。
- 默认保持当前右侧内边距，使文件名与边框间距紧凑。
- 移除悬停/聚焦时动态增加右内边距的规则以及内边距过渡，保证标签宽度在交互前后完全不变。
- 删除按钮悬停时直接覆盖在标签右侧区域，并使用与标签一致的背景遮盖其下方内容；仅透明度、背景色参与过渡，不触发布局变化。
- 将附件标签右外边距从 `2px` 增至 `6px`，为标签后的插入光标和正文提供固定间隔；左侧外边距保持不变。
- 使用一个零宽字符作为末尾光标锚点的真实文本内容，使浏览器可以把 Range 放进可编辑文本节点，而不是放在 `contentEditable=false` 标签边界。
- 新增统一的锚点识别和模型文本转换：零宽占位字符在 DOM 中存在，但在 `plainTextOf()`、`nodeTextLength()`、`caretOffset()`、附件偏移和发送正文中按长度零处理；若用户在锚点内键入内容，只忽略占位字符，真实输入仍进入纯文本模型。
- `setCaretOffset()` 遇到末尾锚点时，明确把选区放进锚点文本节点的零宽字符之后；点击末尾附件也复用相同定位逻辑。
- 锚点显式继承正文的字号和行高，并覆盖为基线对齐，使原生光标高度与正文一致。
- 保留现有结构调和流程：首次输入后，锚点内的真实文字会进入 `text` 状态，下一次调和将其重建为普通 `.composer-token__text`，零宽字符不会残留。
- 技能标签和上下文标签的视觉布局不调整；它们位于编辑器末尾时可复用同一可编辑锚点机制。

## 风险与控制

- 删除按钮出现时可能覆盖长文件名末尾：只在用户悬停附件时短暂覆盖，并使用标签背景保证按钮清晰；标签宽度不再变化。
- 删除按钮不可点击：隐藏状态关闭指针事件，悬停或聚焦状态恢复，原点击处理逻辑不变。
- 光标间距影响行内偏移模型：仅调整 CSS 外边距，不插入文本节点，不改变附件零长度锚点和纯文本偏移计算。
- 键盘可访问性：保留 `:focus-visible` 和 `:focus-within` 展示路径，但不再改变标签尺寸。
- 零宽字符泄漏到用户正文：所有 DOM→模型入口统一剥离锚点占位字符，并在发送前继续以 `text` 状态为唯一正文来源。
- 光标偏移多算一个字符：锚点文本及锚点内选区前缀使用同一模型化函数计算，零宽字符恒定计为零。
- 输入后锚点结构未更新：现有 `editorStructureSignature()` 会忽略纯空锚点；锚点出现真实输入后，模型签名变化触发重建为普通文本节点。
- 退格无法删除附件或误删正文：仅当锚点中占位字符之前没有真实正文时，才把附件识别为紧邻标签；输入后的正文继续走原生退格和结构调和。

## 验证方式

- 前端 TypeScript 检查。
- `git diff --check`。
- 构建后人工确认默认附件标签紧凑、光标与标签间距自然，鼠标反复移入移出时光标和正文不跳动。
- 人工确认悬停仍可删除附件，长文件名默认正确省略，删除按钮显示时标签宽度不变。
- 人工确认仅有附件时光标与正文同高、基线正常，并可直接键入英文、中文、数字和粘贴文本。
- 人工确认附件后输入的正文不包含不可见字符，发送后的消息内容正确。
- 人工确认空正文时按退格可删除相邻附件；已经输入正文时退格优先删除正文，不误删附件。
- 按项目约束不自动运行测试套件。
