# 发送草稿与需求侧栏修复

## 背景与现状
Composer 在 await sendMessage 完成后清空输入，但 store 提前显示用户消息并等待 SSE/prompt，导致重复文本停留。侧栏 nav 与内容均允许 flex 收缩，资产增多时导航被挤压。

## 目标与方案
用户报告并要求处理交互问题。发送前保存正文、附件及锚点，立即清空显示；等待发送结果期间暂禁编辑，失败或异常恢复原草稿，成功不再次清空。附件在途引用沿用现有卸载保护。侧栏禁止整体溢出，nav 不收缩，内容 flex:1/min-height:0 独立滚动。

## 非目标与影响
仅 Composer 与 RequirementChat CSS；不改请求、会话、启动、附件交付及 TAPD 逻辑。Windows 与 macOS 共用前端实现。

## 风险与验证
关注发送失败草稿丢失、附件提前删除和长资产挤压导航。运行静态 TypeScript/语法与差异检查，不运行测试或构建。
