# 未签名远程更新实施记录

用户要求：实现远程更新设计，Windows/macOS 均不使用发布者代码签名。

沿用完整应用制品、静态 HTTPS feed、用户触发下载和安装、任务排空、数据库备份与启动 journal。未签名制品以 HTTPS 和 SHA-512 校验完整性，不宣称具备发布者签名认证。

macOS 原生 Squirrel 更新需要代码签名。当前代码采用下载 DMG、排空与备份后打开安装包并退出，由用户覆盖安装；没有实现独立应用替换程序。

实施顺序：

- [x] 更新策略、状态机、缓存校验、持久化和重试基础实现。
- [x] 业务请求与任务门禁、数据库冻结和一致性备份、启动 schema 检查。
- [x] Windows NSIS 与 Mac DMG 安装入口、受限 IPC、启动健康与恢复入口。
- [x] 设置页、侧栏版本及更新状态。
- [x] 未签名构建、制品发布/撤回工具及[运营说明](../remote-update-operations.md)。
- [x] 17 项更新、Windows 启动适配、真实 SQLite 备份恢复和发布清单测试通过；更新核心模块定向类型检查、前端类型检查与构建通过。
- [ ] 完整后端类型检查：业务依赖中仍有 installed_skill、attachment/store、connector/agent_session_store、skill-draft/store、skill/store 的既有类型错误；本次检查没有 updates 模块错误。
- [ ] Windows/macOS 真实制品、旧到新升级、UAC 与安装目录权限验收。
- [ ] 根据实际 MSI 标识和卸载行为实施桥接迁移；当前只有人工/IT 迁移说明，不自动卸载旧 MSI。

本次续做补齐：

1. 损坏或丢失的安装缓存退回可下载状态，避免反复点击安装但无法修复。
2. Windows 使用更新库验证过的缓存，等待进程启动/UAC 决定后才退出。固定本地 PowerShell 启动器通过环境变量接收路径；拒绝授权时抛出 INSTALL_PERMISSION，由协调器恢复业务与数据库。没有远程脚本执行入口。普通退出仍不会安装。
3. Windows 空间检查使用更新库实际缓存卷；备份卷和安装卷分别检查。
4. macOS 先打开旧版、之后再人工覆盖的情况仍执行目标版本健康检查。
5. 验证期间禁止检查与安装其他更新；验证运行时平台、架构、Python 归档大小、锁定的 Node/Electron/npm 版本及 read_doc 工具装配，不解压 Python。
6. 观察失败持久化 journal，并重启到业务模块加载前的恢复页，避免在线恢复与现有数据库连接竞争。
7. 回归测试覆盖取消准备时不能提前重开门禁、迟到下载回调、撤回、缓存篡改、UAC 取消、特殊字符路径、WAL 数据、恢复前保留新数据库及发布清单与客户端一致性。

发布环境尚需真实 HTTPS 域名和已发布 MSI 产品标识；没有更新源配置时客户端显示未配置，不向示例域名发请求。未执行发布、卸载或替换用户当前应用。
