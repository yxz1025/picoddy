# TestX 用例批量创建

状态：用户已指定每批 200 条并授权修改代码；批量实现已落地，待真实 TAPD 验证。

## 背景与目标

当前 `test_case_import.ts` 对每条 Excel 用例分别创建并读取详情，N 条首次上传至少产生 N 次创建和 N 次详情请求（不含目录查询）。改为分批创建，减少写请求；保留字段核对、需求关联、目录归属、账号隔离与安全续传。

## 非目标

不改启动、会话、产物生成和附件提交逻辑；不改旧版 tcases 接口；不实现浏览器 Excel 导入；不承诺本次解决 Excel 详情准备阶段的限流。共享 OAuth、请求调度及限流模块保持现状。

## 接口依据

官方文档：https://open.tapd.cn/document/api-doc/API%E6%96%87%E6%A1%A3/api_reference/testx/case/batch_create_case.html

`POST api/testx/case/v1/namespaces/{namespace}/repos/{repo_uid}/versions/{version_uid}/cases/batch-create`

请求包含 `TargetFolderUid` 与 `Cases` 数组，支持步骤、预期、标签、优先级及 Issues。复用现有用例字段转换与 IssueUrl 工作空间映射。官方未明确单批上限，且返回示例为单个用例，不能假设返回数组顺序等同请求顺序。

## 方案

1. 完整校验工作簿、版本、唯一标题和目标后，复用现有历史记录检查。
2. 已确认成功的用例直接复用；有远端 ID 或结果未知的历史用例先核对，不能重新进入创建队列。
3. 新用例按最多 200 条串行分批创建（用户已指定）。200 是客户端批大小，并非已确认的新版 TestX 官方上限，实际接口容量仍待验证。每批发送前持久化该批所有行的 creating 记录；身份检查通过后才发送。
4. 一次请求提交该批 Cases。以目标目录中的远端查询和必要的单条详情读取核实结果，按唯一标题、内容、目录及需求关联匹配，不能按响应顺序分配 ID。创建响应若不能可靠映射，也不能盲目重发。
5. 保留逐条回执：已确认 ID 先落盘为 created，字段及需求关联确认后为 linked；批次异常或缺失结果记为 unknown。部分成功、超时、服务异常不等同于整批没有写入。
6. 本批出现未知结果或限流时停止后续创建。续传先核对已发送批次，确认成功的跳过；结果仍不明确的保留提示，不自动重建。未发送的批次保持可提交。
7. 复用现有串行请求调度和限流错误，不添加无上限重试。保留单条详情核验，因此请求量下降主要来自创建合并，不宣称所有请求缩为一次。
8. 前端只调整上传文案体现分批提交，逐条回执继续展示。不更改按钮、会话状态或附件提交流程。

## 影响范围

- `src/domains/requirement/node/test_case_import.ts`：创建队列、批次持久化、批量请求与核对。
- `test/src/domains/requirement/test_case_import.test.ts`：更新模拟 API，覆盖真实批次及异常续传。
- `frontend/src/components/projects/TestingDeliveryControls.tsx`：必要的上传说明文案。
- 更新对应测试交付专项文档。无新增依赖、数据库迁移、启动配置改动。

## 风险

批量接口的实际响应及部分失败语义需真实环境验证。没有确定远端结果时宁可保留未知状态，不自动重复创建。详情核对仍可能遇到限流；这与批量创建是否成功必须分别记录。只用 Node 跨平台能力，不引入平台专用路径或命令。

## 验证

编写：多条用例合并一次创建、200 条同批及 201 条分两批、保留完整字段和需求关联、响应缺失或顺序不同、批次部分写入后超时、续传不重复、限流停止后续批次、身份变化停止、原成功回执复用、Excel 校验不退化。

依项目约束，仅执行 TypeScript 类型检查和差异检查，未经明确授权不运行测试套件。真实创建会向 TAPD 写入数据，不在本轮设计及实现验证中自动执行；交付时明确未验证项目和 Windows 实机限制。

## 实施记录

- 创建使用 `/cases/batch-create`，客户端每批上限 200；最后不足 200 的用例单独一批。
- 每批发送前持久化所有 creating 回执。任何批级错误均保留 unknown，不依据错误类型推断整批未写入。
- 同一核对组共用一次目标目录分页读取（每页 200，官方查询上限），先按标题和目录查找候选，再读取详情核实全部字段和需求关联；仅唯一完整匹配才绑定 ID，不依赖批量响应结构或顺序。
- 已知 ID 续传直接读取详情；未知记录先查找，仍未知则停止新批次。传输、授权和限流异常停止继续读取；字段不一致时，已有可信 ID 的回执保留 created，尚未绑定 ID 的回执保留 unknown，均阻止后续创建。
- 正常附件提交、启动、会话、共享限流及 OAuth 模块未改。
- 验证记录：主进程、前端和回归测试源码 TypeScript 检查通过；未运行测试套件，未进行真实 TAPD 批量写入或 Windows 实机验证，200 条实际接收容量尚未验证。
