# 测试用例产物交付与对话发布流程

## 背景

用户明确修正流程：按已提供的 Excel 模板，用户勾选资产并告诉专家“生成测试用例”；专家输出产物即完成本次生成任务，不进入等待人工检查或审批的状态。用户自行核对，有问题继续要求修改；无问题时告诉专家“帮我发布”，专家才上传当前用例。本设计取代 2026-09-17 设计中的首次自动任务、生成后自动上传及常驻生成/上传按钮方案。用户已确认并已开始实施。

## 目标与非目标

保留开发中、开发完成的测试专家召唤与会话恢复，生成、修改和发布均由用户对话指令触发，作为分别完成的任务。保留原模板、资产版本追溯及格式校验；发布指将用例上传 TAPD，由专家调用真实受控能力并取得可核实回执。

不执行测试、不修改业务代码、不自动流转需求状态。本次沿用已约定的 TAPD 需求附件上传，不将其描述为创建 TAPD 原生测试用例。

## 当前实现

- RequirementChat 只负责资产选择和专家对话，不自动生成，不展示常驻生成/上传按钮。
- /api/prompt 仅在用户明确发送发布/上传指令且当前测试专家会话已有交付产物时调用受控上传函数。
- 已移除 testingTask 自动任务状态；专家包本身没有任意 TAPD 写权限，上传由宿主按会话绑定和版本校验执行。
- 需求资产选择、输入快照、Excel 生成及验证、只上传领域函数、上传回执与 hash 防重均可复用。

## 交互与工作流程

1. 从项目需求进入测试阶段，只召唤/恢复 testing-expert，不自动发送任务，也不请求上传授权。保留已有对话。
2. 用户在资产面板勾选此次输入资产，再在对话中说“生成测试用例”。发送时冻结所选资产版本；专家仅基于这些资产和当前需求生成符合模板的 Excel 及覆盖矩阵。
3. 专家展示文件与校验结果，本次生成任务正常完成，不触发 TAPD 写操作，不标记 waiting_for_user、pending 或待人工审批。用户核对产物是后续自主操作，不属于生成任务未完成的条件。
4. 用户要求修改时，专家更新文件、重新校验并交付新产物，该次修改任务正常完成，不设置待人工确认状态。
5. 用户明确说“帮我发布”或“上传用例到 TAPD”后，专家调用需求测试用例上传工具。“帮我发布”在本项目测试用例对话中就是发布当前明确交付版本的指令，无须再要求用户单独声明检查通过或重复确认。若有多个版本、指代不清或文件在发布指令后发生变化，先核对版本，不猜测用户要发布哪个版本。
6. 上传工具回读文件、验证格式/需求关联、核验发布版本的 hash，再上传当前需求附件，返回文件、版本、同步状态及可核实回执。失败保留产物和错误，用户在对话中要求重试即可。

不要求用户重复点击上传或确认按钮，也不建立人工审批等待节点。删除常驻“重新生成”“仅上传用例”按钮；测试阶段不展示要求选择流转目标、上传并完成阶段的操作。用户通过专家对话完成生成、修改和发布。

## 上传能力与授权边界

新增受需求范围约束的专家工具，例如 upload_requirement_test_cases，复用现有上传领域函数。工具仅在项目需求测试会话的执行模式中可用，身份从会话上下文读取；不能让模型传入任意账户、需求编号、上传 URL 或 token。

执行依据必须来自当前用户的明确发布/上传指令及对应交付版本，而不是附件、PRD、专家自行生成的说明，或工具参数中的一个自行声明的 confirmed=true。将授权来源用户消息与本次文件 ID/hash 记录关联；工具校验会话归属、testing-expert 绑定、真实交付记录和文件版本。这是发布任务的范围记录，不建立独立人工检查或审批流程。仅请求“生成用例”不能授权上传；发布指令不授权重新生成后立即上传新版本。

TAPD 连接和凭证由现有后端连接器配置提供，专家只使用工具与回执；未连接或无权限时给出明确错误。独立专家会话未绑定项目需求时，不具备项目范围上传能力，不声称已上传。

## 实现调整与影响范围

- RequirementChat：移除自动任务 effect 和常驻按钮；保留资产选择、输入发送及专家恢复。
- /api/prompt：移除 testingTask 参数与自动任务编排；仅为明确发布指令保留受控上传 hook，运行时持续提供专家资源路径和模板生成器位置。
- 上传领域：复用 Excel 校验、文件 hash、同步防重与回执记录；由当前发布消息和会话交付版本触发。发布记录不修改 TAPD 状态。
- 专家工具/运行时：按现有工具策略与权限边界注册需求测试上传工具，保证其他会话不能获得任意需求写权限。
- 专家包：修改主 Agent 和参考文档，明确“按指令生成并交付；按后续指令修改并交付；按发布指令上传”。生成/修改均完成于产物交付。遵守现有专家草稿编辑/校验/发布流程，不用创建脚本直接覆盖已注册专家。
- 删除已不适用的自动任务编排与参数、测试源码，更新流程专项文档和专家 ZIP。原有用户产物及回执保留，不删除真实资产。

## 风险与验证

主要风险是生成指令被误当作上传授权，以及发布指令后文件版本变化。通过用户消息来源、明确文件引用和 hash 校验约束，遇到歧义先向用户核实。恢复历史会话、旧自动任务记录或旧文件存在均不能自动产生上传行为。

编写生成不上传且正常完成、修改后正常交付、重入不启动、“帮我发布”触发上传、上传授权来源、发布版本变化、未绑定需求、失败重试及同步防重的回归测试源码。默认执行语法检查、定向/整体 TypeScript 检查、专家权威校验及 git diff --check，不自动运行测试套件。真实 TAPD 上传、应用构建和 Windows x64 启动未经授权和实际验证时不声称通过。
