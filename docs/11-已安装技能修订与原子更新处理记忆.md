# 已安装技能修订与原子更新处理记忆

## SkillHub 动态认证（2026-10-10）

点击左侧“专家·技能·连接器”菜单时通过 `POST /api/skillhub/auth/ensure`（IPC `skillhub.ensureAuth`）检查远端 Session。首次使用邮箱加密凭据登录 SkillHub，然后创建永久 API Token；Session 有效时复用第一次获取的 Token，Session 过期重新登录并创建同名 Token。namespace 查询、技能和专家下载共用当前用户 Token。源码固定 Token 已移除。

Electron 主进程从 `SKILLHUB_AUTH_ACCESS_TOKEN_SECRET` 环境变量或系统钥匙串的 `skillhub-access-token-secret` 条目读取与 SkillHub 服务端相同的 Base64 编码 32 字节共享密钥。当前业务登录资料必须包含真实 `email`（或 `mail`）；不能以工号推导邮箱。完整 API Token 和 SESSION/XSRF Cookie 通过 `safeStorage` 加密保存在应用数据目录的 `skillhub-auth.enc`，退出时清除；CLI 的临时明文配置在调用结束后删除。

接口协议、边界及配置说明见 [动态 Token 设计](designs/2026-10-10-skillhub-dynamic-token-design.md)。API Token 不按时间轮换；一次性加密登录凭据的有效期为 300 秒，Session 有效性通过服务端 `/api/v1/auth/me` 判断。

### 共享密钥配置修复（2026-10-10）

专家·技能·连接器面板提供“配置技能市场”，填写管理员提供的共享密钥后，通过专用 `GET/POST /api/skillhub/auth/config`（IPC `skillhub.authConfig` / `skillhub.saveAuthConfig`）校验并调用系统安全存储，保存后重新认证并加载当前市场列表。接口只返回配置来源和有效状态，不返回密钥。Windows 使用现有 DPAPI 存储，macOS 使用钥匙串；输入不写入普通配置文件。

非空 `SKILLHUB_AUTH_ACCESS_TOKEN_SECRET` 优先，其次是既有通用钥匙串环境变量 `SKILLHUB_ACCESS_TOKEN_SECRET_API_KEY`；空白值按未配置处理，再读取安全存储。非空但格式错误的环境配置明确报错；环境变量生效期间拒绝在面板保存，须先修正或移除变量并重启应用。认证失败或检查中不再显示市场无结果提示。启动不自动读取项目 `.env` 文件。详见 [修复设计](designs/2026-10-10-skillhub-secret-configuration-fix-design.md)。

## 目标

已安装技能不能直接进入可写状态。用户需要先显式创建修订版，系统复制当前已安装目录的完整文件集，后续 Agent 只修改隔离草稿。只有草稿校验通过且用户再次确认后，系统才更新已安装技能。

## 产品流程

1. 技能安装完成后，面板只展示“已安装内容”，并提供“创建修订版”。
2. 点击“创建修订版”后，将 `skills/<name>` 安全复制到当前会话的 `skill-drafts/<id>/package`。
3. 草稿元数据记录：
   - `revisionOf`：被修订的已安装技能名。
   - `revisionBaseDigest`：创建修订时的已安装文件清单指纹。
   - `revisionCreatedAt`：修订开始时间。
4. 面板进入双视图：
   - “修订草稿”：Agent 可通过 `skill_draft_*` 工具修改。
   - “已安装版本”：始终直接读取 `skills/<name>`，只读展示。
5. 修订草稿必须通过原有结构、安全路径、UTF-8 和元数据校验；技能名不允许在修订过程中改变。
6. 用户点击“校验后更新”并确认后，系统检查已安装版本的指纹是否仍与修订基线一致。
7. 指纹一致时进入原子替换事务；不一致时返回 `INSTALLED_SKILL_CHANGED`，禁止静默覆盖。

## 原子替换

更新事务在技能名锁和草稿锁内执行：

1. 将已校验草稿复制到唯一 staging 目录并再次校验文件清单。
2. 写入 `install-intent.json`，模式为 `replace`，记录 staging 与 backup 名称。
3. 将当前已安装目录重命名为 backup。
4. 将 staging 重命名为正式安装目录。
5. 持久化草稿状态为 `installed`，清除修订字段。
6. 删除事务 marker、backup 和 intent。

任何正常异常发生在元数据提交前，都会把新目录移回 staging，并把 backup 恢复为正式安装目录。进程在替换中途退出时，下次读取草稿会依据 intent、marker 和 backup 自动完成提交或恢复旧版本。

## API

- `POST /api/skill-drafts/:draftId/revision`：从已安装版本创建修订草稿。
- `GET /api/skill-drafts/:draftId/installed-files`：列出真实已安装文件。
- `GET /api/skill-drafts/:draftId/installed-file?path=...`：读取真实已安装文件。
- `POST /api/skill-drafts/:draftId/validate`：校验草稿。
- `POST /api/skill-drafts/:draftId/install`：初次安装或原子更新。

所有接口继续校验草稿所属会话必须为 `skill_creator`，文件访问沿用安全相对路径、符号链接拒绝、文件和包大小限制。

## Agent 约束

Agent 不直接写入已安装目录，也不执行安装。创建修订版由用户在面板触发；修订创建后，Agent 仍只使用 `skill_draft_*` 工具修改隔离草稿；最终更新由用户在面板确认。

## 系统内置技能启动与构建记忆（2026-08）

系统内置技能来源已改为真实目录 `resources/builtin-skills/`，当前包含
`weekly-report`、`data-analysis`、`presentation`、`polish-writing`、`doc-qa` 和
`skill-creator` 六项。构建任务 `deno task build:builtin-skills` 扫描该目录，生成
`builtin-skills.manifest.generated.json` 以及包含确定性 gzip/tar payload 的
`builtin-skills.bundle.generated.ts`；构建失败会阻断桌面打包，重复构建的 digest 和
压缩字节保持稳定。桌面、macOS 和 Windows portable/MSI 任务均先执行这个前置任务，
不引入第二套统一技能索引。

启动时 `ensureBuiltinSkillsInstalled()` 将 bundle 解压到系统保护根目录的
`builtin-skills/versions/<digest>`，并以 `current` 指针选出活动版本；`skills.ts` 只扫描
这个活动目录和用户技能目录，内置技能优先解决同名冲突，提示词仅渐进加载元数据，正文
按需读取。`versions` 容器本身不会被扫描，技能路径始终指向活动版本。

系统根、活动指针和内置版本由保护路径策略以及固定 OS advisory lock 管理，应用代码和
内置技能目录不可由 Agent 直接改写；Agent 的可写目标限于会话工作区/产物根。主进程和
legacy sidecar 都必须在技能安装、指针解析和索引完成后才初始化模型并输出
`skills-loaded`；安装或校验失败时会记录明确错误且不会进入 ready 状态。Windows 实机
打包/启动验证暂缓，当前仅保留路径注入和静态回归覆盖。

### 网页列表登录态（2026-10-10）

技能/专家列表与专家详情的 `/api/web/skills` 请求通过 `withSkillHubSession` 携带已检查的 SESSION、XSRF-TOKEN Cookie。会话过期沿用邮箱 access_token 登录流程获取新 Cookie；不把匿名空列表当成用户列表。命名空间与 CLI 下载继续使用 API Token，Cookie 仅留在主进程。
