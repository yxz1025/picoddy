# 插件斜杠选择与会话级工具激活设计

## 背景

当前插件运行时在安装完成后立即加载扩展，并通过 `getPluginTools()` 汇总全部已安装插件的工具。`getFullTools()` 和 `getReadOnlyTools()` 在每轮 Prompt 装配时都会把这些工具合并进 Agent 工具集合。因此，“已安装”事实上等于“对所有普通会话持续可用”。

这种机制保留了 Agent 对“是否调用某个工具”的自主判断，但没有限制 Agent 在判断时能看到哪些插件工具。随着插件数量增加，所有插件工具的名称、描述和输入 schema 都会进入模型上下文，增加上下文成本、工具误选概率和插件同名覆盖风险。

本设计把插件的安装状态与使用状态分离：安装只让插件进入可选目录；用户通过 Composer 的 `/plugin` 斜杠入口为当前任务选择一个插件；宿主只把该插件的工具提供给 Agent；Agent仍然根据每条消息的实际意图自主决定是否调用其中的工具。

## 目标

- 已安装但未选择的插件工具不进入 Agent 工具集合。
- 用户通过 `/plugin` 搜索并选择已安装插件。
- 插件选择形成会话级绑定，后续消息持续开放该插件工具。
- 选择插件不强制调用工具，也不向每条用户消息重复添加指令。
- 新建任务默认没有插件绑定。
- 选择另一个插件时原子替换当前绑定。
- 选择普通技能时解除插件绑定，普通技能仍按现有单轮显式调用执行。
- 插件卸载、加载失败或不再提供工具时，安全解除失效绑定。
- 连接器和专家的现有选择逻辑保持不变。

## 核心原则

```text
安装插件 != 激活插件
选择插件 = 为当前会话开放该插件的工具
Agent = 自主判断是否调用已开放的工具
切换能力或新建任务 = 解除或替换插件绑定
```

“斜杠选择”是用户对工具暴露范围的明确控制，不是对 Agent 的强制执行指令。

## 已确认交互语义

### 会话级持续

用户首次选择插件后，绑定写入当前会话。发送完成后 Composer 不丢失该状态；后续消息即使没有再次输入 `/plugin`，后端仍只加载当前绑定插件的工具。

例如选择联网搜索插件后：

- 用户要求搜索最新信息时，Agent可以调用插件的搜索工具。
- 用户要求总结刚才结果时，Agent可以直接回答，不必再次调用搜索工具。
- 用户讨论无关内容时，Agent可以完全不调用插件。

### 单选与替换

每个普通会话最多绑定一个插件。首版不支持多个插件组合，避免重新引入工具膨胀和选择歧义。

- 选择另一个插件：原子替换当前插件。
- 选择普通技能：清除当前插件绑定，再按现有 `/skill-name` 机制执行该技能。
- 删除当前插件标签：清除会话绑定。
- 新建任务：不继承上一任务的插件。
- 切换回已有任务：恢复该任务持久化的插件绑定。

普通技能的完整 `SKILL.md` 不改为会话级强制调用。技能继续作为本轮 invocation 处理；插件会话绑定只控制工具是否可见。

## 方案比较

### 方案 A：全部插件工具继续常驻，仅增加斜杠标签

实现最简单，但标签只是视觉效果，不能减少工具 schema 上下文，也不能阻止 Agent 选择未选插件。与目标冲突，不采用。

### 方案 B：插件选择仅对当前一条消息生效

工具隔离最严格，但连续任务需要每轮重复选择，无法满足用户期望的任务级连续工作。不采用。

### 方案 C：会话级单插件绑定

用户只需选择一次，宿主在后续每轮恢复同一插件工具；Agent仍自主判断是否调用。工具数量受控、状态可见、切换规则明确。本设计采用该方案。

## 领域模型

### 插件安装状态

现有插件安装目录和进程级加载缓存继续表示“插件是否可供选择”：

```text
~/.pi-a/plugins/<plugin-id>/
```

安装完成后继续发现并初始化扩展，以获得插件元信息和工具定义，但不再把所有已加载工具无条件合并到每轮 Agent 工具集合。

### 会话绑定

在 `conversations` 增加可空字段：

```text
active_plugin_id TEXT NULL
```

字段保存内部插件 ID，即 `listPluginEntries()` 返回的稳定目录 ID，不保存显示名称、斜杠别名或工具列表。

采用单字段而非关联表，因为首版明确只允许一个活动插件。项目不保留旧行为兼容层：字段为空表示没有活动插件。

会话返回给前端的 `Conversation` 增加：

```ts
activePluginId: string | null
```

### 已加载插件查询

将当前全量接口：

```ts
getPluginTools(): AgentTool[]
```

收窄为按 ID 查询：

```ts
getPluginTools(pluginId?: string | null): AgentTool[]
```

无 ID 返回空数组；ID 未加载同样返回空数组。另提供只读元信息查询，供绑定校验和 UI 构建使用，不把内部 `Map` 暴露给调用方。

插件仍可在加载阶段运行入口初始化代码。此设计只隔离提供给 Agent 的工具，不把第三方插件改成独立进程沙箱；现有插件安全模型不变。

## 前端交互

### `/plugin` 入口

Composer 增加与现有 `/skill` 并列的命名空间入口：

```text
/plugin [搜索词]
```

输入 `/plugin` 或 `/plugin web` 时，弹出已安装且成功加载的插件列表。列表项显示：

- 插件显示名称
- npm 包名或插件 ID
- 版本
- 描述
- 工具数量

使用命名空间选择器，而不是为 npm 包名直接生成斜杠命令，原因是 scoped 包含 `@scope/name`，不能安全映射到现有 `/[a-zA-Z0-9_-]+` 语法，也可能与技能名或系统命令冲突。

### 活动插件标签

选择列表项后：

1. 从输入文本中删除 `/plugin` 查询片段。
2. 调用会话插件绑定 API。
3. Composer 在输入区域上方的 chip 区展示持久标签，例如“联网搜索 · pi-web-access”。
4. 标签带关闭按钮；关闭后清除会话绑定。
5. 标签不是用户消息文本的一部分，不写入对话历史。

若用户尚在欢迎页、还没有会话，则先把插件 ID保存在 Composer 的新任务草稿状态。首次发送创建会话后，在同一次请求中完成绑定，再执行 Prompt。发送失败时保留草稿选择，便于重试。

### 切换规则

- 从 `/plugin` 选择另一插件：更新同一标签和会话绑定。
- 从斜杠菜单选择普通技能：先清除活动插件，再插入技能标签。
- 从欢迎页选择固定技能：执行同样的清除动作。
- 点击插件标签关闭按钮：只清除插件，不修改输入文字。
- 切换会话：根据 `Conversation.activePluginId` 渲染对应标签。
- 插件已卸载或加载失败：标签显示失效状态并自动请求清除，错误信息可见但不阻止用户发送普通消息。

“技能市场 → 插件推荐”中的“使用”特殊逻辑删除。所有插件统一从 `/plugin` 或 Composer 的插件选择入口使用，安装页只负责安装、卸载和查看状态。

## API 与 IPC

新增会话绑定 API：

```text
PUT /api/conv/:id/plugin
Body: { pluginId: string | null }
Response: { activePluginId: string | null }
```

行为：

- 会话不存在：404。
- `pluginId` 不是字符串或 null：400。
- 插件未安装或未成功加载：422。
- 插件没有注册任何工具：422；无工具插件不能通过本入口激活。
- 合法插件：在单个数据库更新中替换 `active_plugin_id`。
- null：清除绑定。

按照项目 IPC 规范同步增加：

- `frontend/src/api/client.ts` 路由映射。
- `src/electron/preload.cjs` 白名单方法。
- `src/electron/ipc-handlers.ts` handler，并通过 `_callApi` 进入 `handleApi`。

Prompt 请求不新增由前端任意提交的 `selectedPluginIds`。后端以会话数据库绑定为唯一事实来源，避免渲染进程伪造未安装插件 ID，也避免刷新页面后状态丢失。

首次新任务的绑定由创建会话后立即调用绑定 API完成；只有绑定成功才发送第一条 Prompt。

## 后端工具装配

### 每轮解析

`resolveSessionIntent()` 从会话记录读取 `activePluginId`，形成：

```ts
activePluginId?: string
```

`resolveRuntimeProfile()` 将该 ID传给工具策略。工具策略从插件缓存中取得该插件工具，并仅在允许使用普通工具的会话类别和模式中合并。

预期调用关系：

```text
conversation.active_plugin_id
  -> resolveSessionIntent
  -> resolveRuntimeProfile
  -> resolveToolPolicy
  -> getFullTools/getReadOnlyTools(activePluginTools)
  -> PromptEnvelope.tools
  -> Agent自主判断是否调用
```

### 模式与类别

- `craft/full`：加载活动插件的全部工具，并继续经过现有权限保护包装。
- `plan/readonly`：只加载插件声明为只读的工具。
- `ask/none`：不加载任何工具，包括活动插件工具；绑定仍保留，切回可用模式后恢复。
- 技能创建器和技能编辑器：不加载活动插件工具。
- 专家创建器：沿用该类别的工具策略；首版不允许绑定普通插件，避免与专家技能选择混合。

插件工具不能绕过 `protectWritableTool`、路径策略、命令确认和审计日志。当前“插件同名工具覆盖内置工具”的行为删除；若活动插件工具名与基础工具或选中 MCP 工具冲突，当前 Prompt 明确失败并返回冲突名称，不能静默覆盖。

### Capability 上下文

只有实际进入本轮工具集合的插件工具才进入 `activeToolNames` 和工具 schema。插件工具继续通过运行时注册集合豁免静态 capability 目录校验，但未激活插件的工具名不参与本轮能力判断。

不额外把插件 README、npm 描述或工具清单拼入系统提示。工具自身 schema 已足够让 Agent进行调用判断。

## 技能选择与插件解绑

普通技能选择发生在前端 Composer，因此前端在以下动作中先清除插件绑定：

- 从 `/skill` 动态列表选择技能。
- 从普通 `/xxx` 技能菜单选择技能。
- 接收 `composer:skill-selected` 欢迎页事件。

若清除绑定 API失败，不继续发送技能消息，并显示错误，避免界面认为已经切换但后端仍开放旧插件工具。

后端仍应提供防御性处理：若用户消息被解析为合法技能 invocation 且会话存在活动插件，在本轮执行前原子清除插件绑定，并使用不含插件工具的运行时 profile 执行该技能。这样直接调用 HTTP API 或前端状态发生竞态时，也不会同时激活插件与技能。

## 安装、卸载与失效处理

### 安装

安装完成只刷新插件缓存和 UI目录，不改变任何现有会话绑定，不自动激活。

### 卸载

卸载前查询引用该插件的会话并清空 `active_plugin_id`，随后卸载插件和删除目录。顺序保证不会留下指向不存在插件的长期绑定。

若卸载插件失败，数据库绑定不提前清除；只有实际卸载成功后清理绑定。

### 启动加载失败

应用启动时若某插件目录存在但加载失败：

- 插件不进入可选列表。
- 已绑定会话不获得任何该插件工具。
- 会话列表仍返回原 `activePluginId`，前端显示失效提示。
- 用户可清除绑定或重新安装插件。

不自动切换到其他插件，不回退为加载全部插件。

## 数据与安全边界

- 数据库只保存插件 ID，不保存工具 schema 或执行状态。
- 插件工具只在绑定会话的 Prompt 中可见。
- 插件工具执行继续受当前权限等级、只读白名单、路径策略和审计约束。
- 安装插件仍等同于允许第三方代码在主进程加载；本次改造不改变这一安全声明。
- 插件入口在加载时执行与工具在 Agent 中可用是两个独立阶段，UI文案需要明确区分“已安装”和“使用中”。
- 不允许前端用 Prompt 参数临时注入任意插件工具。

## 代码职责边界

预计修改：

- `src/agent/plugin_tools.ts`：按插件 ID查询工具，提供元信息和工具名冲突所需信息，停止全量默认合并。
- `src/agent/tools/index.ts`：显式接收活动插件工具并统一应用安全包装。
- `src/agent/prompt-runtime/session-intent.ts`：从会话持久状态解析活动插件。
- `src/agent/prompt-runtime/runtime-profile.ts`：把活动插件纳入结构摘要和工具策略输入。
- `src/agent/prompt-runtime/tool-policy.ts`：按模式和类别决定是否加入活动插件工具。
- `src/agent/prompt-runtime/types.ts`：增加活动插件相关类型。
- `src/infra/db.ts`：增加 `conversations.active_plugin_id`。
- `src/domains/session/node/store.ts`：读写、清除会话插件绑定。
- `src/domains/plugin/node/service.ts`：绑定校验和卸载时清理引用。
- `application.electron.ts`：新增会话插件绑定 API，并在技能 invocation 时防御性解绑。
- `frontend/src/api/client.ts`、`src/electron/preload.cjs`、`src/electron/ipc-handlers.ts`：完整 IPC 链路。
- `frontend/src/store/useStore.ts`：会话和新任务插件绑定状态。
- `frontend/src/store/usePluginStore.ts`：插件目录状态，删除全局 `activeCapability`。
- `frontend/src/components/Composer.tsx`：`/plugin` 搜索、持久标签、选择与解绑交互。
- `frontend/src/components/PluginSection.tsx`：移除插件专属“使用”例外。
- `docs/architecture/plugins.md`：更新运行机制和开发者说明。

实现时可以提取纯函数模型处理插件搜索、显示和切换，但不为了本功能重构整个 Composer。

## 测试设计

### 插件工具选择

- 未传插件 ID时 `getPluginTools()` 返回空数组。
- 已加载插件 ID只返回该插件工具。
- 未加载插件 ID不回退为全量工具。
- 插件卸载后查询为空。
- 插件工具名与基础工具或 MCP 冲突时报确定性错误。

### 会话持久化

- 新会话 `activePluginId` 为 null。
- 绑定已加载且有工具的插件成功。
- 绑定不存在、未加载或零工具插件失败且不修改原绑定。
- 替换插件为单次原子更新。
- 清除插件成功。
- 会话列表、单会话读取和恢复均返回绑定。
- 删除会话沿用现有级联行为，不需要额外清理表。

### Runtime Profile

- 没有绑定时插件工具不进入 full 和 readonly 工具包。
- full 模式只加入活动插件工具。
- readonly 模式只加入活动插件声明的只读工具。
- none 模式不加入插件工具但保留会话绑定。
- creator 类别不加入普通插件工具。
- `activeToolNames`、结构摘要和 Prompt manifest 只反映实际活动工具。
- Agent未调用插件工具时不会产生插件工具审计记录。

### Composer

- 输入 `/plugin` 展示已安装且已加载、有工具的插件。
- 搜索支持显示名、包名和描述。
- 选择插件后删除查询文本并显示持久标签。
- 切换会话恢复各自绑定。
- 选择另一个插件替换标签。
- 关闭标签清除绑定。
- 选择普通技能先清除插件，再插入技能标签。
- 欢迎页技能选择同样清除插件。
- API失败时保持前后端状态一致并展示错误。
- 新任务首次发送先创建会话并绑定插件，再发送 Prompt。

### 端到端验收

1. 安装两个分别提供不同工具的测试插件。
2. 新建任务但不选择插件，确认本轮 Prompt manifest 不含任一插件工具。
3. 输入 `/plugin` 选择插件 A，发送普通问题，确认只有插件 A工具进入上下文且 Agent不被强制调用。
4. 继续发送需要插件 A的请求，确认 Agent可以自主调用其工具。
5. 继续发送不需要插件的总结请求，确认 Agent可以不调用工具。
6. 切换到其他会话再返回，确认插件 A绑定恢复。
7. 选择插件 B，确认插件 A工具消失、插件 B工具出现。
8. 选择普通技能，确认插件 B解绑且该技能按当前轮 invocation 执行。
9. 新建任务，确认无插件继承。
10. 卸载活动插件，确认绑定清理且普通对话仍可发送。

## 不在范围内

- 不让 Agent自行安装、激活或切换插件。
- 不支持同一会话同时选择多个插件。
- 不把插件 README 或完整包内容注入 Prompt。
- 不把普通技能改为会话级强制 invocation。
- 不改变专家会话的绑定模型。
- 不改变 MCP 连接器的当前选择生命周期。
- 不实现插件独立进程沙箱或签名市场。
- 不保留“所有已安装插件默认可用”的兼容开关。

## 验收标准

- 未选择插件时，已安装插件工具不会出现在 Prompt tools 或 `activeToolNames` 中。
- 选择插件后，仅该插件工具在当前会话后续消息中持续可用。
- Agent可以在工具可用时自主选择调用或不调用。
- 选择其他插件或普通技能会解除原插件工具。
- 新任务无插件绑定，已有任务能恢复自己的绑定。
- 插件工具不能绕过现有模式、权限、路径保护和审计。
- 插件安装、卸载、技能选择、连接器和专家的现有主流程无回归。
