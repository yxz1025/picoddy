# 斜杠技能菜单完整性设计

## 目标

普通会话输入 `/` 时展示全部已启用技能，而不是只展示前端写死的快捷指令。保留系统模式、动作命令和 `/skill` 搜索入口，不修改后端技能发现、安装或执行逻辑。

## 数据来源与加载

斜杠菜单使用现有 `/api/skills` 返回的技能列表作为动态技能来源，并继续使用 `SLASH_COMMANDS` 作为系统模式、动作和兼容快捷项来源。

Composer 在用户打开任一斜杠菜单时确保技能已加载。已有技能数据时直接复用，不重复请求；加载失败时保留系统指令，避免菜单完全不可用。

## 合并与过滤

- 普通 `/` 菜单合并全部未禁用的动态技能与现有系统指令。
- 专家创建会话继续排除普通模式切换项，保留现有创建流程限制。
- `/skill` 入口继续只搜索未禁用的动态技能。
- 按小写命令名去重；动态技能与固定快捷项重名时优先使用动态技能元数据，使名称和描述与当前技能注册信息一致。
- 查询同时匹配命令名和展示名，保持现有键盘选择与插入行为。

## 状态与边界

- 禁用技能不展示，也不进入可渲染标签命令集。
- 技能新增、安装、删除或启停后继续通过现有 `loadSkills()` 刷新。
- 不修改消息正文、技能命令格式、Agent 激活逻辑或后端 API。

## 验证

- 模型测试覆盖动态技能与系统指令合并、大小写去重、动态技能优先和禁用过滤。
- 回归测试覆盖普通 `/` 与 `/skill` 均会触发技能加载。
- 前端 TypeScript 与生产构建通过。
- 本地界面验证 `/` 菜单包含接口返回的全部启用技能，重名项不重复，禁用技能不可见。
