# SkillHub 专家缓存与“我的专家”隔离设计

## 目标

专家市场与“我的专家”保持两个独立页面和两套存储语义：

- “我的专家”只展示用户自行创建并注册在 `my-experts` marketplace 的专家。
- 专家市场展示 `/api/web/skills?type=EXPERT` 返回的专家，不因下载而进入“我的专家”。
- 市场专家首次召唤时下载；缓存版本与当前发布版本一致时直接启动，版本变化时覆盖缓存后启动。

## 界面行为

专家 Tab 默认展示专家市场，右上角保留“我的专家”和“添加专家”。

市场专家卡片保持市场列表布局，操作区放在卡片右上角，只展示“召唤”。卡片底部不再放置召唤按钮。召唤期间继续显示全页“正在召唤专家…”遮罩。

“我的专家”页面继续只读取 `/api/experts/installed`。自建专家卡片右上角展示“召唤”和编辑图标；查看、打开目录和卸载仍可通过现有更多菜单访问。卡片底部不再重复展示召唤按钮。

## 存储隔离

新增 SkillHub 专家缓存根目录：

```text
<appData>/skillhub-experts/
  index.json
  packages/
    <slug>/
      .picoddy-plugin/plugin.json
      agents/
      skills/
      avatars/
```

`my-experts` marketplace 及其 `marketplace.json` 不参与市场专家下载。市场下载逻辑不得写入、注册或删除 `my-experts` 中的任何条目。

`index.json` 记录每个缓存包的 namespace、slug、version 和相对目录。写入使用临时文件加 rename；包下载使用同文件系统临时目录，校验成功后再替换目标目录。

## 运行时注册

专家注册表增加“缓存市场专家”集合。该集合在对外摘要中仍使用 `catalogSource: "catalog"`，因此不会被 `/api/experts/installed` 返回，也不能进入自建专家的编辑、打开目录或卸载流程。

注册优先级保持：内置专家 > 用户自建专家 > 缓存市场专家 > 原有远程目录专家。用户自建专家与市场 slug 冲突时，自建专家优先，且市场页面仍按 SkillHub identity 判断缓存，不用 `my-experts` 判断。

应用启动时扫描缓存索引并刷新缓存市场专家集合；下载完成后再次刷新。会话绑定和 `startExpertChat` 继续使用现有专家注册表，不新增第二套会话流程。

## 召唤数据流

1. 前端调用 `/api/skillhub/experts/install`，传 namespace、slug、当前发布 version。
2. 后端读取缓存索引并校验目标包。
3. 缓存存在、版本一致且包校验通过：直接返回运行时专家摘要。
4. 缓存缺失、版本变化或包无效：下载到临时目录，补齐本地 schemaVersion，执行完整专家包校验。
5. 校验成功后原子替换缓存包及索引，刷新注册表并返回摘要。
6. 前端收到摘要后复用 `startExpertChat` 进入任务工作台。

下载或校验失败时保留上一个有效缓存；若没有有效缓存则显示召唤失败，不创建会话。

## 兼容与迁移

不根据 slug 自动移动或删除现有 `my-experts` 条目，因为无法可靠判断它是用户创建还是历史市场下载，自动迁移可能误伤用户数据。新实现生效后，所有新的市场下载只进入独立缓存。

当前版本开发验证期间未实际通过市场召唤安装专家，因此没有由本次实现写入 `my-experts` 的市场条目需要迁移。

## 测试

- 缓存命中时不调用 CLI 下载。
- 缓存版本变化时下载并原子替换。
- 下载失败时保留旧缓存和索引。
- 缓存专家进入 `catalog`，不会出现在 installed 列表。
- 市场卡片右上角仅有召唤；我的专家右上角有召唤和编辑。
- 前端构建和相关 SkillHub、专家注册表测试通过。
