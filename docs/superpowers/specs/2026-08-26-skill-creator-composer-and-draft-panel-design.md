# 创建技能输入标签与草稿面板展示设计

## 目标

恢复创建技能会话输入框中的 `skill-creator` 选中标签，并阻止技能创建过程自动打开通用预览面板。技能草稿只有在完整生成且校验通过后才展示，随后由用户显式确认安装。

## 范围与边界

- 仅修改前端展示、交互和状态判断。
- 不修改后端、IPC、数据库、会话分类或 Agent 的技能强制激活逻辑。
- 不改变普通聊天、专家创建、通用产物预览和技能安装流程。
- 保留当前工作区中已经存在的“切换会话时关闭通用预览”和“技能创建交付不自动打开通用预览”改动，并为其补充回归验证。

## 输入框交互

创建技能会话在尚未发送第一条用户消息时，于输入编辑区开头展示 `skill-creator` 行内标签，复用现有创建专家上下文标签的视觉结构，并保留当前创建技能占位文案：

```text
skill-creator  请帮我创建一个可以实现「……」的 skill
```

标签是一次性的创建上下文。第一条用户消息进入消息列表后，输入框中的标签自动消失，并在该条用户消息正文前以同款只读标签展示。后续输入不再显示或重复发送该标签。标签是否待发送完全由当前会话的用户消息历史派生，不增加持久化字段；因此刷新页面后状态仍然一致。发送失败时，现有乐观用户消息会被移除，输入框标签随之自动恢复。

标签允许在发送前删除。由于后端逻辑保持不变，删除标签不会改写创建会话的持久化分类，而是退出当前创建技能会话并回到普通新任务欢迎态。原创建会话及其历史保留在侧栏；重新进入一个尚无用户消息的创建会话时标签恢复，已有用户消息的创建会话则只在首条用户消息中展示标签。

生成或发送过程中禁用删除按钮，避免在任务执行中途切换页面。

## 草稿面板

`SkillDraftPanel` 继续挂载并沿用现有消息结束后刷新草稿状态的机制，但只有以下状态渲染可见面板：

- `valid` 且校验结果为通过；
- `installed`。

草稿不存在、仍在编辑、校验失败或正在初次加载时，组件不渲染可见内容，也不占据右侧宽度。草稿变为 `valid` 后，面板展示文件、校验结果以及现有安装操作；安装仍使用现有二次确认逻辑。

已安装技能进入修订流程后，现有修订面板行为保持不变，避免影响既有技能维护能力。

## 通用预览隔离

技能创建会话仍可以接收 `present_files` 数据，但不会把通用 `ArtifactPanel` 自动展开。切换会话、回到欢迎页或删除当前会话时继续清空通用预览的选中项与展开状态。

技能草稿面板与通用产物预览面板保持独立：前者只在草稿可安装时出现，后者不因技能创建交付自动出现。

## 测试与验证

- 模型测试覆盖创建技能会话只在首条用户消息发送前展示输入标签，普通会话和已发送消息的创建会话不展示。
- 消息渲染测试覆盖标签只附着在创建会话的首条用户消息，后续用户消息不重复展示。
- 模型测试覆盖草稿仅在可安装或已安装状态展示，编辑中和校验失败不展示。
- 回归测试覆盖技能创建交付不自动打开通用预览，普通会话仍自动打开。
- 前端 TypeScript 检查和相关 Node 测试通过。
- 本地浏览器验证标签布局、首条消息发送后标签从输入框迁移到消息区、发送失败后标签恢复、删除后回到普通欢迎态、创建过程中无草稿面板、草稿通过后出现安装确认面板。
