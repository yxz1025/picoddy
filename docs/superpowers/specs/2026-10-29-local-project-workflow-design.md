# 本地项目与分阶段专家工作流设计

状态：用户已确认，已按本地阶段工作流实现。依据用户提供的三张 WorkBuddy 截图及当前源码，不声称已研究截图之外的 WorkBuddy 行为。实施记录见 `docs/designs/2026-10-30-local-project-workflow-implementation.md`。

## 目标

项目从用户描述的目标出发，关联本地目录、代码仓库、专家与可选 MCP。每个阶段拥有独立可恢复会话，用户在会话中讨论并确认交付，再进入下一阶段。共享资产保存在本地，阶段推进不读取或更新 TAPD 状态。

## 方案选择

推荐「项目容器 + 阶段独立会话 + 人工交接」：沿用现有聊天与专家能力，同时让阶段、产物和确认关系可追溯。

不采用单一长会话反复更换专家：上下文混杂，难以明确每次确认对应的版本。暂不采用通用可视化 DAG 编辑器：拖线、分支、并行调度超出本次顺序交付需求；先提供可编辑的顺序阶段模板。

## 页面一：项目首页

侧栏「项目」始终进入项目首页，恢复最近项目另设「继续上次项目」，不默认跳进第一个项目或 TAPD 需求。

顶部：项目标题、短说明、主按钮「新建项目」。下面是搜索和「全部 / 进行中 / 待确认 / 已归档」筛选。

「我的项目」卡片展示名称、目标摘要、当前阶段、当前专家、最近更新时间、待确认提示。点击进入该项目最近使用的工作流阶段。卡片菜单提供设置和归档；归档不会删除会话、资产或仓库。

「从模板创建」展示：产品研发全流程、已有代码迭代、调研与方案、空白项目。模板定义初始指令、阶段顺序和推荐专家角色，不附带虚构执行结果。首页不放统计大卡，也不显示 TAPD 授权提示。

空状态给出「新建项目」和模板入口；搜索无结果与从未创建项目使用不同提示。加载、读取错误保留页面结构并提供重试。

## 页面二：新建项目

采用居中宽弹窗，内容区滚动，标题和操作栏固定。沿用 PiCoddy 字体、边框和圆角；不复刻参考图的卡片、插画或具体布局。

字段顺序：

1. 项目名称，必填，最多 40 个字符，允许中文。
2. 项目目标与指令，必填，多行编辑；右上选择模板。切换模板遇到已有修改先显示差异并确认，不能无提示覆盖。
3. 项目目录，默认应用管理目录下的新目录，也可选择本地目录。明确显示本地资产保存位置。
4. 代码仓库，可选，关联一个或多个现有本地 Git 目录，标记前端/后端/公共库。显示分支与校验结果，不自动切换分支、清理修改或覆盖文件。远程地址可记录为来源；不静默克隆。
5. 专家与阶段，模板预置顺序，行内选择已安装专家、更换角色、添加/移除/调整未启动阶段。支持同一专家负责多个阶段，但会话独立。
6. 连接器，可选，从已有 MCP 连接中添加。TAPD 与其他连接器地位相同，默认不选。

底部操作「取消」「创建项目」。创建只保存配置并进入首阶段的待开始状态，不自动调用模型、下载专家或执行仓库命令。未配置某阶段专家不阻止保存；该阶段启动时提示选择或安装。安装失败不丢失项目草稿。

## 页面三：项目工作台

顶部为「项目 / 项目名」面包屑，右侧为项目设置和打开本地目录。下方页签为「工作流 / 会话 / 资产 / 动态」。不提供尚无协作后端的“邀请”按钮。

工作流页采用三栏：左侧窄阶段轨道，中间当前阶段会话，右侧可收起的项目上下文。保持原有应用侧栏，窄窗口可折叠阶段轨道与上下文。

- 阶段轨道：序号、标题、专家、状态。已完成阶段可回看；未来阶段可预览配置，但不能绕过前序确认开始执行。
- 会话区：阶段目标、绑定专家、输入引用条、现有 ChatArea 与 Composer。当前阶段使用真实会话与真实流式执行，不生成演示输出。
- 上下文：项目需求、仓库、本地共享资产、当前阶段交付。项目级资产可在所有阶段查看；本阶段使用哪些文件与版本明确列出。
- 会话页：按阶段分组列出会话和历史执行轮次，支持恢复；不会把其他项目普通会话自动加入。
- 资产页：文件名、阶段来源、版本、确认状态、本地路径和操作。支持预览、打开位置、上传/引用本地文件；不显示 TAPD 同步状态。
- 动态页：创建、专家更换、执行、交付、确认、退回和失败事件，来自实际持久化记录。

## 默认研发阶段

| 阶段 | 默认专家角色 | 主要交付 | 用户确认 |
| --- | --- | --- | --- |
| 需求澄清 | 产品专家 | 目标、范围、约束、待确认问题 | 确认范围 |
| 产品方案 | 产品专家 | PRD、使用流程、验收标准 | 确认产品方案 |
| 技术设计 | 架构专家 | 源码依据、技术方案、任务拆解 | 确认实现计划 |
| 开发实现 | 开发专家 | 代码变更、实现说明、检查证据 | 确认变更进入测试 |
| 测试验收 | 测试专家 | 测试用例、执行结果、缺陷记录 | 确认验收；失败可退回开发 |
| 交付归档 | 交付专家或开发专家 | 交付清单、构建产物、运行说明 | 确认项目完成 |

UI/交互设计可在创建时添加为独立阶段，默认插入产品方案与技术设计之间。阶段使用稳定字符串 ID，与显示名称、排序和 TAPD 状态解耦。

## 阶段会话与人工交接

顺序状态：待开始 → 进行中 → 待确认 → 已完成。失败与暂停是可恢复状态，不能伪装为完成。未来阶段显示未解锁，历史失效的确认显示待复核。

1. 点击「开始本阶段」，加载明确绑定的专家，创建或恢复本阶段会话。首轮注入项目目标、阶段指令、选定仓库及已确认上游交付摘要和文件版本引用；不拼接所有上游聊天。
2. 用户通过现有会话框交流、提问与修改，专家可以多轮执行。模型回复结束不代表阶段完成。
3. 专家提交候选交付卡，列出文件、摘要、测试证据、风险与未决问题。保存草稿与正式确认分开。没有产物的澄清阶段也须保存可审核的范围记录。
4. 用户可「继续修改」或「确认并进入下一阶段」。确认前查看实际交付文件与版本，不能只确认模型的一段“已完成”文字。
5. 后端检查会话空闲、当前阶段、候选文件存在、版本一致、前序依赖已确认，再原子写入确认记录并解锁下一阶段。重复点击只产生一次确认。
6. 界面进入下一阶段的待开始会话，显示交接摘要、专家和输入版本。用户点击「开始本阶段」才执行，不因页面跳转自动触发模型或命令。

退回前序阶段保留既有聊天与资产。修改已确认文件、输入范围或批准的代码版本后，原确认记录保留为历史；受影响后续阶段标记待复核，不自动继续或删除产物。用户可查看影响并重新确认。

运行中的阶段不允许更换专家或完成交接。中断、重启、模型失败与文件读取失败后，可恢复本阶段会话并重试。交接中禁止用前端乐观状态提前解锁。

## 本地共享资产

项目目录下 `assets/` 放用户可访问的工作文件，`.picoddy/` 保存受控版本快照与交接清单。已关联仓库保持原路径，不复制整个仓库到资产区。应用数据存储仍使用现有 SQLite 和账户边界。

资产元数据记录项目、产生阶段、会话、相对路径、内容哈希、版本与确认信息。相同文件被编辑后产生新版本；下游保持引用已确认快照，提供「查看新版本 / 更新引用」。不可变快照写入成功后才允许确认阶段。

资料可以来自用户手动添加或专家真实交付。对外部路径执行权限校验，资产预览/打开均通过项目作用域校验，不能靠客户端传入任意路径。原有执行权限、审批和凭证管理继续生效。

## TAPD 与 MCP 边界

新项目页面及生命周期不调用 TAPD 授权、需求查询、任务同步、附件上传和状态流转接口。阶段切换没有 TAPD ID、附件字段或外部状态选项。

用户显式关联 MCP 后，该项目的专家才能按现有工具授权使用它；关联 TAPD 不会启用后台轮询或自动同步。写入外部系统继续遵循既有审批机制。若选择的 MCP 不可用，只阻止依赖它的操作，不阻止打开项目或进行其他本地阶段。

旧 TAPD 需求入口不再承载新的项目流程。保留其持久化数据和原文件，可从独立历史入口只读查看；不自动创建、同步或推进旧需求。若以后迁移为本地项目，由用户显式导入，旧外部标识仅作为来源元数据。

## 源码观察与最小改动边界

- 当前 `frontend/src/components/projects/ProjectPanel.tsx` 使用前端 DemoProject/localStorage，同时挂接 RequirementsDesk 与 TAPD 授权，不适合作为新工作流的持久化权威。
- `RequirementChat.tsx` 已复用 ChatArea/Composer 并建立阶段独立会话，但请求和完成流程直接绑定 `/api/tapd/requirements/...`。
- `projectDemo.ts` 的阶段采用稀疏数字 ID，缺少明确开发实现阶段；新流程应新建独立定义，保留旧 ID 的历史解释，不原地重排旧数据。
- `src/domains/project/node/store.ts` 已有 SQLite 项目及会话关联，可作为项目实体基础。
- `src/domains/requirement/node/` 已包含输入、仓库、资产、交付与专家逻辑，需逐项分离本地能力与 TAPD 副作用，不能直接换 URL 即宣称完成。

保留模型运行时、流式聊天、会话存储、专家安装与绑定、仓库读取和文件预览能力。新增薄的本地项目工作流服务、作用域 API、阶段状态和确认持久化；新路径不调用 TAPD。前端拆为 ProjectHome、ProjectCreateDialog、ProjectWorkspace、StageRail、StageChat、StageReview 和 ProjectAssets 等组件。

## 验收标准

1. 不配置 TAPD 或任何 MCP，也能创建、打开项目并完成全部默认阶段；项目操作中没有 TAPD 网络请求。
2. 项目由真实数据库持久化，刷新或重启可恢复项目、阶段、会话与资产，不依赖演示种子或 localStorage 保存业务状态。
3. 创建、切换页面和交接到下一阶段都不会自动调用模型；开始操作与自动继续有明确边界。
4. 不同阶段会话独立，绑定所选专家，引用已确认上游交付版本。
5. 运行中、失败、缺失文件、版本过期、重复确认、断电重启均不会错误推进阶段。
6. 测试报告对应实际执行证据；没有运行则显示未执行，不能显示演示通过。
7. 修改上游基线会标记下游待复核，保留历史及文件。
8. 旧项目记录可保留和查看；项目列表与新流程不弹出 TAPD 强制授权。
9. 检查浅/深色、键盘、焦点恢复、弹窗滚动、窄窗口和减少动态效果。

## 本次范围

先完成桌面端本地顺序工作流。多人协作、云同步、自动发布部署、任意 DAG 和多专家并行不在本次范围。交付确认只归档本地成果，发布到远程仓库或外部平台仍是用户单独触发的操作。
