# 全项目测试目录统一与无用代码清理设计

## 目标

统一项目测试文件位置，并在不破坏动态入口和已有未提交业务改动的前提下，清理有证据确认无用的代码。

## 测试目录结构

后端和脚本中的 `*.test.ts`、`*.test.tsx`、`*.spec.ts` 和 `*.spec.tsx` 文件移动到根目录 `test/` 下，并保留原有目录层级：

```text
test/
  src/...
  scripts/...
```

迁移的测试文件中的相对导入统一改为指向实际源码路径。`frontend/` 下的源码和测试文件保持原位置不动，前端测试继续使用现有相对导入和命令。

## 测试命令

新增或更新统一后端测试入口，覆盖：

- `test/src/**/*.test.ts`
- `test/scripts/**/*.test.ts`

原有后端单文件测试命令同步更新到新路径。前端测试命令和路径不变。Electron 类型检查仍覆盖生产源码和脚本；后端测试目录若不在生产 tsconfig 中，则使用 `tsx --test` 执行。

## 无用代码清理规则

只删除满足至少一项证据且经过验证的内容：

- 文件没有任何生产代码、配置、构建入口、动态导入或测试引用；
- 导入符号没有使用，且删除后类型检查通过；
- 导出符号没有消费者，且不是 IPC、插件、生成脚本或公开入口；
- 明确重复且已被新实现完全替代的旧代码。

以下内容默认保留并人工检查：

- Electron IPC handler 和 `client.ts` 路由；
- `main.mjs`、`application.electron.ts`、Vite/electron-builder 入口；
- 插件 manifest、动态 `import()` 目标和生成脚本；
- `AGENT.md`、构建资源和运行时配置；
- 用户已有未提交修改涉及的文件，除非用户明确要求清理其中的无用代码且能证明安全。

## AGENT.md 规则

在“必须遵守”中增加：

> 后端和脚本测试文件统一放在根目录 `test/` 下，并按源码目录镜像组织；`frontend/` 测试保持现有位置，不要移动前端测试。

## 验收

- `rg --files` 检查 `src/` 和 `scripts/` 下不存在迁移后的测试文件；
- 所有迁移后的后端测试能够执行，前端测试保持可执行；
- Electron 类型检查通过；
- 前端构建通过；
- 删除清单可逐项追溯引用证据；
- `git diff --check` 通过；
- 不影响现有功能改动和动态入口。

## 非目标

- 不进行无证据的大规模重写；
- 不删除用户数据、构建产物或运行时缓存；
- 不把生产代码移动到测试目录；
- 不新增测试框架，仅统一现有测试组织方式。
